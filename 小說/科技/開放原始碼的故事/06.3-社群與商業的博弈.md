# 6.3 社群營運與商業公司之間的權力博弈：個人貢獻者與商業資本的微妙平衡

## 權力的問題：誰擁有專案？

開源日常的表象是「人人都可提交 patch」，但背後的核心問題持續五十年：**誰有權決定專案的方向、誰有權收錢、誰有權改規則？**

開源史上出現過四種權力結構：

### 1. 仁慈的獨裁者（BDFL）

- 範本：**Linus Torvalds**（Linux）、**Guido van Rossum**（Python，2018 年卸任）；
- 特點：決策最終由一人定奪，社群以「信任個人的品味」為基礎；
- 優點：快、一致；
- 風險：**巴士因子（bus factor）**——如 Guido 2018 年辭去 BDFL（因校院理性論戰的耗竭），立即暴露 Python 的接班難題。

### 2. 貢獻者委員會 / 精英制

- 範本：**Apache 基金會**（PMC 投票制）、**Python 的核心開發者治理**；
- 特點：committer／PMC 投票制，制度化的民主；
- 優點：避免單點，決策不繫於一人；
- 風險：委員會僵化、決策慢、**新血升不上 committer 就失去話語權**——2004 年 XFree86 許可證事件導致整批開發者出走，正是這類制度張力的代表。

### 3. 企業獨資專案

- 範本：**MySQL（雙重許可 + 貢獻者總持權交給公司）**、**Elastic**、**JetBrains（Kotlin）**；
- 特點：公司控制版權與方向，社群是「免費外部資源」；
- 風險：**公司利益改變 → 社群被迫陪葬**（如第 8 章的 Elastic 事件對社群發出的警告）。

### 4. 中立基金會託管

- 範本：**Linux Foundation（Linux、Kubernetes 的 CNCF）**、**Apache 基金會**、**Software Freedom Conservancy**；
- 特點：**版權或商標由中立法人持有**，規則不依賴任何一家公司的商業壁壘；
- 優點：企業敢用、競爭公司也能共同貢獻——是現代「巨頭開源」的主流形式。

2. **亂碩的權力不 dear 平**：曾有大型專案（如 OpenStack、OpenCV 等）發生過「**合作公司影響力治理的變奇**」——誰的員工被批評為「**治理 membres**」就會拒絕(countering 的爭執)，開源史不乏「**誰的員工占多數投票，誰就把規則改掉**」的实例；
3. **維護者在一線默默撐住整個生態**（詳見第 7 章維護者倦怠），但他們**通常自己不收錢**。

## 商業資本的入侵模式（2000s 至今）

公司參與專案時，有**五種策略**由淺入深：

| 策略 | 描述 | 案例風險 |
|---|---|---|
| **純消費** | 用不回饋 | 信任流失 |
| **單向捐贈** | 撥 code 不派人事 | 治理失衡 |
| **治理參與** | 派代表加入 PMC／基金會 | 「誰的員工最多」專案傾斜 |
| **流程控制** | 建 CI、文檔、release cadence | 事實上掌握版本節奏 |
| **產品分流** | 自己造「企業版」收費服務 | 核心社群空心化 |

## 經典案例：「XFree86 危機」與「Ubuntu 誕生」

- **XFree86 大出走**：2004 年，XFree86 採用新許可證（含廣告條款），導致 Debian、Fedora 等主流發行版**全部棄用**，整批開發者轉投新生的 **X.org**——**許可證之爭引發了整個 X Window 生態的大遷徙**；
- **Shuttleworth 與 Ubuntu（2004）**：南非企業家 Mark Shuttleworth 讓出自己公司（Thawte）後投身 Debian，主張**每 6 個月一個可預測的發布週期**。Debian 社群擔心「**公司玩玩、最後撒手**」，Shuttleworth 採取分工的方式——成立 **Canonical** 公司、發行版保持自由許可、並設立 **Ubuntu Community Council** 與 **Ubuntu Foundation**（2005）等制度層——**「公司 + 基金會 + 社群議會」的三層結構成為其後的治理範本**。

## 均衡的規則：可信的第三方與透明

歷史聚焦到最後，制度均衡沉澱出三條鐵律：

1. **版權歸中立法人**或**永不轉讓**（Linux 核心每位貢獻者保留自身版權、僅授予授權——**避免版權集中**）；
2. **決策規則公開**（voting procedures, committer policies, CLA/DCO）；
3. **資金透明**（如 Debian 的反收費等官 DPL constraints）。

## 小結

社群與公司的博弈，本質上就是**「榮譽經濟 vs 資本市場」的兩種生產關係**的相處問題。紅帽把公司做成「最大的社群成員」、MySQL 把社群做成了「品牌資本」、基金會把公司合作人群收編為「中立裁判」——三種路徑各有其長短。進入 2010 年代，這場博弈將嵌入更大的悲劇與潮流：**維護者的倦怠、雲端的「白嫖」與 AI 的出現**。第九、十、十一章皆為其餘波。
