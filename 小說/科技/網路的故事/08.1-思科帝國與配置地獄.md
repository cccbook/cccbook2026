# 8.1 傳統路由器/交換機的硬體綁定困境：思科（Cisco）帝國的封閉生態與配置地獄

## 思科帝國的起源：一段校園愛情

1984 年，史丹福大學的**Leonard Bosack 與 Sandy Lerner**——一對分別負責電腦系與商學院網路的夫妻檔——為了讓兩棟樓的異質網路互通，寫出了多協定路由器，創立思科（Cisco，取自 San Francisco）。1986 年出貨第一台 AGS 路由器，1990 年上市，2000 年泡沫高峰市值一度全球第一。

思科模式的本質是一個**垂直封閉生態**：

```
思科硬體（ASIC/機箱）
＋ 思科作業系統（IOS / NX-OS，專有）
＋ 思科命令列介面（CLI）
＋ 思科認證體系（CCNA/CCNP/CCIE）
＝ 一整套「只能整體購買」的網路
```

這個模式在 1990–2000 年代大獲成功：企業與電信整體採購、工程師以「會敲 Cisco CLI」為身分證、思科以高毛利與軟體支援費稱霸全球路由器交換機市場。

## 硬體綁定困境的四個症狀

### 1. 配置地獄（Configuration Hell）

網路設備以**命令列逐行配置**，一台核心交換機的配置檔動輒數千行，且：

- **無版本控制**：配置靠文字檔備份、Excel 記錄拓撲，「網路的真相」存在工程師腦中。
- **不可重現**：改動一台設備的 300 行配置，無法像軟體一樣 diff、回滾、單元測試。
- **變更即風險**：一次手滑可能整區斷網；維護窗口選在深夜，是全行業的共同創傷。

### 2. 閉源黑箱

韌體閉源、bug 靠原廠修補、故障診斷靠神秘命令。客戶無法審計、無法客製。2018 年 CIA「Vault 7」文件曝出思科設備長期存在的漏洞被利用改造為監聽工具——**閉源黑箱的風險成為國安議題**。

### 3. 成本與鎖定

高階機箱單台數十萬美元，模組、授權、支援合約層層收費；一旦進入生態，遷移成本極高（vendor lock-in）。企業 IT 預算中「網路」成為增長最快的黑洞之一。

### 4. 創新速度的錯位

2000 年代，伺服器世界的變革天翻地覆：虛擬化、分散式系統、DevOps——但網路設備的軟體仍以「數年一版、原廠發布、人工配置」的方式緩慢演化。**雲端廠商發現：網路是它們資料中心裡最不敏捷的一環**。

## 雲端巨頭的不滿：規模改變一切

Google、Amazon、微軟的資料中心以**數萬台伺服器**為單位擴張，對網路的需求徹底不同：

- **規模**：需要數千台交換機，思科定價無法承受；
- **敏捷**：要像伺服器一樣以軟體自動化配置（數萬台設備不可能人工敲 CLI）;
- **可控**：擁塞、拓撲、故障恢復要能以**集中演算法**調度，而非分散式協定的黑箱。

**「網路應該像伺服器一樣被程式化」**成為新一代工程師的共識。

## 先行者：Broadway/Firehose 與 OpenFlow

- **2005 年前後，史丹福的 Martin Casado 在 Clean Slate 計畫中開發 Ethane**（2006）：用一個中央控制器統一管理校園網路的安全策略——「把網路控制權集中到軟體」的第一次大型實驗。
- Casado 與導師 Nick McKeown 等人將思想泛化，**2008 年發表 OpenFlow**：定義「交換機的轉發表由外部控制器下發」的開放協定——這就是 SDN 的點火裝置（下一節詳述）。
- 同時期，Google 內部早已自行研發集中控制式網路（日後公開的 B4 廣域網），Facebook 發起 **OCP（Open Compute Project, 2011）**，開源資料中心硬體設計——**白盒交換機（whitebox switch）**產業誕生：買裸機硬體＋自由選擇作業系統（ONIE、SONiC、Cumulus）。

## 小結

思科帝國的成功與困境是同一件事的兩面：**垂直整合帶來可靠性與利潤，也帶來封閉與遲緩**。當買家從企業 IT 變成每天擴張數千台設備的雲端巨頭，封閉生態的議價權徹底反轉。下一節，我們看 OpenFlow 與 SDN 如何把控制平面從盒子裡解放出來。
