# 2.3 電信巨頭的嘲弄：為什麼 AT&T 專家斷言「封包交換絕對無法傳輸語音」？

## 兩種文化：電信 vs 電腦

要理解這段歷史的衝突，必須理解兩種工程文化的世界觀：

| | 電信工程文化（AT&T/Bell System） | 電腦工程文化（RAND/MIT/NPL） |
|---|---|---|
| 設計哲學 | 過度供給（over-provisioning）：事先算好最壞情況，鋪足線路 | 事後恢復：讓系統聰明到能自己繞過故障 |
| 品質指標 | 呼損率、固定延遲、金屬般的穩定 | 吞吐量、平均延遲、軟體可修補 |
| 失效觀 | 故障是意外，必須預防 | 故障是常態，必須容忍 |
| 資源 | 電路專屬保留 | 統計複用、動態共享 |

1960 年代的電話網是「上帝般的可靠性」：撥了就通、延遲恆定。而封包交換在其看來，像是把神聖的通訊交付給一群會塞車、會丟包、會當機的電腦。

## 「絕對無法傳輸語音」

巴蘭後來在多次訪談中回憶：他在 1960 年代初向 AT&T 的高階工程師解釋封包交換概念時，得到的反應是**憤怒與嘲弄**。他的陳述大意如下：

- AT&T 的工程師告訴他，這個構想「**在物理上不可能**」——封包網路的排隊延遲與抖動（jitter）會讓語音斷斷續續，根本無法通話。
- 巴蘭將報告送請 AT&T 的專家審閱後，得到的書面回應之一是：**「AT&T 強烈懷疑分散式封包交換是否能運作」**——並附上一長串電信老派的論證。
- 最令他哭笑不得的是：他向 AT&T 提議以數據服務的方式試驗此概念時，對方的答覆是——**「數據通訊對電話公司而言太小眾了」**（"Data communications is not interesting to the telephone company"）。

這段「正確地錯誤」的歷史值得細品：以**當時的技術約束**而言，電信工程師的質疑有堅實依據——封包網路要傳好語音，需要低延遲排隊調度（多年後的 WFQ、VoIP 的 jitter buffer、QoS 才解決）；而「數據市場不大」的判斷，以 1965 年全球只有數萬台電腦的現實看，也符合當時的經驗。**組織的慣性，使其在最擅長的領域裡看不見典範轉移。**

這正是克萊頓·克里斯汀生（Clayton Christensen）「創新者的窘境」在 1960 年代的真實演出：AT&T 把資源投入最賺錢的語音業務（理性的！），於是錯過了幾十年後吃掉整個產業的數據洪流。

## 歷史的迴聲：其他經典誤判

這種嘲弄在科技史上屢見不鮮，封包交換的遭遇並不孤單：

- 1876 年，西方聯盟（Western Union）的內部備忘錄認為「電話這玩具沒有多少價值」——後來它被貝爾體系碾壓。
- 1943 年，IBM 董事長湯瑪斯·華生據傳說過「全世界大概只需要五台電腦」。
- 1977 年，DEC 創辦人 Ken Olsen 說「沒有人想在家裡放一台電腦」。

巴蘭本人在晚年總結時特別強調：**問題不是愚蠢，而是既得利益與範式信仰**。電信業的計費、工程、監管全部建立在電路交換之上，承認封包交換可行，等於承認整個組織的資產與專業需要重估。

## 報復性的結局

歷史的結局極具諷刺：

1. ARPANET 成功後，電信業轉向封包交換，推出 X.25 分封交換服務（1976 年 CCITT 標準化）——電信界自己把封包交換商品化了。
2. 1990 年代起，VoIP 崛起；2000 年代，軟體交換機（Softswitch）與 SIP 取代電路交換機；今天全球電話系統的核心早已是 IP 網路。**「絕對無法傳輸語音」的技術，最終吞併了整個電話網。**
3. AT&T 本尊：1984 年解體、2005 年被自己昔日分出去的小貝爾之一（SBC）反向併購——帝國以「借屍還魂」的方式結束。

## 小結

嘲笑封包交換的不是蠢人，而是聰明且敬業的專家，這正是這段歷史最深刻的教訓：**評估新範式時，組織身份本身就是認知盲區**。下一章，我們將看到巴蘭的異端構想如何在 ARPA 落地成為 ARPANET——人類第一個封包交換網路。
