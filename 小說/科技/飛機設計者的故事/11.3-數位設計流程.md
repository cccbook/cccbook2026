# 第 11 章 · 第 3 節 數位設計流程：從圖板到數位雙生

## 波音 777：圖板的黃昏

1994 年首飛的波音 777，是航空史上的一道分水嶺：它是**第一架完全以 CATIA 三維數位模型設計、不靠全尺寸實體樣版對接的主線客機**。此前，飛機的數千個零件由不同工廠製造，靠樣板與工裝「硬碰硬」地試裝，誤差以人力返工消化。777 計畫讓波音在全球鋪設了數千個 CATIA 工作站，工程師在螢幕上「虛擬裝配」，在鑽第一個孔之前就發現干涉與錯位。據波音當時的說法，設計返工大幅減少——更深刻的變化是組織性的：數位模型強迫設計、製造、維修部門**同時**看同一份幾何，「協同工程」從口號變成制度的骨幹。

## 驗證鏈：CFD 與風洞的分工

現代設計流程是一條層層過濾的鏈：

```mermaid
flowchart LR
    A[需求定義] --> B[CAD 三維模型]
    B --> C[CFD 數值風洞]
    C --> D[風洞試驗]
    D --> E[原型機試飛]
    E --> F[量產與服役]
    F -.壽命數據回饋.-> B
```

CFD（計算流體力學）以納維-史托方程的近似解，在數天內掃過數百個構型；但它對分離流、轉捩的預測仍有誤差，因此**風洞仍是不可取代的最終裁判**——數位工具的角色不是取代風洞，而是把風洞小時留給真正的歧路。波音 787 進一步把數位協同推向全球供應鏈：數百家國際夥伴共用自己的數位定義協同設計。這場實驗成敗互見——787 的全球外包曾造成交付大延誤，證明**數位模型可以傳遞幾何，卻難以自動傳遞製造文化與品責**。

## 數位雙生與壽命管理

「數位雙生」（digital twin）是 777 遺產的延伸：為每一架服役飛機建立一個隨實際構型、載荷、維修紀錄同步更新的虛擬模型，用疲勞與腐蝕模型預測剩餘壽命、優化維護排程，將航空業「按時維修」文化推向「視狀態維修」。

## ALIS 的教訓：軟體即飛機

數位化也會反噬。F-35 的後勤資訊系統 ALIS（Autonomic Logistics Information System）原意是讓每架戰機的零件壽命、訂單、維修紀錄自動流轉，卻因架構老舊、單點集中、介面繁瑣而惡名昭彰，長期被飛行員與地勤詬病，甚至一度靠離線「影子系統」繞道運作。美軍最終以全新開發的 ODIN（Operational Data Integrated Network）取代。這是真實的教訓：**當飛機本身是卓越的工程，而圍繞它的軟體制度是失控的工程，瓶頸就在後者**。設計者的戰場，已從金屬與氣流，擴張到資料模型與組織流程——飛機越來越像一台會飛的資料庫，而設計師必須學會為「不可見的部分」負責。
