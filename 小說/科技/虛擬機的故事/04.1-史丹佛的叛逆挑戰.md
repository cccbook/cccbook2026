# 4.1 教授與學生的叛逆挑戰：無視英特爾的警告，硬要在 x86 上搞虛擬化

## 兩位主角

**孟德爾·羅森布倫（Mendel Rosenblum）**：史丹佛大學電腦科學助理教授，作業系統與電腦體系結構專家。**戴安·格林（Diane Greene）**：工程背景橫跨機械、造船與資訊，曾在多家公司從事作業系統與效能工程，當時正返回校園攻讀電腦科學博士。兩人後來結婚，成為科技史上最著名的夫妻創業組合之一。

## 起點：一個研究問題，不是一個創業點子

1990 年代中期的史丹佛，羅森布倫的研究關注點之一是**作業系統的可擴展與彈性架構**。在這個脈絡下，一個「瘋狂」的問題浮上檯面：

> 「教科書說 x86 不可虛擬化——但那只是在說『陷阱式』方法。如果我們**不靠陷阱**，而是在指令執行前**動手改寫**呢？」

這個問題的技術內核，就是後來的**二進制動態翻譯**（詳見 4.2）。而讓它從論文想法變成商業現實的，是當時的環境與格林的商業嗅覺。

## 時代的三股推力

### 1. 伺服器蔓延（Server Sprawl）——經濟推力
1990 年代後期，網路熱潮讓企業機房塞滿了低利用率伺服器（每台只跑一個應用，利用率常低於 15%）。電力、空調、機架空間、管理人力全面失控。**「把一台機器切成十台」突然又是個絕妙的生意。**

### 2. 效能的成熟——技術推力
x86 CPU 在 1990 年代末快了兩個數量級，P6 微架構的亂序執行能力，使得「翻譯開銷」首次可以被硬體吃掉。**時機到了。**

### 3. 「不可能」的斷言——心理推力
正因為所有人都說不可能，這片賽道才空無一人。Intel 不做、微軟不屑、學界不碰。**對叛逆者而言，這是最理想的藍海。**

## 傳聞中的英特爾：我們不看好

流傳最廣的故事版本是：創業初期團隊曾向 Intel 展示/討論 x86 虛擬化，得到的回應大致是——x86 的保護模型不是為虛擬化設計的，這條路走不通；Intel 沒有計畫為此改動架構。（其餘版本更戲劇化，但核心訊息一致：**正牌硬體巨頭認定此路不通。**）

歷史的諷刺在七年後到來：2005 年 Intel 發布 **VT-x**，把虛擬化硬生生做進矽晶片——當年他們警告別人不要走的路，他們自己鋪了石板。

## 1998：從博士課題到車庫公司

1998 年，羅森布倫、格林，加上史丹佛的同儕（包括愛德華·布戈因、史考特·德夫恩、彼得·伯明罕等共同創辦人）正式成立 **VMware**。創業前的發表管道同樣值得注意：1997 年史丹佛的論文（Rosenblum 等，《The Complete Evaluation of Virtual Machines》相關研究）與後來 2000 年的 SOSP 論文《Virtual Machine Monitors: Current Technology and Future Trends》，確立了學理正當性。

格林出任 CEO（直到 2008 年），羅森布倫任首席科學家。**一個懂技術深度的教授＋一個懂市場的 CEO**，這個組合決定了 VMware 的氣質：不是學術玩具，也不只求快速變現，而是要把「虛擬化」做成一門嚴肅的基礎設施生意。

```text
時間軸：
1997  史丹佛研究與原型驗證 DBT 可行
1998  VMware 成立；同年 Windows 98 發布、Google 創立
1999  VMware Workstation 1.0 問世
2001  ESX Server 進入資料中心
2003  VirtualCenter 與 VMotion 改寫企業 IT
2004  EMC 以 6.35 億美元收購 VMware
```

## 為什麼叛逆者是「史丹佛體系」？

一個耐人尋味的背景：**矽谷的制度環境**。史丹佛長期鼓勵師生創業（惠普、Sun、Cisco、Google 皆出於此），教授保留教職、學生輟學創業是常態而非醜聞。風險資本（紅杉等）願意為「聽起來不可能」的技術下注。這套「大學–創投–產業」的生態制度，是 VMware 能誕生的隱形前提——換在 1970 年代的東岸大公司文化裡，這個點子大概率死在提案會議上。
