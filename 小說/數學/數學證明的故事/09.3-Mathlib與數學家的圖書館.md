# 9.3 Mathlib 與數學家的圖書館

## 從零散定理到一座圖書館

2017 年 7 月之前，Lean 社群裡的數學內容是零散的：每個人寫自己的 `.lean` 檔案，重複定義 `Nat` 的加法、重複證明三角不等式、互相無法引用。任何一個「大型定理」都不可能建立起來。

Mathlib3 的建立（由一群社群成員共同推進，後來由托馬斯·布魯姆（Thomas Bloom）長期維護）改變了這一切。它的目標寫得很清楚：

> 建立一個以 Lean 為基礎的、廣泛涵蓋純數學與數學分析，並且其他 Lean 使用者可以直接使用的數學定理圖書館。

這是一個「公共設施」式的組織：不是一個人的專案，而是一個社群共有的、由無數人提交的、持續成長的資料庫。

2021 年 7 月，Mathlib4 建立；2023 年 9 月 Lean 4.0 發布後，mathlib4 成為主流。

到 2026 年，mathlib 的規模大致是：數萬個檔案、數百萬行 Lean 程式碼、涵蓋了從初等算術到代數幾何、數論、解析、拓撲、機率論、微分方程、線性代數的幾乎所有本科到研究所課程的內容。

## 一座圖書館的組織學

mathlib 的結構本身就是一門「數學的組織學」的課：

| 命名空間 | 內容 |
|---|---|
| `Algebra` | 群、環、域、模、幺半群 |
| `Analysis` | 極限、連續、微分、積分、賦範數空間 |
| `Topology` | 拓撲、拓撲空間、連續映射 |
| `LinearAlgebra` | 向量空間、矩陣、線性映射 |
| `NumberTheory` | 整除、同餘、素數、ζ 函數、Dirichlet 級數 |
| `Data` | 各類資料結構 |
| `Combinatorics` | 圖論、極值理論、計數 |

而它的基礎語言設計是這本書最值得學的部分之一：

```lean
structure Group (α : Type) extends Monoid α where
  inv : α → α
  inv_mul_cancel : ∀ a : α, inv a * a = 1
```

`structure ... extends ...` 是 Lean 裡最常見的定義風格：**用一個既有結構加上新的欄位與公理來定義新結構**。這與希臘人的「定義—公理—定理」是同一件事，但被機器檢查了。

而且 mathlib 裡的定理不僅是「對的」，它們還帶著：

- **命名與文件**：每個定理有名字、有 LaTeX 風格的說明；
- **策略標記**：`@[simp]`、`@[norm_cast]`、`@[continuity]` 等屬性讓自動化知道「這個等式可以安全地用 simp 化簡」；
- **範例與應用**：一些定理附帶「這個定理怎麼用」的文件。

這使得數學家可以像查字典一樣使用它。

## 「重寫」：把定理變成程式

mathlib 最有影響力的技術，不是任何單一定理，而是**重寫（rewrite）**。

`calc` 與 `simp` 允許你把一個表達式沿著已知的等式逐步變形：

```lean
example (a b c : ℕ) : a + b + c = a + (b + c) := by
  simp [Nat.add_assoc]
```

這看起來平淡，但它改變了數學家的思考方式：**命題不再是一個要從頭推理的整體，而是一串可以機械執行的變形步驟。**

這其實是阿基米德時代「求面積法」的現代版：把一個複雜的目標，用一連串已知的等式，變形到顯而易見的形式。

而 2026 年 Lean FRO 發布的 `grind` 戰術、以及 2026 年的「Lean Kernel Arena」（用於評比獨立核對器的公開基準），都指向同一個方向：讓「變形」這件事自動化到讓人看不見的程度。

## 一個真實的案例：leanprover-community 的「重要定理形式化」

2019 年，數學家凱文·巴澤在社群裡發起了一個計畫：把每個「值得形式化」的定理登記成一個 issue，並且給出難度分級。結果產生了下面這張地圖（部分）：

| 領域 | 例子 |
|---|---|
| 數論 | Bertrand  postulate、孿生素數的無界性、$n!$ 是 $n$ 的倍數、$\sqrt{2}$ 的無理性、Riemann ζ 的基本性質 |
| 群論 | Sylow 定理、Cauchy 定理、有限群的分類（2026 年 10 月由 Axiom 完成） |
| 幾何 | 三角形內角和、圓周角定理、射影幾何的基本定理 |
| 分析 | 極限的各種等價刻畫、微積分基本定理的各種版本 |
| 組合 | Ramsey 定理、Pigeonhole、Cauchy–Davenport |

其中特別值得一提的是：

- **Bertrand  postulate 的形式化**（2020 年，托馬斯·布魯姆等人完成），用到了 Rosati 的方法處理 large numbers，是 Lean 中第一個真正「有分量」的定理；
- **perfect numbers**（完美數）的形式化；
- **Riemann ζ 函數的形式化**：2025 年 3 月，戴維·勒夫勒（David Loeffler）與麥可·史托爾（Michael Stoll）在 arXiv 發表〈Formalizing zeta and L-functions in Lean〉（arXiv:2503.00959），報告了他們在 mathlib 中形式化 ζ 函數與 Dirichlet L 函數的理論，並給出了**黎曼猜想的正式陳述**——

```lean
def RiemannHypothesis : Prop := ∀ (s : ℂ) (_ : riemannZeta s = 0) (_ : ¬∃ n : ℕ, s = -2 * (n + 1)) (_ : s ≠ 1), s.re = 1 / 2
```

這一行程式碼，就是「黎曼猜想」在 2026 年 11 月之前最精確的正式版本。它很重要，因為它意味著：**任何 Lean 證明，只要宣告它的陳述等於 mathlib 的 `RiemannHypothesis`，就自動是在證明黎曼猜想。**

這正是 2026 年 11 月那次認證的第一道防線：不是「他宣告了一個類似的命題」，而是「他宣告的命題就是 mathlib 的命題」。

## Mathlib 帶來的制度改變

**第一，數學家開始「二次發表」。** 一個定理的正式 Lean 證明，成為論文的附錄、成為學術簡報的亮點、也成為年輕數學家進入領域的敲門磚。

**第二，數學教育的重新設計。** 越來越多的入門課使用 Lean：不是把 Lean 當成「輔助工具」，而是把它當成「寫數學的方式」。這背後有一個教育信念：先學會寫出機器可檢查的論證，你才真正知道「為什麼」是什麼意思。

**第三，評審的新層次。** 一篇論文可以聲稱「定理 $T$ 已在 Lean 中形式化」，而評審人只要去讀那個 `.lean` 檔案，並且相信 Lean 的核心。這在實務上大幅改變了可信度的分擔方式。

**第四，AI 的訓練靶場。** 由於 Lean 的所有定理都有明確的、可機器檢查的陳述，它自然成為「訓練數學 AI」的理想環境：模型的輸出可以被客觀地打分（編譯通過=對）。這是 2023 年之後 AI 數學爆炸的技術前提。

## 一個警告

但這裡有一個必須說清楚的問題：**形式化不解決「該證明什麼」或「證明是否有意義」的問題。**

- 形式化證明的是「陳述為真」，而不是「陳述重要」；
- 形式化能檢查邏輯，但不能檢查「你的定義是不是你想要的」；
- 形式化的成本極高（數學家報告，一個中等難度的定理的形式化可能需要數週到數月的時間），而收益對某些定理來說並不划算。

2026 年 11 月的那次認證之所以重要，正因為它跨越了這道線：一個被認為「值得」的問題，第一次用「形式化的方式」得到了確認。
