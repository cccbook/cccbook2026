# 07.1　2000 年 UIUC：Lattner 與 Adve 的論文

## 自學者的來路

1978 年，Chris Lattner 出生於美國喬治亞州，童年在奧勒岡州波特蘭近郊的社區長大。太平洋西北的濕潤氣候孕育了那個年代典型的美國工程文化：車庫裡的電腦、圖書館裡的教科書、以及一群相信「軟體可以自己寫出來」的青少年。Lattner 屬於自我教育的世代——他自學程式設計，在個人電腦上摸索 BASIC 與組合語言，習慣了不靠正規課程、直接閱讀文件與原始碼解決問題。這種「先動手、再理解架構」的學習路徑，後來成為他做事的簽名風格：不迷信既有系統，敢於從第一性原理重新設計。

他進入 University of Illinois Urbana-Champaign（UIUC）電腦科學系就讀。UIUC 是美國中西部運算研究的重鎮——1960 年代的 ILLIAC 系列超級電腦、PLATO 教學系統都誕生於此，NCSA Mosaic 瀏覽器更是在 1993 年從這個校園點燃了網際網路革命。Lattner 在這裡完成大學部與研究所學業，而真正改變他命運的，是遇上了指導教授 Vikram Adve。

## Adve 的問題意識

Vikram Adve 是印度裔學者，研究重心在程式分析：profile-guided optimization（以執行期統計資料引導優化）與 data structure analysis（分析程式中的資料結構如何被使用）。2000 年前後，他觀察到一個當時編譯器界的結構性困境：一項新的分析或優化技術，從論文到真正跑在某個「真實」編譯器上，往往要花費數年。原因很簡單——主流編譯器（如 GCC）是巨大的單體式系統，內部介面文件稀少、模組間耦合緊密。研究者想插入一個實驗性的資料流分析，得先讀懂幾十萬行程式碼，而且往往只能在特定版本上打補丁，換個版本就報廢。

學術界的標準解法是自建小型研究編譯器（如 SUIF），但這些玩具系統缺乏工業級的優化與後端，實驗結果無法反映真實世界。Adve 提出了一個直白的診斷：編譯器基礎設施不「模組化、可重用」，導致整個研究社群與工業界的生產力都被拖累。他問 Lattner：能不能設計一套編譯器，讓新技術像插卡一樣裝上、拆下、重複使用？

## LLVM 的誕生

這個提問落在 Lattner 手裡，長成了一個雄心勃勃的構想：一套「終身程式分析與轉換」（lifelong program analysis & transformation）的框架。2000 年，Lattner 開始著手設計這套後來名為 LLVM（Low Level Virtual Machine）的系統。名字裡的 "virtual machine" 有其時代語境：Java VM 正當紅，但 LLVM 的 IR 並非要像 JVM bytecode 一樣跨平台發布，而是作為編譯器內部「低階、型別化、SSA 形式」的中間表示。

他的碩士論文（2002）提出的幾個關鍵設計決策，日後被證明極具遠見：

- **以 SSA 為基礎的 IR**：靜態單賦值形式讓資料流分析天然簡潔，優化 pass 可以直接受益。
- **型別化指標與無限暫存器**：每個值都有型別資訊，指標操作顯式化，虛擬暫存器數量不受硬體限制，把暫存器分配推到最後一關。
- **三種等價表示**：同一份 IR 可以是記憶體中的 C++ 物件、磁碟上的位元碼（bitcode），以及人類可讀的文字格式（.ll）——最後這一點對教學與除錯的價值難以估量。
- **以 C++ 函式庫呈現**：不是一個叫你「使用者」的工具，而是一組叫你「作者」的類別。撰寫一個優化 pass 可能只需要一兩百行程式碼，繼承幾個介面即可掛進管道。

2002 年 Lattner 與 Adve 在碩士工作基礎上發表了論文〈LLVM: A Compilation Framework for Lifelong Program Analysis & Transformation〉，2004 年正式刊於 CGO（Code Generation and Optimization）會議。這篇論文的標題如今讀來像預言：「終身」二字意味著編譯不該是一次性事件，而可以是程式整個生命週期中反覆進行的分析與轉換——這正是日後 JIT、靜態分析工具、 sanitizer 一路展開的思路。

## 授權的政治學

2003 年 LLVM 以開源方式釋出時，Lattner 做了一個影響遠超技術層面的決定：不採用 GPL，而採用 UIUC/BSD 風格的寬鬆授權。當時開源世界正深陷 GPL 爭論——2002 至 2006 年間 GCC 社群為 GPLv3 的反 tivoization 條款激烈分裂，商業公司（包括蘋果）對 GPL 工具鏈的未來充滿疑慮。BSD 式授權意味著任何公司都可以把 LLVM 內嵌進閉源產品而不必公開自己的程式碼。這個選擇讓 LLVM 從第一天起就對商業世界敞開大門，也種下了它與 GCC 分道揚鑣的命運。

早期的開源社群以學術圈為核心：mailing list 上的討論熱烈而友善，Lattner 本人以驚人的回覆速度與耐心回答幾乎每一個問題，奠定了社群「技術辯論不留情面、對新手極其包容」的文化。最早一批貢獻者如史丹佛的 Ted Kremenek（後來領導 Clang 靜態分析器）與 Nick Lewycky 等人，逐漸把這個校園專案推向工業等級。

## 一個研究生與一個時代的接口

回望 2000 年的 UIUC，LLVM 的誕生並非天才靈光一閃，而是三股力量交會的結果：Adve 對「可重用基礎設施」的問題意識、Lattner 極強的工程執行力與品味、以及開源授權政治在世紀之交留下的真空地帶。經濟上，網路泡沫破裂後科技業渴望低成本、低摩擦的工具；制度上，GPLv3 的爭議迫使企業尋找替代品；教育上，研究者需要能真正實驗的系統。一個研究生的論文，恰好站在了這些歷史力量的接口上——而他把這個接口，經營成了接下來二十年的主幹道。
