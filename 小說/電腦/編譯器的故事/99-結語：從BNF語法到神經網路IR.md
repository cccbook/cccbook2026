# 結語：從 BNF 語法到神經網路 IR——編譯器作為人類控制複雜度的永恆橋樑

## 一、七十年的三個恆常

從霍普的 A-0 到 AlphaDev 的指令搜尋，編譯器技術換了好幾代血統，但有三件事始終不變。

**其一，翻譯是分層的。** 七十年前 Forward，UNCOL 的夢想（$N$ 種語言配 $M$ 種機器只需 $N+M$ 個組件）失敗了，但七十年的歷史證明這個夢想只是** premature**：p-code 成了，bytecode 成了，LLVM IR 成了，MLIR 的多層 IR 成了。每一層抽象都在重複同一句話：**把語義與機器解耦，複雜性才能被管理**。

**其二，形式化是信任的基礎。** BNF 讓語言無歧義，SSA 讓優化可推理，CompCert 用 Coq 證明編譯器正確，AlphaDev 的成果要過驗證才能進主線。編譯器是人類少數把「正確性」當成數學問題來管理的工程領域——這個紀律在 AI 生成代碼的時代變得空前重要：**機率性的生成，需要確定性的驗證**。

**其三，介面與治理決定生死。** GCC 的單體架構輸給 LLVM 的函式庫設計；egcs 的分叉再合流證明治理僵化會被社群拋棄；GPLv3 的授權政治直接推動了蘋果的 LLVM 投資。編譯器的勝負從來不只是演算法的勝負，而是**生態制度的勝負**——這是軟體史（包括本系列其他卷冊）反覆出現的主題。

## 二、被解放的人類

回顧這七十年，編譯器真正解放的從來不只是「機時」。霍普的 A-0 讓商業機構的程序員不必懂硬體；FORTRAN 讓物理學家自己寫程式；Java 的 JVM 讓程式跨平台；V8 讓十億人寫的 JavaScript 跑得飛快；Triton 讓研究員不學 CUDA 也能寫 GPU kernel。**每一代編譯器都把「一種機器的知識」從千萬程式員的腦中移走，換成「一種抽象的表達力」**。

Backus 在 1977 年圖靈獎演講問：程式設計能否從 von Neumann 風格中解放？七十年的答案漸漸清晰：解放是分批進行的——組語、手動位址、跨平台適配、效能調優、現在連「寫出正確的 kernel」也在被解放。每解放一批，人類就把精力投向更高層的複雜性：架構、語意、系統、意圖。**編譯器是人類智力的槓桿，而且槓桿還在變長**。

## 三、AI 時代的翻譯官

神經編譯的時代提出了新問題：當翻譯本身變成機率性的，翻譯官的角色是什麼？本書的立場是歷史性的：每一次工具躍遷（編譯器取代手寫組語、JIT 取代靜態編譯的教條、LLM 輔助開發）都伴隨「工程師將死」的恐慌，而每一次的結局都是**人類上移到新的抽象層級**。AI 會寫 pass、會搜尋指令序列、會生成 kernel——但它需要人類定義不變式、搭建驗證器、承擔簽名的責任。

編譯器工程的未來藍圖因此清晰可辨：**人類書寫語義與不變式（規格、型別系統、驗證器），機器在這些約束下搜尋最優的物理實現**。這不是翻譯官的黃昏，而是翻譯官的升職——從逐句傳譯，升任為翻譯品質的總監。

## 四、最後的話

1952 年，霍普的 A-0 讓機器第一次「理解」了人類的指令序列。七十多年後，人類的意圖甚至可以不必先變成形式化的程式碼——自然語言直接成為一種「前端」。從 BNF 語法到神經網路 IR，翻譯的兩端都在演化：起點越來越接近人類思維，終點越來越深入矽的物理。

但橋的誓言從未改變：**忠實地傳達意圖**。只要人類還需要在「想法」與「物理世界」之間往返，編譯器——無論它的核心是有限自動機、SSA 圖還是神經網路——就會一直是文明最精密的同聲傳譯。而寫下下一座橋圖紙的人，也許正在讀這本書。
