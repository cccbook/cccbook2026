# 第 2 章　物理佈局資料庫與 GDSII 標準的誕生

# 2.3 手工佈局與電路模擬的第一次交會：早期 SPICE 模擬器在電路驗證上的萌芽

## 2.3.1 Berkeley 的另一條線：模擬「行為」而非「幾何」

當 Calma 在處理幾何時，加州大學 Berkeley 的 Donald Pederson 實驗室則走著完全不同的路線：**給定電路的元件清單（netlist），預測它的電壓隨時間的變化**。

1969–1971 年，Ronald Rohrer 與 Larry Nagel 執行了一門「大型主機電路分析程式」的課程專案，即 **CANCER**（Computer Analysis of Nonlinear Circuits, Excluding Radiation——排除放射效應，刻意不支援軍用核輻射需求，象徵 Berkeley 的開放學風）。1973 年，Nagel 改寫並發布 **SPICE1（Simulation Program with Integrated Circuit Emphasis）**；1975 年由 Nagel 與 Ellis Cohen 發展的 **SPICE2** 成為真正的里程碑。

## 2.3.2 SPICE 做對的三件技術決策

SPICE 的重要性來自三個奠基選擇，至今所有電路模擬器（HSPICE、Spectre、Qspice…）都繼承：

1. **改良節點分析法（Modified Nodal Analysis, MNA）**：Cohen 與 Nagel 將整個電路與方程組化為稀疏矩陣，用 LU 分解求解（複雜度約 $O(n^3)$ 的稠密降至接近 $O(n)$ 稀疏）；
2. **MOS 電晶體的簡化模型**：以 Volterra/牛頓–拉夫遜（Newton-Raphson）迭代求非線性直流解，並用隱式積分處理時間軸；
3. **開放授權＋便宜大學電腦**：Berkeley 把 SPICE 以近乎免費的方式散佈給大學與企業，只要回報改進即可——這是**開放社群模式的先聲**，比 Linux 早 15 年。

## 2.3.3 模擬與手工佈局的「第一次交會」

1970 年代，SPICE 的用戶與画紅膜的是**同一批人**，流程大致是：

```mermaid
graph LR
    A["手工畫電路圖"] --> B["以打孔卡輸入元件清單<br/>至 SPICE"]
    B --> C["模擬電壓波形<br/>確認設計可行"]
    C --> D["再手工畫 Rubylith 佈局"]
    D --> E["目視重複比對<br/>版圖與電路一致性"]
```

工程師的「寶貴直覺」第一次可以由**重複可再現的數值實驗**取代：先在電腦上試十種電流鏡，再挑一個做版圖。**設計空間探索（design space exploration）**的概念自此誕生——但當時的一切仍然以手工打孔與離線批次處理進行，猶如「隔天才知道結果」。

## 2.3.4 政治、教育與開源文化的政治學

SPICE 的傳播方式在制度上極特殊：

- **美國國家科學基金會（NSF）與國防經費**資助了 Berkeley 的積體電路與電腦 科學教育；
- **Berkeley 的學術授權**要求使用者回報改善，形成多校與企業共用、共同演進的「準開源」網絡；
- **教育再循環**：全世界半導體工程師幾乎都在大學課堂上用過 SPICE——當他們進入產業，自然要求公司提供同世代的模擬工具。這個「教育擴散→產業需求→商業工具」的鏈條，是後來 EDA 市場最可靠的成長引擎。

## 2.3.5 前因後果

- **前因**：電晶體建模知識（Shockley 方程、Grove 的 MOS 理論）＋主機計算資源的普及＋1960 年代電路分析嘗試（IBM ECAP 等）。
- **事件**：1973 SPICE1、1975 SPICE2 發佈，MNA 方法確立。
- **後果**：SPICE 成為「世界標準的電路物理化驗室」；1980 年代 Meta-Software 的 **HSPICE** 商業化了名氣（1996 年被 Avant! 收購，2002 年隨 Avant! 進入 Synopsys，6.3 節）；而「模擬在先、佈局在後」的順序思想，將在 Mead-Conway 的解耦哲學中被提升到系統層次（第 3 章）。
