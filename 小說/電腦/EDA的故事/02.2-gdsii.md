# 第 2 章　物理佈局資料庫與 GDSII 標準的誕生

# 2.2 GDSII 格式的標準化：將方塊、多邊形與層次（Layers）轉化為晶圓廠可讀數據的語言

## 2.2.1 1978：一次安靜的革命

1978 年，Calma 發表 **GDSII（Graphic Data System II）**。與其說它是新版本，不如說它是第一次把自己定位成「**產業交換語言**」：不綁 workstation、不綁廠商、僅是一種描述幾何的公共語言。任何公司的繪圖系統只要能「讀寫 GDSII stream」，就能與世界上所有晶圓廠交易。

數十年後的今天，GDSII（副檔名 .gds / .gdsii）仍是晶圓代工廠交付光罩資料的最終格式——一種**比大多數軟體公司壽命都長**的資料格式。

## 2.2.2 GDSII 的語言學解剖

GDSII 是「**資料流（stream）**」格式：檔案由一系列記錄構成，記錄由「記錄頭＋型別＋資料」組成。核心述語集：

| 記錄 | 語意 | 類比於程式語言 |
|---|---|---|
| `BGNLIB / ENDLIB` | Library 邊界 | 檔案的根節點 |
| `BGNSTR / ENDSTR` | Structure（cell）定義 | 函式定義 |
| `SREF / AREF` | 單元引用／陣列引用 | 函式呼叫（包括向量展開） |
| `BOUNDARY` | 多邊形 | 物件字面量 |
| `LAYER / DATATYPE` | 層與資料類別 | 命名空間 |
| `TEXT` | 標註字串 | 註解 / label |

換言之，**GDSII 本質上是一種只有「幾何常數與函式引用」的組合語言**。它把晶片定義為「在無限平面上重複放置有限個多邊形」的座標事實。這個抽象極度適合製造，也極度低階——這對矛盾直接催生了日後整個 EDA 的抽象階梯（RTL、Verilog、standard cell，第 3、4 章）：設計者與製造者之間需要一層又一層的翻譯。

## 2.2.3 為何 GDSII 能長壽 45 年？

三個決定性的制度與技術原因：

1. **契約凍結效應**：晶圓廠與設計公司之間以 GDSII 交付作為合約交割點，一旦成為法律上與會計上的「成品」定義，改格式等於改契約；
2. **格式簡單到「人人能寫解析器」**：沒有專利檔鎖、沒有壓縮秘密，各家 EDA 公司把它寫成共享的基礎設施；
3. **反向路徑的存在**：當後續格式（如更先進的 OASIS，2003 年由 SEMI 標準化，檔案體積小 10 倍以上）出現時，GDSII 仍因「總是有需求、誰都會用」而未被完全取代——**網絡效應壓倒技術優勢**，這是資訊產業反覆出現的定律。

## 2.2.4 產業、文化與人才層面

GDSII 的普及創造了一種**新職業**：mask data preparation（Mask Data Prep）工程師，專責將 GDSII 交付晶圓廠前的放大、合併、OPC 處理（第 7 章）。這個職位存在至今。另一方面，「GDSII 檔案＝晶片的全部」的視角，也孕育了「**晶片是可以被完全描述的存在**」這個重要思想：可計算、可搬運、可交易——為未來（第 8 章的地緣斷供、第 9 章的 3D-IC 疊層）埋下伏筆。

## 2.2.5 前因後果

- **前因**：GDS 的層次結構（2.1）＋格式戰國的政治壓力。
- **事件**：1978 年 GDSII 被 Calma 發表，並在近十年內成為普遍交換標準（後來 SEMI 亦有相關文獻紀錄 stream 介面）。
- **後果**：EDA 公司獲得「共同匯率的貨幣」；晶片設計確立為可交易數位資產；「抽象階梯」的第一層底座完成，等待邏輯綜合革命上樓。
