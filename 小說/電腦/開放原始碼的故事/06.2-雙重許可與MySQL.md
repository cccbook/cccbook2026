# 6.2 雙重許可證（Dual-Licensing）商業模式：MySQL 如何靠開源成為企業級資料庫黑馬？

## 另一條路：把開源許可證當成銷售工具

紅帽的模式是「免費軟體、收費服務」。**MySQL AB**（瑞典，1995 年由 **Michael "Monty" Widenius、David Axmark、Allan Larsson** 創立）走的是另一條更精明的路——**雙重許可證（dual licensing）**：

> 同一份原始碼，同時以兩種許可證發布：
> - **GPL v2**：任何人免費使用，強制衍生作品開源；
> - **商業授權**：付出一筆費，買下**不強制開源**的權利。

## 博弈論的天才：讓「閉源公司」付錢

雙重許可的精妙之處在於**精準切割付費者**：

| 你是誰 | 你的選擇 |
|---|---|
| 個人開發者 / 學生 / 開源軟體作者 | 用 GPL 版（免費；只要你的專案也 GPL） |
| 商業公司，自己軟體願意 GPL | 用 GPL 版（免費） |
| **商業公司，想在自己專有軟體中嵌入 MySQL** | **必須買商業授權**（否則違反 GPL） |

以經濟學描述：**GPL 把「閉源整合者」轉化為付費顧客，而開源者全部免費**——等於用法律工具自動完成了**市場區隔與歧異定價**。相較於紅帽賣服務，MySQL 賣的是**法律豁免權**。

## MySQL 的飛升之路

| 年份 | 事件 |
|---|---|
| 1995 | 公司創立，MySQL 第一版 |
| 1998 | GPL 版本重新發布（早期為受限免費授權，2000 年改採 GPL + 商業雙軌，過程引發 FSF 的密切配合） |
| 2002 年前後 | 擴散到 Web 開發主流，成為 LAMP 的資料庫支柱 |
| 2005 | 營收達數千萬美元量級，安裝基數以數百萬計——免費的黑客用戶與大公司的商業授權共存 |
| 2008 | **Sun 以約 10 億美元**收購 MySQL AB |
| 2010 | Oracle 收購 Sun，MySQL 進入 Oracle 之手 |
| 2009 | Monty 反制：創立 **Monty Program AB**，由社群分叉 **MariaDB**（以 GPL 形式繼續），成為獨立替代品 |

MySQL 的絕招是**「開源免費撐起品牌 + 商業許可笑造企業溢價」**——它以極廉價的聲譽成本取得海量用戶，再從巨頭身上收授權費。**「用戶數越好，議價權越大」**——這個商業公式成為無數專案的範本。

## 雙重許可的內在糾結與限制

1. **貢獻執照的問題**：全世界的自由貢獻者的 patch，如何被整合進「商業版」？MySQL AB 的解法是要求貢獻者簽署 **版權轉讓 (copyright assignment)** 給公司——這與「社群自治」的基本精神猛烈衝突。MySQL 之所以被批评是「**偽開源**」，正是因為**版權集中**；
2. **境界張力**：雙重許可讓 GPL 與商業授權「不可互相混合」——技術上必須**只使用無 GPL 依赖的 codebase**，管理成本極高；
3. **被收購的宿命**：一旦「最終版本只剩一家公司說了算」，被巨頭收購後**「開源」的意義就取決於那家公司**——Oracle 接手 MySQL 後，社群多數出走 MariaDB；這就是**「命運歸於公司，而非社群」**的核心風險。

## 對比：成功與失敗的雙重許可

MySQL 的成功不意味雙重許可通行無阻：

- **同類成功者**：Sleepycat (Berkeley DB)、Qt（Trolltech，特殊的多許可模型 + LGPL 開放路線）、Zabbix；
- **失敗/倒退者**：如 **Zope/Plone** 曾讓社群分化、**Sourcefire** 等案遭遇社群反彈；
- **關鍵規律**：雙重許可要成立，必須「**免費版帶來的網絡效應 > 商業版收費損失的自由弘利**」——否則會陷於既圈不住用戶、又抓不住顧客的兩難。

## 小結

雙重許可證證明：**許可證不僅有防禦功能，還能主動進攻商業**。但它的成就是以「**版權歸於一家公司**」為代價，這使它與 **社群協作者的平等精神**存在先天的緊張。下一節，我們看社群與公司的這場張力，在歷史上如何反覆上演。
