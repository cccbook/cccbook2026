# 8.1 巨頭擁抱開源：微軟以 75 億美元收購 GitHub，從「開源宿敵」變成「開源第一大貢獻者」

## Nadella 時代：把敵人的戰場變成自己的基礎設施

2014 年，**Satya Nadella** 接替 Steve Ballmer 成為微軟執行長，微軟的戰略心跳同時改變：

- **"Microsoft ❤ Linux"**（2014 宣告）：微軟在 OpenSSH、.NET Core（2014/11 開源）、VS Code（2015/4 開源）上戲劇性轉向；
- **2015–2016 年**：參與 OpenAPI、SQL Server Linux 版；**Azure 對 Linux VM 的使用率甚至高於 Windows VM**（2017 年公開數據）；
- **2016 年**加入 Linux Foundation（** platinum 成員**），並終止了當年最激進的對立策略。

2018 年 6 月 4 日，微軟宣布以 **75 億美元**收購 **GitHub**——**史上最大的開源相關收購**。

## 收購的三層邏輯

1. **開發者生態的戰略要塞**：雲端運算時代，誰掌握了開發者入口（IDE＋代碼托管＋CI），誰就決定了工作負載落在哪朵雲——GitHub 是**100M 開發者的流量池**；
2. **銷售效率**：Acquisition 之前的微軟已十年追隨 GitHub（Visual Studio Team Services 一直拿不下 GitHub），**「買下它」比「打敗它」更快**；
3. **品牌的重生傳說**：公開接受「**開源已征服全球公共地表**」之事實，象徵「**反對開源的文化遺產就此清零**」。

### 微軟的真正路線：開源是「**輸入者**」，不是「**提供者**」

微軟的開源策略有一個當年近乎革命性的事實：**「我們不生產開源，我們集運開源」**——它的核心福利是：

- **在 GitHub 上廣泛發布**（包含其 OS 生態的 VS Code、TypeScript、PowerToys、Mono 等）；
- 建立內部**Open Source Program Office（OSPO）**，統籌授權管理；
- 與 Red Hat 的官方競和（2016 年 Red Hat on Azure、**SUSE/SLES on Azure**）。

## 結果與後續

- **2019–2023 年**：GitHub 使用者從約三千多萬升到**1 億以上**（2023 年官方宣布 1 億開發者）；Copilot（2021）以 **OpenAI Codex** 為基礎帶起 AI 副駕駛浪潮；
- **NPM 被收編**（2020 年 npm 成為 GitHub 家族）；**Actions/Codespaces** 把 CI 與雲端 IDE 綁進平台；
- **排名與事實**：2020 年代初的帳號開發者排行上，微軟係開源貢獻量名列前茅——**從「癌症」到「第一大貢獻者」的十餘年旅程**；

### 歷史的交錯

值得玩味的三個事實：

1. **Git 之父 Linus 寫 Git 是為了對抗 BitKeeper 封閉**——**微軟卻在 2018 年買下了 Git 的國際主場**；
2. **Nadella 的 CEO 位置是 Ballmer 提名的**——**「癌症」的喊話者竟然親自任命了擁抱開源的繼承者**；
3. **Elron／人管的挑戰**：收購案使用了「**開發者流量**」的估值邏輯，但 GitHub 的財務結構是**社交型平台的單位經濟**——這個併購案的後續效應（Copilot 的定價、平台政策變化）要在長期更顯現（見第 10 章 AI Agent）。

## 小結

微軟的轉型描繪了一個殘酷的事實：**開源並沒有「打敗」微軟，而是微軟重新學會了**開發者生態的玩法**。它證明了：**當開源成為全球 software 的公共編織法，**「與其戰勝它，不如站在它的中心**。下一節，我們看另一個轉主：Google 開源 Kubernetes，把「雲端的遊戲規則」copy 成公共標準。
