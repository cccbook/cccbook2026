# 10.3 當 AI Agent 開始自己編寫並貢獻開源代碼：人類與 AI 共同織造的未來軟體庫

## 從 Copilot 到全自動貢獻者

2021 年 **GitHub Copilot**（基於 OpenAI Codex）讓 AI 能夠**補全程式碼**。2023–2024 年的 LLM 潮把「**AI Agent**」推向舞台：

- **2023 年**：AutoGPT、MetaGPT 等獨立專案首度實驗「**由 AI 接手完整工程任務**」；
- **2024 年**：**Devin**（Cognition）宣稱能**獨立完成任務、跑測試、提出 PR**——「AI 工程師」正式入場；各大廠的 IDE/API 也接連開放**自動化協作**能力；
- **2024–2025 年**：**Claude 的 Computer Use**（AI 操作完整開發者工作流）、**GitHub Copilot Workspace** 等工具讓 AI 可以**從 issue 出發 → 設計方案 → 提交 PR**。

## 第一波衝擊：AI 直接向開源專案投遞代碼

2024 年起，開源社群迎接了明確的「AI 貢獻潮」：

- **多個主流專案**（Django、多個 Rust/Lua/Ruby 社群）**公開要求或不接受 AI 生成內容**，或明文要求**註明 AI 協助屬性**；
- **審核者的新難題**：如何辨識「人類親寫」與「AI 生成 patch」——**用戶端校驗成為新焦點**；
- 多數專案的最終共識接近「**AI 可以用，但人類技術判斷不可缺席**」。

## 四個嶄新挑戰

### 1. 貢獻者身份的模糊

- Git 以作者 email 與簽名追蹤；**AI 生成的 code 沒有「作者」**——它是**模型（由無數人類 code 凝成）的混合資產**；
- **「AI 貢獻率」** 登記成為了一些專案的探索題目——**「人類歸屬」面臨意義層面的重寫**。

### 2. 物權的地位

- **AI 生成的作品**的版權歸屬不清：美國著作權局（2023 年起）多份意見書指出**純 AI 生成內容無法獲得著作權**；開源許可證要求「版權聲明」在 AI 內容上**弱化**；
- 法律對「**AI 訓練資料的版權**」（見 9.3）的訴訟潮**回到生產者這裡的責任**。

### 3. 顛覆「貢獻者經濟」的邏輯

如果 AI 能完全替代 code 編製：

- **「人寫 code」的人力價值重新定價**；
- **「少數維護者 + 多數 AI」**可能成為**大型專案的新常態**——**維護者被壓縮為「審核者」**，而成為更稀缺的資源；
- **「誰出 PR、誰算仁義」**的榮譽體系需要制度重構。

### 4. 品質與「迴路污染」

- **AI 生成的 code 常見迷惑性 bug（hallucination）**；
- 若**生態大部分生成**來自**AI 的自我生成**，**「模型塌陷（model collapse）」式退化**——**迴路重複訓 AI 的輸出**——是長期生態的潛在風險；
- **一個開放生態是否因 AI 加速而失去「多樣性與驗證」** 是新判斷。

## 伦理與制度反應

2024–2025 年的社群對策：

- **Ban or require**：特定專案**明禁 AI**；**更主流專案要求 disclosure**；
- **Copyleft 的模糊處理**：**GPL 的許可規範**是否對 AI 生成 code 的「合法歸屬**」**產生新的**法律解讀，仍在進行中；
- **OpenSSF 與供應鏈評分**：**scorecards、SBOM** 等**開始把 AI 生成內容納入風險視野**；
- **貢獻盟約**（Contribution AI Polices）**成為新的文件類型**（如 Python、Rust 社群的指引）。

## 這場革命可能把開源帶去哪？

三種可能的終局：

1. **「人類審核者為王」**：AI 加速寫碼，人類主要身分是**管理者與裁判**；
2. **「自動化開源」**：多數專案以**自動化代理**與小團隊維護——**開源社群的審美被大模型重塑**；
3. **「人機共棲」**：AI 是最強的 pair programmer，人類仍是「**為何這樣做**」的仲裁者——**開源的榮譽與審美文化被保存下來**。

## 小結

當 AI Agent 開始**自己寫 code、開 issue、發 PR**，整個開源世界的底層假設「**貢獻者是人**」受到根本挑戰。第八、九、十章的所有線索——許可證、基金會、治理、地緣——都會在這個問題上匯流。這正是本書結語要談的：**開源作為人類協同進化工程的未來**。
