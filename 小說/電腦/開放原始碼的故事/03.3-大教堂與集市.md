# 3.3 埃里克·雷蒙（Eric Raymond）與《大教堂與集市》：集市模式（Bazaar）如何碾壓傳統大教堂開發？

## 觀察者：從 1980 年代起置身其中

**埃里克·史蒂文·雷蒙（Eric S. Raymond, ESR）**是自由軟體文化的老兵——早期 GNU 計畫的貢獻者、《新駭客詞典》的編纂者。1996–97 年間，他把**親身主持開源專案 fetchmail** 的經驗與對整個運動的觀察，寫成一篇會議論文與一本小冊子：**《大教堂與集市》（The Cathedral and the Bazaar,1997 年首次發表，1999 年出版成書）**。

## 兩種開發範式

Raymond 用兩個比喻性的意象概括開發範式的分野：

| | **大教堂（Cathedral）** | **集市（Bazaar）** |
|---|---|---|
| 代表 | 封閉小組精心設計（傳統軟體工程、GNU Emacs 早期） | 去中心：網路志願者協作 |
| 組織 | 集中、階層、神秘 | 分散、自對等、開放 |
| 發布 | 長週期、封閉測試 | **早發布、常發布（release early, release often）** |
| 假設 | 「很多眼睛 = 更混亂」 | 「**給夠多的眼睛，所有的 bugs 都是很淺的**（Linus's Law）」 |

> **Linus's Law**：「Given enough eyeballs, all bugs are shallow.」——足夠多的觀察者，讓每個 bug 都變淺。這是對 Linux 現象的理論總結：**平行審查的除錯效率，勝過階層組織的計畫**。

## 19 條格言與「Linus 領導模式」

書中最重要的工程洞見之一，是辨識出 **Linus 式領導者**的特殊角色：

- 他不是「設計者」，而是**「決定誰可以參與、如何整合貢獻」的仲裁者**；
- 他「**不做對的事，而是做能出貨的事**」；
- 他把技術領導變成**「社群動力學」**問題——如何讓數千名陌生人自願獻出 patch。

這種領導模式後來被稱為**仁慈的獨裁者（Benevolent Dictator for Life, BDFL）**——與 Debian 的民主章程、Apache 基金會的委員會模式並列，成為開源治理的三個基本原型。

## 翻譯給商業世界的「政治學」

《大教堂與集市》的歷史引爆點不在技術，而在**語言政治**：

- Raymond 刻意**去除道德語言**，開頭第一句就是：「Linux 忽然變得對全球商業有巨大吸引力……」；
- 他提出 **「Homesteading the Noosphere」**（墾殖無形智域）等概念，把開源視為**榮譽經濟（reputation economy）**而非利他不動機——**參與者不是聖人，而是追求聲望的理性人**（這與 Robin Dunbar、Lave & Wenger 的社群實踐理論相通）；
- 他回答了商業世界最焦慮的問題：**「為什麼有人願意免費送出如此有價值的軟體？」**答案是：因為他們獲得了**某種別的報酬**（聲望、學習、合作網路、解決自己痛點）。

## 1998：一場由論文引爆的革命

《大教堂與集市》最初以論文形式在 1997 年發表（Tim O'Reilly 主辦的 Perl 大會上登場並迅速在網路流傳），但真正的引爆點是 **1998 年 1 月 Netscape 開源 Mozilla**。Raymond 事後證實：**Netscape 的決策者讀過這篇論文**，並把它作為內部論證的依據。

1998 年 2 月，Raymond 與同僚正式把「自由軟體（Free Software）」的商業友好版本命名為「**開放原始碼（Open Source）**」——《大教堂與集市》成為新運動的**理論聖經與商業說書本**。

### 開源經濟學的三個概念（源自此書與後續論文）

1. **Gift Culture**：贈與文化——聲望是最稀缺資源；
2. **Scratch your own itch**：開源專案的動力來自「解決自己的問題」（如 fetchmail）；
3. **「很多眼睛 + 常發布」**：品質可以被群體放大。

## 影響與反思

- **正面**：把開源「去道德化」打開了商業大門——IBM、甲骨文、戴爾從此能接受開源作為策略；整整一代商業決策者讀的就是這本小冊子。
- **反思與批評**：
  - RMS 尖銳批評 Raymond 的「去道德化」：缺乏道德立場的開源，將難以抵抗專有化倒退（此分歧日後成為「free software vs open source」的核心張力）；
  - **Joel Spolsky 等實務派指出**：Linux 的成功還有無數背景因素（POSIX 標準、GCC、網路基礎設施）——**「集市」不是萬靈藥**；當專案負責人是「有錢的公司」（如 Android）時，常常又回到大教堂式的集中開發；
  - **「許多眼睛」如何成真，仰賴 Git/GitHub 等基礎設施**——1997 年的理論超前於當時的工具。

## 小結

《大教堂與集市》把 Linux 的驚人現象**翻譯成商業世界能理解的語言**，是開源從亞文化走向主流的關鍵一步。但它同時埋下了兩個裂痕：**道德派 vs 務實派**的分裂，以及**義務捐贈 vs 商業取用**的張力。下一章，1998 年，「Open Source」一詞正式誕生——開源運動的「建國時刻」。
