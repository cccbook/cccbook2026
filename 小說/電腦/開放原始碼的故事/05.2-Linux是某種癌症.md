# 5.2 史蒂夫·鮑爾默的名言：「Linux 是某種癌症」與商業軟體巨頭的極致恐慌

## 「癌症」的由來

**2001 年 6 月**，微軟執行長**史蒂夫·鮑爾默（Steve Ballmer）**接受《芝加哥太陽報》（Chicago Sun-Times）記者 Scott Berinato 專訪說出了那段被引用二十年的話：

> 「**Linux 是某種癌症，它從智慧財產權的意義上貼附在自己接觸到的一切事物上。**」（"Linux is a cancer that attaches itself, in an intellectual property sense, to everything it touches."）

他的邏輯是針對 GPL 的「傳染性」：任何與 GPL 程式碼連結的專有程式，都可能被迫以 GPL 開源——對以智慧財產權為商業根基的微軟而言，這是**法理上不可承受的屈辱**。

需要釐清的事實：

- 這是**鮑爾默本人的比喻**（他素有情緒化發言的名聲），不是微軟官方策略文件的措辭；

## 語言暴力背後的商業邏輯

鮑爾默的憤怒並非情緒失控，而是**精確的商業焦慮**：

1. **伺服器的失血**：2000–2005 年間，Linux + Apache/x86 組合在低階伺服器的增長率遠超 Windows Server；
2. **「免費」改變定價權**：Windows Server 收費 + CAL 授權的模式遇到了**價格為 0 的對手**，每個重新算帳的 CIO 都在問「為什麼要多付錢」；
3. **生態的指數威脅**：微軟用經費動員全球開發者，而開源用的是**聲望模型**——鮑爾默很清楚，面對不收錢的對手，時間站在對方那邊；
4. **思想污染的恐懼**：「cancer」其實是對 GPL 的隱喻暴擊——微軟真正恐懼的不是 Linux 這個產品，而是**「開發模式」**的擴散：一旦企業接受「開源是合法選項」，微軟整套商業模式的地基就動搖了。

## FUD 的頂點與反效果

「癌症」言論是 **FUD（恐懼、不確定、懷疑）戰術的頂點**，也是它的轉捩點：

- **2001–2004 年**：微軟發動「**Get the Facts**」行動——委託顧問公司發布 Windows vs Linux 的總持有成本（TCO）比較報告，正面回擊開源；
- **2003–2007 年 SCO 訴訟**：SCO 集團（取得 UNIX 源碼相關資產）起訴 IBM，主張 Linux 核心包含 UNIX 專有程式碼，並向 Linux 用戶發出「訴訟函」。微軟隨即**以「SUN/UNIX 授權」名義購買 SCO 的授權**（2003 年 5 月），被輿論解讀為「承認 Linux 有法律問題」的宣傳操作。**歷史裁決**：SCO 的主張在一系列訴訟中被逐條擊潰（公司 2007 年申請破產保護、2011 年走上清算）——**這場 FUD 之戰反把開源的法律地位磨得更硬**；
- **輿論反噬**：極端措辭使開源支持者團結，並把微軟塑造成「反進步的守舊帝國」——**年輕世代的技術偏好自此明確轉向開源陣營**；

## 最終的和解與反轉

歷史上最戲劇性的反而是**微軟的全面倒向**：

- **2006 年 11 月**：微軟與 **Novell** 簽署**跨許可協議**（patent cooperation），共同互保雙方客戶不被專利訴訟——被視為「**對 Linux 的事實承認**」（雖然鮑爾默同時還在強調「Linux 闖了 235 項微軟專利」）；
- **2014 年**：新執行長 **Satya Nadella** 就任，微軟戰略相當於「**微軟愛上了 Linux**」——內部名言「**Microsoft ❤ Linux**」；2016 年加入 Linux 基金會；2018 年以 **75 億美元**收購 GitHub（見第 8 章）；2020 年代，微軟 GitHub 上的開源貢獻已是全球最大之一；
- **鮑爾默本人**在退休前後（如 2013 年前後的演講與訪談）語氣逐漸柔化，承認微軟曾低估開源的影響。

## 「癌症」言論的歷史定位

可以用一句話總結：「**癌症」不是微軟對 Linux 的評價，而是微軟對自己商業模型未來的恐懼投射。**五年後，微軟全面擁抱開源時，這句話就成了內部傳承的「世紀之恥」，反而成為開源運動最有力的商業教材。

## 小結

「Linux 是癌症」代表的是**專有軟體帝國的最後怒吼**：從 FUD 到 SCO 訴訟到 Get the Facts，微軟以語言、訴訟與報告全面對抗開源——卻在內部預言了自身的轉型。當對手從「指控」走到「收購」，開源完成了從**邊緣到帝國核心**的歷史翻轉。下一節，我們看 1990 年代末開源如何真正贏得伺服器戰場——Apache 與 LAMP。
