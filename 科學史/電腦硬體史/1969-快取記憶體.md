# 1969 - 快取記憶體（記憶體階層的誕生）

## 案件摘要
1969 年，IBM 在 **System/360 Model 85** 上推出史上第一台配備 **cache** 的商用電腦：
$$\text{小而快的 SRAM} \;\text{擋在 CPU 與主記憶體之間}\; \Longrightarrow\quad \text{平均存取時間大幅下降}.$$
**破案關鍵**：CPU 與記憶體的速度鴻溝（processor-memory gap）越拉越大——
DRAM 跟不上 CPU。IBM 的解法是利用程式的**局部性原理（locality）**：
把「最近用過的資料」留在小而快的 SRAM 裡。
這個「記憶體階層（memory hierarchy）」思想成為**所有現代電腦的標準架構**——
從 L1/L2/L3 快取到固態硬碟，都是同一個案子的延伸。

## 前因 -- 為什麼會有這個案子
- **速度鴻溝的擴大**：1960s 的 CPU 週期約 100 ns 以下，但**磁芯記憶體（core memory）**
  存取需 500–1000 ns——CPU 有 **80% 以上的時間在等記憶體**：
  $$\text{CPU 等待比例} = 1 - \frac{t_{memory}}{t_{cpu} + t_{memory}} \approx 0.8.$$
  造更大更快的記憶體？**快與大在物理上是矛盾的**：
  $$\text{容量} \propto \text{面積} \quad\Rightarrow\quad \text{延遲} \propto \sqrt{\text{容量}} \;\text{（導線與寄生電容）}.$$
- **局部性原理的成熟**：1960s 的程式分析發現兩個規律：
  - **時間局部性**：剛用過的資料，很快就會再用（迴圈、常用變數）。
  - **空間局部性**：用過位址 $a$，不久就會用 $a$ 附近（陣列、順序指令）。
  $$P(\text{存取位址 } a+\Delta \mid \text{剛存取 } a) \gg P(\text{隨機位址}).$$
  **IBM 的推理**：與其造一個大而快的記憶體，不如**造一個小而快的擋在中間**，
  讓局部性把熱資料自動留在裡面。
- **360/85 的任務**：IBM 需要一台浮點與整數性能都壓倒對手的大型機；
  Model 85 配上 **16–32 KB 的快取**（當時是天價的 SRAM 技術）——
  實測性能**接近全用高速記憶體的機器**，成本卻低得多。
- **存貨問題**：快取不是理論新發明（Atlas 機 1962 已有 virtual memory 與類似思想），
  IBM 的貢獻是**第一個系統化、商用化、可量產的 cache 設計**。

## 線索與推理 -- 數學式、程式、理論

### 第一條線索：平均存取時間（AMAT）
快取的核心公式：
$$\text{AMAT} = t_{hit} + \text{miss rate} \times t_{miss}.$$
- SRAM 快取：$t_{hit} \approx 30\ \text{ns}$；miss 後去主記憶體：$t_{miss} \approx 500\ \text{ns}$。
- 若 miss rate = 5%：$\text{AMAT} = 30 + 0.05 \times 500 = 55\ \text{ns}$——
  **比直接存取記憶體（500 ns）快 9 倍**。
- 若 miss rate 壓到 1%：$\text{AMAT} = 35\ \text{ns}$——**幾乎等於全用 SRAM**。
$$\frac{\text{直接存取}}{\text{AMAT}} = \frac{t_{memory}}{t_{hit} + m \cdot t_{memory}} \xrightarrow{m \to 0} \frac{t_{memory}}{t_{hit}}.$$
**關鍵推理**：miss rate 對 AMAT 是**乘法敏感**的——
miss 率從 5% 降到 1%，性能提升遠大於 $t_{hit}$ 減半。

### 第二條線索：局部性原理與 hit rate
程式的局部性決定 miss rate。典型科學程式（矩陣運算）的時間與空間局部性極佳：
- 迴圈體重複執行 $N$ 次 → **時間局部性**把指令留在快取。
- 按序掃描陣列 → **空間局部性**讓每個 cache line（block）的每個 byte 都被用到。
**2^n 法則**：快取容量每加倍，miss rate 約**減半**（直到局部性飽和）：
$$\text{miss rate}(2C) \approx \frac{\text{miss rate}(C)}{2} \quad\Longrightarrow\quad \text{miss rate}(C) \propto \frac{1}{C}.$$
**90/10 規律**：程式 **10% 的程式碼佔 90% 的執行時間**——
快取只需容納這 10%，就能攔截絕大多數存取。

### 第三條線索：cache 組織（direct-mapped、set-associative、全相聯）
主記憶體位址對映到快取的三種方式：
| 組織 | 對映規則 | 硬體成本 | miss 率 |
|------|---------|---------|---------|
| **全相聯** | 任何 block 可放任何位置 | 最高（比較器最多） | 最低 |
| **組相聯**（$n$-way） | 每 block 可放 $2^n$ 個 set 中的任一 | 中 | 中 |
| **直接對映** | block 只能放**唯一**位置：$\text{index} = (\text{addr} \div \text{line size}) \bmod C$ | 最低 | 最高 |
位址拆解（組相聯）：
$$\text{位址} = \underbrace{\text{tag}}_{\text{高位}} \;|\; \underbrace{\text{set index}}_{\log_2 S \text{ 位元}} \;|\; \underbrace{\text{block offset}}_{\log_2 B \text{ 位元}}.$$
- $n$-way 組相聯：$2^n$ 路比較器並行比對 tag——**$n$ 越大越快命中，但越貴**。
- IBM 360/85 用的是**組相聯**的先驅設計；現代 L1 用 4–8 way，L3 用 8–16 way。

### 第四條線索：替換與寫入策略
- **替換策略（replacement）**：組相聯滿了要驅逐一個 block——
  **LRU（Least Recently Used，最近最少使用）**：利用時間局部性，驅逐最久沒用的。
  精確 LRU 需 $n!$ 狀態追蹤，實作用近似（pseudo-LRU、計數器）。
- **寫入策略（write policy）**：
  - **write-through**：寫快取時**同步寫主記憶體**——簡單但慢（每次寫都上匯流排）。
  - **write-back**：只寫快取，**驅逐時才寫回**主記憶體（需 dirty bit）——快但一致性複雜，**現代 L1/L2 用之**。
- **多層階層**：一層快取不夠，就疊多層：
$$\text{AMAT} = t_{L1} + m_{L1}(t_{L2} + m_{L2}(t_{L3} + m_{L3} \cdot t_{mem})).$$
  L1 小而快（~1 ns）、L2 中（~4 ns）、L3 大而慢（~15 ns）、DRAM 慢（~80 ns）——
  **每一層都在為下一層攔截 miss**。

### 第五條線索：三 C 模型（miss 的三種病因）
Mark Hill（1987）把 miss 分成三類——**三 C 模型**：
- **Compulsory（冷啟動）**：第一次存取，無可避免——解法：**prefetch（預取）**。
- **Capacity（容量）**：快取太小裝不下工作集——解法：**加大快取**。
- **Conflict（衝突）**：對映碰撞（多個熱 block 擠同一 set）——解法：**提高相聯度**。
$$\text{miss} = \text{compulsory} + \text{capacity} + \text{conflict} \quad\Longrightarrow\quad \text{三 C 決定快取設計的方向}.$$

### Python：direct-mapped 與 set-associative cache 模擬

```python
# 快取模擬：direct-mapped vs 2-way set-associative，算 hit/miss 率與 AMAT

def cache_sim(accesses, cache_lines=8, ways=1, line_size=4):
    """accesses: 位址序列（word 為單位）；ways=1 即 direct-mapped"""
    n_sets = cache_lines // ways
    cache = [None] * cache_lines          # [tag] 或 None
    age = [0] * cache_lines               # LRU 計數
    hits = misses = clock = 0

    for addr in accesses:
        clock += 1
        block = addr // line_size
        s, tag = block % n_sets, block // n_sets
        candidates = [s * ways + w for w in range(ways)]
        if any(cache[c] == tag for c in candidates):    # hit
            hits += 1
            age[next(c for c in candidates if cache[c] == tag)] = clock
        else:                                           # miss
            misses += 1
            valid = [c for c in candidates if cache[c] is not None]
            c = (next(c for c in candidates if cache[c] is None) if len(valid) < ways
                 else min(valid, key=lambda c: age[c]))  # LRU 驅逐
            cache[c], age[c] = tag, clock

    total = hits + misses
    t_hit, t_miss = 1, 12  # ns（L1 命中 1ns，miss 去 L2/記憶體 12ns）
    amat = t_hit + (misses / total) * t_miss
    return hits, misses, hits/total, amat

seq_fit  = [a for _ in range(4) for a in range(32)]   # 8 blocks，塞得進 8-line cache
seq_big  = [a for _ in range(4) for a in range(64)]   # 16 blocks，容量不足
seq_conf = ([a for a in range(16)] + [a + 32 for a in range(16)]) * 4  # 兩陣列映射到同組

for seq, name in [(seq_fit, "局部性佳（32-word×4輪）"),
                  (seq_big, "容量不足（64-word×4輪）"),
                  (seq_conf, "同組衝突（兩陣列交替）")]:
    for ways in (1, 2, 4):
        wname = {1: "direct-mapped", 2: "2-way      ", 4: "4-way      "}[ways]
        h, m, hr, amat = cache_sim(seq, cache_lines=8, ways=ways)
        print(f"{name} | {wname}: 命中率 {hr*100:5.1f}%, AMAT {amat:5.2f} ns")
    print()
```

```
局部性佳（32-word×4輪） | 4-way      : 命中率  93.8%, AMAT  1.75 ns

容量不足（64-word×4輪） | 2-way      : 命中率  75.0%, AMAT  4.00 ns
容量不足（64-word×4輪） | 4-way      : 命中率  75.0%, AMAT  4.00 ns

同組衝突（兩陣列交替） | direct-mapped: 命中率  75.0%, AMAT  4.00 ns
同組衝突（兩陣列交替） | 2-way      : 命中率  93.8%, AMAT  1.75 ns

```
（模擬對應**三 C 模型**的三種病因：**局部性佳**的序列 direct-mapped 就攔截 93.8%
（局部性的功勞）；**容量不足**時怎麼提高相聯度都沒用（capacity 只能加大快取）；
**同組衝突**時 direct-mapped 掉到 75%，提高到 2-way 就恢復 93.8%（conflict 用相聯度解決）——
**這就是為什麼 L1 用 4–8 way 就夠，不必全相聯**。AMAT 從 12 ns 降到 1.75 ns——**快取的威力**。）

## 結案 -- 後果與影響
- **記憶體階層成為標準**：360/85（1969）之後快取成為大型機標配（IBM 3033、Amdahl 470）；
  **1980s 微處理器**：Motorola 68020（1984）首顆內建快取，**Intel 486（1989）** 首顆內建 L1 的 x86；
  **1990s–2020s**：L1/L2/L3 三層成為標準——L1 約 32–64 KB（ns 級）、
  L3 可達 100+ MB（Apple M 系列），**容量成長萬倍，思想未變**。
- **cache line 與 prefetch**：cache line（64 bytes）成為記憶體傳輸的單位；
  **硬體預取（prefetch）**攔截 compulsory miss——三 C 模型指導了整個 1990s 的快取優化。
- **記憶體牆（memory wall）戰役至今**：CPU 速度成長遠快於 DRAM（DRAM 延遲 40 年只降 ~10 倍，
  CPU 頻率降萬倍）——**processor-memory gap 越拉越大**；
  解法一路演進：更大快取 → 多層階層 → **亂序執行隱藏延遲**（見「1967-Tomasulo演算法.md」）
  → **多執行緒（SMT）** → **HBM 高頻寬記憶體**；
  **AI 時代的記憶體牆**：GPU 訓練的瓶頸在 HBM 頻寬（見「2012-GPU深度學習算力.md」）——
  1969 年的命題在 2020s 換了戰場繼續打。
- **局部性成為軟體工程的基本功**：cache-friendly 資料結構、
  row-major 遍歷、blocking/tiling（矩陣分塊）——**HPC 與深度學習的核心優化技術**都源於局部性原理。
- **Amdahl 式的教訓**：無論 CPU 多快，
  $$S = \frac{1}{(1-m) + m \cdot \frac{t_{mem}}{t_{cache}}}$$
  只要有 $m$ 比例的存取打到慢記憶體，性能就被拉回——**快取優化是永遠的戰場**。
