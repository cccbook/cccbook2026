# 1991 - 分支預測：賭徒與流水線的推理遊戲

## 案件摘要
1991 年，T.-Y. Yeh 與 Yale Patt 在 Hsu/Patt 的工作基礎上發表
**two-level adaptive branch prediction**（兩層自適應分支預測）——
用「**分支的歷史紀錄歷史**」來預測分支，把預測準確率從 90% 推上 98%+。
配合**推測執行（speculative execution）**，CPU 開始「猜測未來並先做再說」——
猜錯就回滾（rollback），猜對就大賺。
**這是現代 CPU 性能的基石，也是 2018 年 Spectre/Meltdown 安全災難的案源。**

## 前因 -- 為什麼會有這個案子
- **流水線的分支代價**：5 級流水線中，分支指令要到第 4–5 級才知道「跳不跳、跳去哪」——
  在此之前 CPU 必須**停頓（stall）或亂猜**。每次分支的浪費：
  $$\text{mispredict penalty} = O(\text{pipeline depth}) \quad (\text{級數越深的流水線，猜錯越痛}).$$
- **分支無所不在**：典型程式**每 5–6 條指令就有 1 條分支**（迴圈、if、函式呼叫）。
  若每次分支都停 3 個週期：
  $$\text{有效 IPC} = \frac{1}{1 + \dfrac{0.2 \times 3}{1}} = 0.625 \quad\Longrightarrow\quad \text{性能直接打 } 6\text{ 折}.$$
- **硬體越深，問題越兇**：RISC 戰爭（見「1981-CISC與RISC之戰.md」）讓流水線從 5 級加深到 10+ 級、
  超標量每週期發射多條指令——**一個分支猜錯要丟掉 10–20 條在飛的指令**。
- **預測演算法的軍備競賽已開打**：static（1980s 編譯器提示）、1-bit bimodal、2-bit 飽和計數器
  陸續出現，但都只有「單層記憶」——Yeh/Patt 的洞見是**記住「歷史的歷史」**：
  同一個分支在不同歷史情境下的行為完全不同。

## 線索與推理 -- 數學式、程式、理論

### 第一條線索：預測演算法的進化史
| 演算法 | 年代 | 策略 | 準確率（典型） |
|--------|------|------|---------------|
| **Static** | 1980s | 總是預測不跳／向後跳（編譯器提示） | ~65–85% |
| **1-bit bimodal** | 1980s | 記住上次跳不跳 | ~85–90%（迴圈尾端必錯一次） |
| **2-bit 飽和計數器** | 1981+ | 狀態機：連錯兩次才改變預測 | ~90–93% |
| **Two-level adaptive** | **1991** | 歷史表 + 樣式表（記住歷史的歷史） | **~95–98%** |
| **gshare** | 1991 | 分支位址 XOR 全域歷史 → 索引 | ~95%+ |
| **TAGE** | 2010s | 多長度歷史的標籤幾何表 | **99%+**（現代 CPU 標配） |

### 第二條線索：2-bit 飽和計數器狀態機
2-bit 計數器有 4 個狀態，**連續兩次預測錯誤才改變立場**（抵抗偶然的例外）：
$$\text{ST(強跳)} \to \text{WT(弱跳)} \to \text{WN(弱不跳)} \to \text{SN(強不跳)}.$$
- 預測取狀態高位元：ST/WT 預測「跳」，WN/SN 預測「不跳」。
- **迴圈範例**（跳 9 次後不跳 1 次）：1-bit 預測器**每次迴圈錯 2 次**（開頭與尾端），
  2-bit 預測器**每迴圈只錯 1 次**（尾端）——這就是飽和計數器的勝利。
- 限制：**單層記憶**。同一分支若行為隨情境改變（如 `if (x > 0)` 中 x 有規律），
  2-bit 計數器只會給出一個平均答案。

### 第三條線索：Yeh/Patt 的 two-level adaptive 預測
**兩層結構**：第一層記「這個分支最近的歷史」（branch history register），
第二層用歷史當索引查「歷史樣式表」（pattern history table, PHT）：
$$\text{分支位址} + \text{近期歷史 } (b_{n-1}, \dots, b_0) \xrightarrow{\text{索引}} \text{PHT} \to \text{2-bit 預測}.$$
- **核心洞見**：許多分支的行為是「**歷史的函數**」——
  例如 `a[0]=1, a[1]=0, a[2]=1, a[3]=0...` 中 `if (a[i])`，
  2-bit 計數器錯 50%，two-level 用長度 2 的歷史可 **100% 預測**（00 → 不跳, 10 → 跳...）。
- **gshare 變體（1991，McFarling）**：分支位址 XOR 全域歷史後索引 PHT——
  讓所有分支共享一張大表又互不干擾。
- **BTB（Branch Target Buffer）**：預測要配合「跳去哪」——BTB 以分支位址為索引，
  快取**分支目標位址**，讓 CPU 在取指階段就重定向——零延遲的目標預測。

### 第四條線索：推測執行與猜錯代價
- **推測執行**：預測後**直接沿預測路徑執行**（不只取指），結果先寫入重命名暫存器/ROB；
  確認正確才「退役（retire）」，猜錯就**整段回滾**：
  $$\text{期望性能} = \frac{1}{1 + p \times m \times \text{depth}} \quad (\text{Amdahl 式分支代價：} p \text{ = 分支頻率, } m \text{ = 猜錯率}).$$
- **數字推理**：$p = 0.2$、mispredict penalty = 15 週期（深流水線）：
  - 1-bit（m = 0.10）：$S = \dfrac{1}{1 + 0.2 \times 0.10 \times 15} = 0.83$
  - 2-bit（m = 0.07）：$S = 0.88$
  - two-level（m = 0.02）：$S = 0.94$
  **預測準確率每提升 1%，整機性能就提升約 1–3%**——這是 CPU 設計者的軍備競賽動機。
- **副作用伏筆**：推測執行雖然回滾了**架構狀態**（暫存器、記憶體寫入），
  但**微架構副作用**（cache 狀態、執行時間）留下痕跡——
  2018 年 **Spectre/Meltdown** 攻擊正是用「故意猜錯 → 測量 cache 副作用 → 偷出秘密」，
  **把 27 年前的性能技巧變成安全漏洞**。

### Python：分支預測器模擬（static / 1-bit / 2-bit / gshare）

```python
def predict_static(seq):
    """static：總是預測不跳"""
    return sum(pred != actual for pred, actual in zip([0]*len(seq), seq))

def predict_1bit(seq, table_bits=4):
    """1-bit bimodal：記住上次結果（每位址一個 bit）"""
    table = [0] * (1 << table_bits)
    miss = 0
    for i, actual in enumerate(seq):
        idx = i & (table_bits - 1)  # 簡化：用循環位置索引
        if table[idx] != actual:
            miss += 1
        table[idx] = actual
    return miss

def predict_2bit(seq, table_bits=4):
    """2-bit 飽和計數器：狀態 0..3，>=2 預測跳；連錯兩次才改立場"""
    table = [0] * (1 << table_bits)
    miss = 0
    for i, actual in enumerate(seq):
        idx = i & (table_bits - 1)
        pred = 1 if table[idx] >= 2 else 0
        if pred != actual:
            miss += 1
        table[idx] = max(0, min(3, table[idx] + (1 if actual else -1)))
    return miss

def predict_gshare(seq, table_bits=4):
    """gshare：分支位址 XOR 全域歷史 → 索引 2-bit PHT（此處位址取 0，退化為純全域歷史索引）"""
    table = [1] * (1 << table_bits)
    gh, miss = 0, 0
    for i, actual in enumerate(seq):
        idx = gh & ((1 << table_bits) - 1)
        pred = 1 if table[idx] >= 2 else 0
        if pred != actual:
            miss += 1
        table[idx] = max(0, min(3, table[idx] + (1 if actual else -1)))
        gh = ((gh << 1) | actual) & ((1 << table_bits) - 1)
    return miss

# 測試序列：50 次的 9-跳迴圈（迴圈尾端必錯）+ 規律交錯段（two-level 的主場）
loop = [1]*9 + [0]
seq = loop*50 + [1,0]*50
for name, fn in [("static", predict_static), ("1-bit", predict_1bit),
                 ("2-bit", predict_2bit), ("gshare", predict_gshare)]:
    miss = fn(seq)
    print(f"{name:7s}: 錯 {miss:3d} / {len(seq)} → 準確率 {100*(1-miss/len(seq)):.1f}%")
```
輸出：
```
static  : 錯 500 / 600 → 準確率 16.7%
1-bit   : 錯 104 / 600 → 準確率 82.7%
2-bit   : 錯  62 / 600 → 準確率 89.7%
gshare  : 錯  60 / 600 → 準確率 90.0%
```
（偵辦結論：**1-bit 預測器每次迴圈錯 2 次**（104 ≈ 2×50 + 過渡）、
**2-bit 只錯 1 次/迴圈**（62）——飽和計數器如理論所料；
對**規律交錯**的分支，單層預測器束手無策，
two-level 用歷史當索引可達 **100%**（Yeh/Patt 1991 的核心實驗）；
static 在真實分支序列上慘不忍睹，證明「預測必須自適應」。）

## 結案 -- 後果與影響
- **推測執行成為現代 CPU 標準（1995–）**：
  - **Intel Pentium Pro（1995）**：P6 微架構首度把**亂序執行 + 推測執行 + 分支預測**整合量產。
  - **PowerPC 604（1994）**、AMD K7（1999）跟進——推測執行成為高性能 CPU 的必備配備。
- **準確率軍備競賽**：從 2-bit 的 ~90% 到 two-level 的 98%，
  再到 **TAGE（2010s，Seznec）的 99%+**——現代 CPU（Intel/AMD/Apple M 系列）的分支預測器
  都是 TAGE 系或其變體，**配合數萬位元的歷史表**。
- **深流水線的通行證**：Intel Pentium 4 的 20–31 級超深流水線，
  完全依賴 99% 準確率的分支預測——**沒有分支預測，就沒有 GHz 時代**。
- **Spectre/Meltdown 的教訓（2018）**：
  攻擊者用推測執行的**微架構副作用**（cache 通道）偷出核心記憶體——
  影響幾乎所有 1995 年後的 CPU，迫使作業系統與硬體加裝防護（KPTI、retpoline）。
  **教訓：性能機制會留下可測量的痕跡，痕跡就是攻擊面。**
- **與 AI 時代的連結**：分支預測的「用歷史預測未來 + 查表」思想，
  與現代**推測式記憶體預取、值預測**一脈相承——**「賭對就賺」的哲學貫穿了整個微架構史**。
- 歷史定位：Yeh/Patt 兩層預測證明——**一個純演算法的改進（不動電路結構）
  可以帶來 10–30% 的整機性能提升**，這是電腦架構史上投資報酬率最高的「軟體式」破案之一。
