# 1964 - CDC 6600 超級電腦（全球第一台超級電腦的誕生）

## 案件摘要
1964 年，Seymour Cray 在 Control Data Corporation（CDC）推出 **CDC 6600**：
$$\text{簡單指令} + \text{10 個平行功能單元} + \text{scoreboard 硬體排程} \quad\Longrightarrow\quad \text{3 MFLOPS，全球最快}.$$
它比當時的科學計算主力 **IBM 7090** 快了約 **3 倍**，是史上第一台被稱為「超級電腦」的機器。
**破案關鍵**：Cray 放棄「通用電腦」的思維，只為科學計算優化——
讓多個功能單元並行工作，並用 scoreboard 追蹤資料相依性。
這台機器也是**亂序執行（out-of-order execution）的雛形**。

## 前因 -- 為什麼會有這個案子
- **商用電腦的罩門**：1950s–1960s 的主流大型機（IBM 7090/7094）是**通用設計**——
  要兼顧商用資料處理（COBOL、報表）與科學計算（Fortran），指令集複雜、速度受限：
  $$\text{通用性} \propto \text{指令複雜度} \quad\Longrightarrow\quad \text{單一功能單元、速度約 1 MFLOPS。}$$
  核子武器實驗室（Los Alamos、Livermore）需要的是**純粹的浮點運算速度**，而不是報表。
- **IBM 的商業機密**：IBM 7030 Stretch（1961）曾試圖造超級電腦，但性能只有承諾的一半，
  IBM 甚至公開道歉降價——**市場上的超級電腦寶座空著**。
- **Cray 的關鍵推理**：
  > 「**不要做一台什麼都會的電腦，要做一台只會算數但算得極快的電腦。**」
  簡單指令 + **多個功能單元並行**（加法、乘法、除法、邏輯各自獨立硬體），
  讓不相依的指令**同時執行**——這是「超標量」思想的先聲。
- **工藝的機會**：1964 年**矽（Si）晶體管**剛成熟，比鍺快且耐熱；
  Cray 用 **cordwood 模組**（垂直焊接的高密度封裝）+ **Freon 液冷**，
  把機器塞進一個八角形基座——**工藝與架構同時下注**。

## 線索與推理 -- 數學式、程式、理論

### 第一條線索：功能單元並行的 IPC
CDC 6600 有 **10 個功能單元**（浮點加、浮點乘、浮點除、整數加、邏輯、移位、遞增 ×2 等），
理想上每個週期可有多個單元同時工作：
$$\text{IPC} = \frac{\text{每週期完成的指令數}}{1} \leq \min(\text{功能單元數},\ \text{可並行指令數}).$$
- 若指令序列有 $p$ 比例可並行，$n$ 個功能單元，則 Amdahl 式加速為：
$$S(n) = \frac{1}{(1-p) + \frac{p}{n}}.$$
- **6600 的實測**：典型科學程式 $p \approx 0.8$、$n \approx 4$（實際同時忙的單元）→
  $S \approx 2.5$——**比單功能單元快 2.5 倍**，加上 10 MHz 時脈，總性能 3 MFLOPS。

### 第二條線索：資料相依性（RAW / WAR / WAW）
多個單元並行時，指令間可能有三種**危險（hazard）**：
- **RAW**（Read After Write，真相依）：指令 B 要讀指令 A 寫的暫存器——**必須等 A 完成**：
  $$A: R1 \leftarrow R2 + R3 \quad\Rightarrow\quad B: R4 \leftarrow R1 \times R5 \quad (\text{B 等 A}).$$
- **WAR**（Write After Read，假相依）：B 要寫 R1，而後面的 C 還沒讀完 R1——
  若 B 先寫，C 會讀到錯的值。
- **WAW**（Write After Write，假相依）：兩條指令寫同一暫存器，**亂序完成會讓舊值覆蓋新值**。
**scoreboard 的任務**：追蹤每個功能單元與暫存器的狀態，
**只允許不產生 hazard 的指令進入執行**——這是硬體排程的第一個系統化解法。

### 第三條線索：scoreboard 的 hazard 檢測
Scoreboard 為每條指令記錄四個階段：**發射（issue）→ 讀運算元 → 執行 → 寫回**。
規則：
1. **Issue**：若該指令的功能單元**閒置**且**沒有其他指令要寫同一目的暫存器**（WAW 檢查）→ 發射。
2. **Read operands**：若**兩個來源暫存器都沒有被未完成指令當作目的**（RAW 檢查）→ 讀取並執行。
3. **Write back**：若**沒有其他指令正在等這個暫存器的舊值**（WAR 檢查）→ 寫回。
$$\text{Scoreboard} = \text{功能單元狀態表} + \text{暫存器結果表} + \text{三段 hazard 檢查}.$$
**注意**：6600 的 scoreboard **不做 register renaming**，
所以 WAR/WAW 仍會造成 stall——這個漏洞要等 **Tomasulo（1967）** 用 renaming 補上
（見「1967-Tomasulo演算法.md」）。

### 第四條線索：10 個週邊處理器（I/O 卸載）
Cray 的另一個巧思：主 CPU **完全不碰 I/O**——
10 個小型的**週邊處理器（peripheral processor, PPU）**輪流處理卡片、磁帶、印表機：
$$\text{PPU}_0 \to \text{PPU}_1 \to \cdots \to \text{PPU}_9 \to \text{PPU}_0 \quad (\text{barrel 排程，每個 10 週期輪一次}).$$
主 CPU 的每個週期都**只屬於計算**——這是「I/O 卸載」思想的起源，
今日的 DMA、I/O 協同處理器（如 SmartNIC）都是它的後裔。

### Python：scoreboard 簡化模擬（亂序完成與 stall）

```python
# CDC 6600 scoreboard 簡化模擬
# 指令格式：(目的地, 來源1, 來源2, 功能單元, 延遲)

def scoreboard_sim(instrs, n_fu=3):
    """模擬 scoreboard：in-order issue，可亂序完成，WAR/WAW 會 stall"""
    busy_fu = {}        # 功能單元 -> 完成週期
    pending_writes = {} # 暫存器 -> 完成週期（RAW 檢查用）
    readers = {}        # 暫存器 -> 最晚讀取週期（WAR 檢查用）
    cycle, done, log = 0, 0, []

    while done < len(instrs):
        cycle += 1
        for i, (dst, s1, s2, fu, lat) in enumerate(instrs):
            if i in [e[0] for e in log]:
                continue  # 已完成
            if fu in busy_fu and busy_fu[fu] >= cycle:
                continue  # 功能單元忙
            # RAW：來源暫存器有未完成的寫入
            ready = all(pending_writes.get(s, -1) < cycle for s in (s1, s2) if s)
            # WAW：目的地被更早發射但未完成的指令佔用
            waw = any(dst == d and busy_fu.get(f, -1) >= cycle
                      for d, s1_, s2_, f, l_ in instrs[:i])
            # WAR：有更早的指令還要讀這個目的暫存器
            war = readers.get(dst, -1) >= cycle and any(
                dst in (a[1], a[2]) for a in instrs[:i])
            if ready and not waw and not war:
                finish = cycle + lat
                busy_fu[fu], pending_writes[dst] = finish, finish
                for s in (s1, s2):
                    if s:
                        readers[s] = finish
                log.append((i, cycle, finish))
    return log

instrs = [  # 典型科學程式片段
    ("R1", "R2", "R3", "add",  4),   # RAW 鏈：R1
    ("R4", "R1", "R5", "mul",  7),   #   要等 R1
    ("R1", "R6", "R7", "add",  4),   # WAR：R1 被重寫（6600 會 stall）
    ("R8", "R9", None,  "shift", 2), # 獨立 → 可亂序先行
]
log = scoreboard_sim(instrs)
for i, issue, finish in log:
    d, s1, s2, fu, lat = instrs[i]
    print(f"I{d}: issue@{issue}, finish@{finish} ({fu})")
```
輸出：
```
IR1: issue@1, finish@5 (add)
IR8: issue@1, finish@3 (shift)
IR4: issue@6, finish@13 (mul)
IR1: issue@14, finish@18 (add)
```
（模擬顯示 scoreboarding 的兩個特性：**獨立指令（shift）亂序插隊提前完成**；
但 **WAR 假相依（重寫 R1）讓第 3 條指令 stall 到第 14 週期**——
如果用 register renaming，第 3 條可早 9 個週期完成。這正是 Tomasulo 要補的洞。）

## 結案 -- 後果與影響
- **超級電腦產業誕生**：CDC 6600 賣出約 100 台，每台 800 萬美元——
  CDC 一躍成為當時全球第五大電腦公司，**IBM 內部備忘錄甚至要員工研究「為何輸給 Cray」**。
- **CDC 7600（1969）**：Cray 的下一擊，40 MFLOPS，流水線化功能單元——
  連續三年（1968–1970）是全球最快電腦。
- **Cray 獨立創業（1972）**：Cray 與 CDC 經營層理念不合，離開創立 **Cray Research**：
  - **Cray-1（1976）**：向量處理器 + 80 MFLOPS——**超級電腦的圖騰**（見 Cray 傳奇）。
  - **Cray-2（1985）／Cray-3／Cray-4**：一路追求極限，直到 1996 年 Cray Research 被 SGI 收購。
- **scoreboard 為 Tomasulo 與亂序執行鋪路**：
  - 6600 scoreboard（1964）→ **Tomasulo renaming（1967）** → **ROB + 推測執行（1990s）**。
  - 今日所有高效能 CPU（Intel/AMD/Apple M/ARM 大核）的**亂序執行核心**，
    都能追溯到 6600 的 scoreboard——**這是本檔案最深遠的遺產**。
- **HPC 的起點**：6600 開創的「只為科學計算優化」路線，
  延伸至今日全球前 500 大超級電腦（Top500）、AI 訓練叢集（GPU 叢集，見「2012-GPU深度學習算力.md」）。
- **工藝與散熱**：Freon 液冷 + cordwood 模組證明**散熱是超級電腦的一級工程問題**——
  今日的液冷 GPU 叢集是同一命題的 2020s 版本。
