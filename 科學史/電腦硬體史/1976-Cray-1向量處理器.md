# 1976 - Cray-1 向量處理器：世界最快電腦的「C 形」偵探報告

## 案件摘要
1976 年，Seymour Cray 離開 CDC 後創立 Cray Research，推出 **Cray-1**——
世界第一部正式商品化的**向量超級電腦**：80 MHz 時脈、峰值 160 MFLOPS、氟化液冷系統、
以及史上最著名的**C 形圓弧機殼**（把機櫃排成弧形以縮短內部走線長度）。
它沒有發明任何一種新元件，卻把「**一條指令處理一整個向量**」的哲學推到極致，
開啟了高效能計算（HPC）的黃金年代。
**本案偵辦重點：為什麼最快的純量處理器也救不了科學計算，而向量機能？**

## 前因 -- 為什麼會有這個案子
- **CDC 6600/7600 的遺產（1964–1969）**：
  Seymour Cray 在 CDC 設計出世界第一台超級電腦 CDC 6600（3 MFLOPS 級），再進化到 CDC 7600。
  但 Cray 發現了一個結構性罩門：**純量（scalar）機器每條指令只處理一個數字**，
  而科學計算（矩陣、流體力學、核爆模擬）處理的是**整個陣列**。
- **純量處理器的三重浪費**：
  - **迴圈開銷**：對長度 $N$ 的陣列做運算，需要 $N$ 次迴圈迭代，每次都有索引更新、
    條件判斷、跳躍——真正算數的指令反而佔少數：
    $$\text{有用運算} \ll \text{總指令數} \quad (\text{典型向量核內有用指令佔比僅 } 20\text{–}40\%).$$
  - **指令頻寬不足**：每個時脈週期只能發射 1 條指令，而浮點運算要 3–4 個週期，
    CPU 大部分時間在「等」與「跳」。
  - **記憶體牆的雛形**：純量機一次 load 一個字，記憶體頻寬利用率極低。
- **Star-100 的先驅（CDC, 1974）**：CDC 曾推出向量機 Star-100，但採「記憶體到記憶體」架構、
  管線極深（啟動延遲長），短向量性能慘烈——**證明了方向正確、設計錯誤的下場**。
- **Cray 的裁決**：向量指令 + **向量暫存器（vector register）** 才是正解——
  把整個向量的中間結果留在 CPU 內，不必反覆穿越記憶體。

## 線索與推理 -- 數學式、程式、理論

### 第一條線索：一條指令，一整個向量
Cray-1 的核心概念：**單一指令 = 一整個向量的運算**。
例如 Fortran 迴圈：
```fortran
DO I = 1, 64
  C(I) = A(I) + B(I)
END DO
```
- **純量機**：需要約 $64 \times 5 \approx 320$ 條指令（load、add、store、索引、branch）。
- **Cray-1**：只需要 **3 條指令**：
  $$V1 \leftarrow A; \quad V2 \leftarrow B; \quad V3 \leftarrow V1 + V2 \quad (\text{再 } \text{store } C \leftarrow V3).$$
  向量單元在管線中**每個週期產生一個結果元素**——
  $$\text{總週期} \approx \text{管線深度} + N \quad (\text{而非 } kN, \; k \text{ 為每元素週期數}).$$
- **向量暫存器**：Cray-1 有 **8 個向量暫存器，每個 64 元素 × 64 bits**（S 暫存器為純量）。
  這 512 個元素是「向量機的快取」——**短向量也能全程留在暫存器內**，避開 Star-100 的災難。

### 第二條線索：管線深化與 chaining（向量鏈結）
Cray-1 是**深度管線機器**：每條功能管線 3–14 級，且**多條管線並行**（加法、乘法、移位、邏輯各自獨立）。
- **Chaining（鏈結）**是 Cray-1 最漂亮的技巧：
  **前一條向量指令的結果一產生，就立刻餵給下一條指令當運算元**——
  $$A+B \text{ 的輸出流} \xrightarrow{\text{鏈結}} \times C \text{ 的輸入} \quad\Longrightarrow\quad \text{add 管線與 mul 管線同時工作}.$$
  例如 $D = (A+B) \times C$：add 管線每週期吐出一個 $(a_i+b_i)$，乘法管線立刻接手乘上 $c_i$——
  兩條管線形成**接力流水線**，等效頻寬加倍：
  $$\text{鏈結後每元素週期} \approx \max(t_{add}, t_{mul}) \quad \text{而非} \quad t_{add} + t_{mul}.$$
- 這是後來**記憶體管線**與現代 CPU「轉發（forwarding）」網路的祖師爺。

### 第三條線索：Amdahl 定律的向量版
向量加速不是無限的——**程式裡不能向量化的串行部分**會吃掉一切（Amdahl 定律的向量形式）：
$$S = \frac{1}{(1-f) + \dfrac{f}{r}} \quad \text{（} f \text{ = 可向量化比例，} r \text{ = 向量加速比）}.$$
- 若 $r = 10$（向量單元比純量快 10 倍）：
  - $f = 0.9$：$S = \dfrac{1}{0.1 + 0.09} = 5.26$
  - $f = 0.99$：$S = \dfrac{1}{0.01 + 0.099} = 9.17$
- **推論**：向量機只有在程式 **90%+ 可向量化**時才划算——這催生了「自動向量化編譯器」的軍備競賽。
- 這也是 **Roofline 模型**的前身：性能由「計算峰值」與「記憶體頻寬 × 運算強度」取小者決定：
  $$\text{perf} = \min(\text{peak}, \; \text{BW} \times \text{intensity}) \quad \text{（intensity = 每讀寫 1 byte 的浮點運算數）}.$$
  Cray-1 的 BW 與 peak 設計得很平衡（兩個記憶體埠 ≈ 2 words/cycle @ 80 MHz），
  **這個「算術強度 vs 頻寬」的思考方式，一直延續到今天的 GPU**。

### 第四條線索：矩陣運算、LINPACK 與向量化編譯器
- **LINPACK benchmark（1979，Jack Dongarra）**：
  原本是量測線性代數套件的報告，因 Cray-1 的出現變成**超級電腦的標準速度測試**——
  它是「矩陣乘法/分解」這類規律運算，正是向量機的主場（$O(N^3)$ 運算、$O(N^2)$ 資料）。
- **Fortran 向量編譯器（CFT）**：自動偵測可向量化的迴圈（無相依性、無分支）並生成向量指令——
  **「編譯器自動向量化」從此成為 HPC 編譯器的標配**，一直延續到今天的 nvcc/GPU 編譯器。
- **Cray-1 vs CDC 7600**：7600 峰值約 36 MFLOPS 級但靠指令並行硬撐；
  Cray-1 以 80 MHz + chaining 直接做到 160 MFLOPS——**結構性勝利，不是頻率勝利**。

### Python：向量化模擬與 Roofline 加速比

```python
def scalar_cycles(n, overhead_per_iter=5, fp_cycles=4, pipeline_depth=4):
    """純量機：每迭代 = 載入+運算+存回+索引+分支（overhead 條指令）"""
    return n * (overhead_per_iter + fp_cycles) + pipeline_depth

def vector_cycles(n, vlen=64, setup=4, elem_cycles=1, pipeline_depth=8):
    """向量機：setup 幾條指令 + 每元素 1 cycle 的管線結果流（向量長度上限 vlen）"""
    num_vectors = (n + vlen - 1) // vlen
    return num_vectors * (setup + pipeline_depth) + n * elem_cycles

# 1) scalar vs vector 的週期數比較
for n in [64, 256, 1024, 8192]:
    s, v = scalar_cycles(n), vector_cycles(n)
    print(f"N={n:5d}: scalar {s:6d} cycles, vector {v:6d} cycles → 加速 {s/v:5.2f}x")

# 2) Amdahl 向量版：加速比 vs 可向量化比例
def amdahl_vector(f, r):
    return 1 / ((1-f) + f/r)

print()
for f in [0.5, 0.8, 0.9, 0.95, 0.99]:
    print(f"f={f:.2f}, r=10 → S = {amdahl_vector(f, 10):.2f}x")

# 3) Roofline：性能 = min(峰值, 頻寬 × 運算強度)
peak, bw = 160e6, 40e6   # FLOPS, words/cycle(換算)
print()
for intensity in [0.5, 1, 2, 4]:
    perf = min(peak, bw * intensity)
    print(f"intensity={intensity} → perf = {perf/1e6:5.0f} MFLOPS {'(頻寬受限)' if perf < peak else '(計算受限)'}")
```
輸出：
```

N=  256: scalar   2308 cycles, vector    304 cycles → 加速  7.59x

N= 8192: scalar  73732 cycles, vector   9728 cycles → 加速  7.58x


f=0.50, r=10 → S = 1.82x
f=0.80, r=10 → S = 3.57x
f=0.90, r=10 → S = 5.26x
f=0.95, r=10 → S = 6.90x
f=0.99, r=10 → S = 9.17x

intensity=0.5 → perf =    20 MFLOPS (頻寬受限)
intensity=1 → perf =    40 MFLOPS (頻寬受限)
intensity=2 → perf =    80 MFLOPS (頻寬受限)

```
（偵辦結論：管線攤提後，**向量機在所有長度都有 5–7.6x 的加速**——迴圈開銷被一次指令抹平；
而 Amdahl 向量版告訴我們——**向量化比例 f 才是超級電腦的真正戰場**，
這正是 Cray 花大力氣做 Fortran 自動向量化編譯器的原因。）

## 結案 -- 後果與影響
- **HPC 產業的誕生（1976–1990s）**：Cray-1 熱賣（售價 800–1600 萬美元），
  Cray-2（1985，8 處理器）、Cray X-MP（1982，多 CPU + 更強 chaining）接連問世——
  「超級電腦」從實驗室玩具變成產業。
- **LINPACK → TOP500（1993）**：Dongarra 的 LINPACK benchmark 成為 **TOP500 榜單**的評測標準，
  每半年公布世界最快 500 台電腦——HPC 從此有了「全球排行榜」。
- **向量 → SIMD（x86 的精神源頭）**：向量機的「一條指令多資料」思想，
  縮小成 64/128-bit 暫存器版本就是 **SIMD**——
  x86 MMX（1997）、SSE（1999）、AVX（2011, 256/512-bit）**都是 Cray-1 的孫子**。
- **日本 FESP 競逐（1980s）**：Fujitsu VP、NEC SX、Hitachi S 系列以更激進的向量機反攻世界市場，
  1990 年代 NEC SX-4 一度打敗 Cray——**「日本超級電腦衝擊」逼出美國政府扶植政策**。
- **向量機 vs 超標量**：1990s 後通用 CPU（超標量 + 快取）在性價比上追上向量機，
  HPC 轉向**大量商用處理器組成的叢集（cluster）**；但向量思想轉移到 SIMD、GPU 與 AI 加速器中存活。
- **GPU 的前身**：GPU 的「大量執行單元 + 規律資料 + 頻寬至上」完全符合 Roofline 模型——
  見「2012-GPU深度學習算力.md」。**Cray-1 的哲學在 GPU 上復活**。
- 歷史定位：Cray-1 證明——**結構性設計（向量 + chaining + 液冷）比堆頻率更能突破性能上限**，
  這是 HPC 黃金年代的開端。
