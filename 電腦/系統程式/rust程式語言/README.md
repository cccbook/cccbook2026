# Rust 程式語言：從核心原理到高效實戰

*Rust Programming: From Core Principles to Production Practice*

Rust 不是「更快的 C++」，而是一套**把安全性從工程紀律變成語言保證**的設計。它的所有權、借用檢查器與型別系統不是三個獨立功能，而是同一個目標的三種表達：**在不依賴垃圾收集器、不依賴手動記憶體管理的前提下，讓記憶體安全成為可由編譯器證明的性質**。

本書的路徑不是語法手冊，而是**一條問題驅動的因果鏈**：

- 為什麼需要所有權（第 4 章）→ 記憶體管理三條老路各自的代價
- 借用檢查器如何從所有權推導出來（第 4、5 章）→ 生命週期只是借用檢查器的**人類可讀介面**，不是另一套機制
- 編譯期無法保證的東西怎麼辦（第 6、8、10 章）→ `Option`、`Result`、`Rc`/`RefCell` 的內部可變性
- 抽象如何不付出執行期代價（第 9、11 章）→ 泛型、特徵靜態多態與零成本抽象
- 記憶體安全之上還需要執行緒安全（第 12、13 章）→ 編譯器保證的無資料競爭，與 async 的執行模型
- 如何把這套保證延伸到程式碼庫（第 14、15 章）→ 巨集、測試、Clippy 與文件
- 最後以三個真實專案收束（第 16-18 章）→ CLI、Web API 與發布與持續整合

## 撰寫格式說明

- 檔名格式：`xx.y-短標題.md`，短標題採不含標點與特殊符號的關鍵詞
- 完整章節標題寫在各檔 H1 與本目錄中
- 行內數學一律寫成 `$ 公式 $`（`$` 前後各留一個半形空格）；顯示數學以獨立行 `$$` 包裹
- 禁用 `\[ \]`、`\( \)` 與反引號包數學
- 程式碼範例一律使用 fenced code block 並標註語言（`rust`、`bash`、`toml`）
- README 的連結必須與實際檔名完全一致
