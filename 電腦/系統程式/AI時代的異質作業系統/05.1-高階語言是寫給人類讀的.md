# 5.1　高階語言是寫給人類讀的

> 本節導論：高階語言的存在理由，是「讓人能寫、能讀、能維護程式」。當寫程式的人變成 AI，這個理由就動搖了。本節拆解高階語言的人類中心假設。

## 5.1.1 高階語言的三個人類中心假設

高階語言（C、Python、Java……）的設計，圍繞著「人類的認知限制」：

**（1）可讀性（readability）。**
變數命名、縮排、註解、空白——這些都是為了讓人類讀懂。機器完全不需要「`user_count` 比 `x` 好讀」這種事。

**（2）可組合的抽象（composable abstraction）。**
函式、類別、模組、泛型——這些抽象是為了讓人類能用「少數概念」駕馭「大量細節」。它們的管理成本（命名衝突、型別系統、封裝）是為人類的認知服務的。

**（3）可維護性（maintainability）。**
語言特性如繼承、介面、存取修飾子，都是為了「多人協作、長期維護」而設計。它們讓程式「好改」，而不是「好執行」。

這三個假設，本質上都是 **「寫程式的是人、程式的壽命很長」** 的推論。當這兩個前提改變，高階語言的價值就重新被評估。

## 5.1.2 為什麼 AI 不需要高階語言

LLM 生成程式時，直接生成的是「權重驅動的 token 序列」。它生成 C 或 Python 的「方便」，在於這些語言有大量訓練資料、有成熟的工具鏈。但這只是「訓練資料的偏誤」，不是「本質上的必要」。

從理論上看，AI 完全可以直接生成 **IR**（中間表示）或 **組合語言**，只要：
* 生成模型有足夠的 IR 訓練資料，或
* 有一個「高階語言 → IR」的翻譯器，讓 AI 生成高階語言、再翻譯成 IR。

關鍵洞察是：**高階語言對 AI 而言，只是「生成的中間產物」，不是「最終產物」**。人類需要高階語言來「讀」與「改」，AI 不需要——它可以直接產出 IR，跳過「人類可讀」這個階段。

## 5.1.3 高階語言的「語意落差」

更根本的問題是：**高階語言的語意，與硬體的執行模型之間，有巨大的落差**。

以 C 為例：
* C 的 `for` 迴圈，在硬體上可能是「分支 + 計數器」。
* C 的 `struct`，在硬體上可能是「一段連續記憶體 + 位移」。
* C 的函式呼叫，在硬體上可能是「堆疊 + 返回位址」。

這些落差，由編譯器填補。但填補的過程會 **丟失高階語意**：編譯後的機器碼，再也看不到「這是一個矩陣乘」「這是一個卷積」這些高階結構。這正是第 0 章談的「領域語意流失」。

對 AI 而言，這種「語意流失」是雙重浪費：
* 生成時，AI 要先「想」出高階語言的結構（for 迴圈），再讓編譯器拆解它。
* 執行時，硬體看不到高階結構，無法做領域特化的最佳化。

如果 AI 直接生成「保留高階語意的 IR」（例如用 `linalg.matmul` 表達矩陣乘），就能避免這個雙重浪費。

## 5.1.4 語言的四個功能，逐一檢視

把高階語言的功能拆成四項，逐一檢視它在 AI 時代的價值：

| 功能 | 對人類 | 對 AI |
| --- | --- | --- |
| 可讀性 | 必要 | 無關（AI 讀 IR 也一樣） |
| 抽象（函式/類別） | 降低認知負擔 | 可用 IR 的 op 取代 |
| 型別安全 | 早期發現錯誤 | 可用 IR 型別 + 驗證取代 |
| 可維護性 | 長期修改 | 無關（用完即丟） |

可以看到，**高階語言的核心價值（可讀、可維護）對 AI 幾乎無用**；而它提供的「抽象、型別安全」，IR 也能提供，甚至更好（IR 的型別更貼近硬體語意）。

## 5.1.5 一個思想實驗：AI 直接生成 IR

設想 AI 的輸出不是 Python，而是 MLIR：

```mlir
func.func @process(%input: tensor<1024xf32>) -> f32 {
  %sum = linalg.reduce ins(%input : tensor<1024xf32>) outs(%0 : tensor<f32>) {
    ^bb0(%in: f32, %out: f32):
      %add = arith.addf %in, %out : f32
      linalg.yield %add : f32
  } dimensions = [0]
  %scalar = tensor.extract %sum[] : tensor<f32>
  return %scalar : f32
}
```

這份 IR：
* 直接表達「對 1024 個 float 求和」的高階語意。
* 可以被編譯器降階到 CPU、GPU、NPU。
* 可以被驗證器檢查（記憶體邊界、型別）。
* 沒有人類可讀性的負擔（雖然其實還算可讀）。

AI 生成這樣的 IR，比生成等價的 Python 更直接、更精確、更可驗證。這就是「語言的退場」的具體含義。

## 5.1.6 「退場」不是「消失」

必須澄清：語言的「退場」不是說程式設計師從此不寫高階語言，而是說 **「高階語言不再是系統介面的核心」**。它會退到兩個位置：

* **控制面**：人類仍然用高階語言（或自然語言）描述意圖、寫控制邏輯、做系統管理。這是「給人用」的介面，不會消失。
* **生成的中間態**：AI 可能仍以高階語言作為「思考的中間步驟」，但最終產出會翻譯成 IR。高階語言變成「草稿」，IR 變成「定稿」。

換句話說，**高階語言從「執行檔的來源」退位為「意圖的表達方式」**，而 IR 成為「執行的真正介面」。

## 5.1.7 本節小結

* 高階語言的三個人類中心假設：可讀性、可組合抽象、可維護性。
* 這些假設建立在「寫程式的是人、壽命長」之上，當前提改變就動搖。
* AI 生成高階語言只是「訓練資料的偏誤」，本質上可直接生成 IR。
* 高階語言與硬體有語意落差，編譯過程丟失領域語意，對 AI 是雙重浪費。
* 逐項檢視：可讀性、可維護性對 AI 無用；抽象、型別安全 IR 也能提供。
* 「退場」不是消失，而是從「執行檔來源」退位為「意圖表達方式」。
