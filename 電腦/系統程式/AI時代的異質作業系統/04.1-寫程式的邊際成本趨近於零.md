# 4.1　寫程式的邊際成本趨近於零

> 本節導論：經濟學的「邊際成本」概念，理解 AI 寫 Code 的衝擊時意外地好用。當「多寫一段專用程式」的成本趨近於零，整個軟體工程的權衡都會翻轉。

## 4.1.1 邊際成本是什麼

在經濟學裡，**邊際成本（marginal cost）** 是指「多生產一單位產品所增加的成本」。關鍵洞察是：決策應該基於 **邊際**，而非 **平均**。

把它借到軟體：

* **寫一段新程式碼的邊際成本**：多花的人力、時間、風險。
* **重用現有元件的邊際成本**：學會它、整合它、處理它的限制。

傳統軟體工程的核心權衡，就是這兩者的比較。當「寫新程式的邊際成本」很高時，我們傾向「重用」——用函式庫、用框架、用現成服務。這催生了整個套件生態。

## 4.1.2 軟體生產的邊際成本曲線

回顧四個階段，看邊際成本的變化：

| 階段 | 寫新程式的邊際成本 | 主流策略 |
| --- | --- | --- |
| 手工編碼 | 極高（機器碼、易錯） | 重複使用既有紙帶/卡片 |
| 高階語言 | 高（需工程師數日） | 建立函式庫、重用 |
| 函式庫生態 | 中（需整合、維護） | 套件管理、組合 |
| AI 生成 | 趨近於零 | 針對任務即時生成 |

在第四階段，「多寫一段專用程式」的成本，可能低於「找出、理解、整合一個通用套件」的成本。這時，**權衡翻轉了**：與其重用一個臃腫的通用套件，不如讓 AI 生成一段剛好夠用的專用邏輯。

## 4.1.3 為什麼會趨近於零

「趨近於零」不是誇飾，它來自三個具體的機制：

**（1）生成速度。**
LLM 生成幾十行程式碼，可能只要幾秒。人類寫同樣的程式，可能要幾分鐘到幾小時。速度差了一到兩個數量級。

**（2）不需要理解全部。**
人類寫程式，必須理解每一行；AI 生成程式，人類可以只驗證「結果對不對」，不需要逐行理解。這大幅降低了「認知成本」。

**（3）針對性。**
通用套件要處理「所有可能的情況」，因此臃腫。生成的專用程式只需處理「這一次的情況」，因此精簡。精簡的程式更容易生成、更容易驗證、更容易執行。

## 4.1.4 邊際成本翻轉帶來的四個後果

**（1）從「通用」到「專用」。**
傳統：寫一個通用函式庫，處理所有輸入。
新：針對這次的資料，生成一段專用邏輯。這在資料處理、ETL、報表生成等領域已經發生。

**（2）從「維護」到「重新生成」。**
傳統：程式有 bug，修它、維護它。
新：程式有 bug，或者需求變了，直接重新生成一個新的。因為生成成本低於維護成本。「維護」這個概念本身被削弱。

**（3）從「版本」到「快照」。**
傳統：軟體有版本號（v1.2.3），有向後相容承諾。
新：每次都是為當下生成的新版本，不需要向後相容（因為沒有「舊的使用者」需要照顧，程式用完即丟）。

**（4）從「程式碼」到「意圖」。**
傳統：資產是程式碼。
新：資產是「意圖的描述」（prompt、規格、範例）。程式碼只是意圖的一次具體化。

## 4.1.5 邊際成本不是零：隱藏的成本

誠實地說，「趨近於零」是對「生成」這件事而言，但整條鏈路還有成本：

* **驗證成本**：生成的程式可能是錯的、不安全的。驗證它需要成本（這也是第 6 章「載入前驗證」的動機）。
* **規格成本**：要生成對的程式，得先把意圖描述清楚。描述意圖本身需要成本。
* **除錯成本**：生成錯了，要找出哪裡錯、怎麼修，可能比手寫更難（因為不是自己寫的）。
* **信任成本**：生成程式的行為是否符合預期？需要建立信任機制。

所以更精確的說法是：**「生成」的邊際成本趨近於零，但「驗證與信任」的邊際成本上升了**。這個轉移，正是為什麼「載入前驗證」會成為新 OS 的核心原語——因為驗證成了新的瓶頸。

## 4.1.6 一個經濟學的類比：從手工到大量生產

這個轉變，很像工業革命從「手工業」到「大量生產」的轉變：

* 手工業：每個產品都是訂製的，邊際成本高，所以產品少而貴。
* 大量生產：模具成本高（固定成本），但每個產品的邊際成本低，所以產品多而便宜。

AI 寫 Code 的類比是：

* 傳統軟體：每個功能都要手寫，邊際成本高，所以功能少而通用。
* AI 生成：模型訓練成本高（固定成本），但每次生成的邊際成本低，所以可以「一事一程式」。

差別在於：工業革命的瓶頸是「模具」，AI 時代的瓶頸是「驗證」。誰能解決驗證，誰就能真正享受低邊際成本的好處。

## 4.1.7 對作業系統的意涵

邊際成本翻轉，對 OS 的直接意涵是：

* **OS 不能再假設「程式是稀缺的」**：傳統 OS 的每個設計（行程建立、動態連結、檔案系統）都假設程式稀有、值得珍惜。當程式廉價，這些設計的固定成本就顯得荒謬。
* **OS 必須支援「高頻率的生成-執行-銷毀」**：如果每秒要生成、執行、銷毀數千個小程式，OS 的啟動與清理成本必須趨近於零。
* **OS 的核心價值轉向「驗證」**：既然生成廉價，價值就在「確保生成的是對的、安全的」。這就是為什麼本書把「載入前驗證」列為核心原語。

## 4.1.8 本節小結

* 邊際成本是「多生產一單位」的成本，軟體工程的權衡基於它。
* 軟體生產四階段：邊際成本從「極高」降到「趨近於零」。
* 趨近於零的三機制：生成速度、不需要理解全部、針對性。
* 四個後果：通用→專用、維護→重新生成、版本→快照、程式碼→意圖。
* 但「驗證與信任」的邊際成本上升，成為新瓶頸。
* 經濟學類比：從手工業到大量生產，瓶頸從「模具」變成「驗證」。
* 對 OS 的意涵：不能再假設程式稀缺，必須支援高頻生成-執行-銷毀，價值轉向驗證。
