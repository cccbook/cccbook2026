# 8.1　從時間片切分到計算子圖調度

> 本節導論：作業系統的排程器，半世紀以來都在做同一件事——把 CPU 時間切成片，分給不同的執行緒。但異質計算的排程單位不是「時間」，而是「計算」。本節重新定義排程。

## 8.1.1 時間片排程的假設

傳統 OS 的排程器，核心假設是：

* **計算資源是同質的**：所有 CPU 核心都一樣，只是「有多少個」不同。
* **執行的單位是執行緒**：排程器在執行緒之間切換。
* **時間是主要資源**：排程器決定「哪個執行緒跑多久」。
* **公平性是目標**：每個執行緒都應該分到合理的時間。

這個模型叫 **時間片排程（time-slicing）**，它的代表是 CFS（Completely Fair Scheduler，Linux 從 2.6.23 起採用）與其後繼 EEVDF。

時間片排程的抽象是：**「計算 = 時間」**。一個執行緒需要多少計算，就用多少時間來衡量。

## 8.1.2 為什麼「計算 ≠ 時間」

在異質計算裡，「計算 = 時間」這個等式失效了：

**（1）不同裝置的計算模型不同。**
在 CPU 上，一次 FMA 是「一個指令」；在 GPU 上，一次 FMA 是「一個 warp 的一個 lane」；在 NPU 上，一次 FMA 是「一個 PE 的一個週期」；在 FPGA 上，一次 FMA 是「一個 DSP 區塊的運作」。同樣的「一次 FMA」，在不同裝置上的「時間意義」完全不同。

**（2）不同運算的「計算強度」不同。**
有的運算是計算密集（compute-bound），有的是記憶體密集（memory-bound）。對前者，時間主要花在計算；對後者，時間主要花在等資料。用「時間」排程，無法區分這兩種。

**（3）平行度不同。**
一個工作可能有 1000 個可平行的執行緒，也可能只有 1 個。用「時間片」排程，無法表達「這個工作需要多少平行度」。

**（4）裝置的「適合性」不同。**
同一個矩陣乘，在 GPU 上可能比 NPU 快，但矩陣轉置在 NPU 上可能更快。排程器需要知道「誰最適合這個運算」，而不只是「誰有時間」。

## 8.1.3 新的排程單位：計算子圖

新的排程，單位不是「執行緒」，而是 **「計算子圖（compute subgraph）」**——計算圖的一個連通子集。

一個計算圖可以被切成多個子圖，每個子圖是一個「可獨立執行的計算單元」：

```mermaid
graph TD
    subgraph 計算圖
        A["op1"] --> B["op2"]
        B --> C["op3"]
        C --> D["op4"]
        B --> E["op5"]
        E --> F["op6"]
    end
    subgraph 子圖 1（給 GPU）
        A
        B
    end
    subgraph 子圖 2（給 NPU）
        C
        D
    end
    subgraph 子圖 3（給 CPU）
        E
        F
    end
```

排程器的任務，是決定 **「哪個子圖、去哪裡、何時執行」**。這比「哪個執行緒跑多久」複雜得多，因為它要考慮：

* **資料依賴**：子圖之間有依賴，順序不能亂。
* **裝置適合性**：這個子圖適合哪個裝置。
* **資料位置**：資料在哪個記憶體，搬到裝置的成本多少。
* **資源容量**：裝置的記憶體、頻寬是否夠。
* **延遲目標**：整個計算圖的端到端延遲要求。

## 8.1.4 排程問題的複雜度

這個排程問題，本質上是 **「有向無環圖（DAG）的異質多處理器排程」**，這是一個經典的 NP-hard 問題。

經典的 DAG 排程問題（如 R-DAG、HLFET、ETF 演算法）已經研究了數十年。但異質計算帶來新的複雜度：

* **異質性**：每個節點（運算）在不同裝置上的執行時間不同。
* **資料傳輸**：節點之間有資料傳輸成本，取決於它們落在哪些裝置。
* **記憶體限制**：每個裝置的記憶體有限，子圖的大小受限制。
* **動態性**：執行時間、資源可用性可能動態變化。

所以排程器必須是 **「啟發式（heuristic）」** 的：在有限時間內，找到「夠好」的解，而非「最佳」解。

## 8.1.5 排程的兩種時機

排程可以在兩個時機發生：

**（1）編譯期排程（static scheduling）。**
編譯器在編譯時就決定好「哪個子圖去哪個裝置」。優點是「無執行期開銷」；缺點是「無法適應執行期的變化」（如裝置忙碌、資料大小變動）。

**（2）執行期排程（dynamic scheduling）。**
排程器在執行時，根據當下的資源狀態決定。優點是「能適應變化」；缺點是「有排程開銷」。

**實際系統通常結合兩者**：編譯期做「粗略的切分與指派」，執行期做「細部的調整與負載平衡」。這正是第 8.3 節「排程器與編譯器的閉環」。

## 8.1.6 一個具體的例子

設想一個 Transformer 推論，由數百個算子組成。排程器可能這樣做：

* **編譯期**：把整個模型按層切分，每層是一個子圖。根據每層的運算特性（attention 是矩陣密集、FFN 是 GEMM），預先指派「attention 去 GPU、某些小算子去 CPU」。
* **執行期**：監測 GPU 的負載，若 GPU 空閒，把更多子圖丟給它；若 GPU 忙碌，把部分子圖移到 NPU。

```mermaid
graph LR
    G["計算圖（數百算子）"] --> C["編譯期：粗切分、預指派"]
    C --> R["執行期：負載平衡、動態調整"]
    R --> E["執行"]
```

## 8.1.7 「排程」概念的擴張

把上述綜合起來，新排程器的「排程」概念，已經遠超傳統：

| 維度 | 傳統排程 | 計算圖排程 |
| --- | --- | --- |
| 單位 | 執行緒 | 計算子圖 |
| 資源 | CPU 時間 | 異質算力（多種） |
| 目標 | 公平、吞吐 | 延遲、吞吐、能效 |
| 決策 | 何時、哪個核心 | 何時、哪個裝置、怎麼切 |
| 時機 | 執行期 | 編譯期 + 執行期 |
| 難度 | 中 | 高（NP-hard） |

這不是「改進排程器」，而是「重新定義排程」——從「分配時間」變成「分配計算」。

## 8.1.8 本節小結

* 時間片排程假設同質資源、執行緒單位、時間為資源、公平為目標。
* 異質計算下「計算 ≠ 時間」：計算模型、計算強度、平行度、裝置適合性都不同。
* 新排程單位是「計算子圖」：計算圖的連通子集。
* 排程要考慮：資料依賴、裝置適合性、資料位置、資源容量、延遲目標。
* 這是 NP-hard 的 DAG 異質多處理器排程，需啟發式。
* 兩種時機：編譯期（無開銷、不適應）與執行期（適應、有開銷），實際結合兩者。
* 重新定義排程：從「分配時間」到「分配計算」。
