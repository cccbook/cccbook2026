# 11.1　拋棄半世紀歷史包袱的勇氣

> 本節導論：革命派的問題不是「能不能做出新 OS」，而是「敢不敢拋棄」。本節先建立「重新設計」的思想立場，再給出設計原則。

## 11.1.1 重新發明的思想實驗

1960 年代，設計 UNIX 的人面對的是一台 PDP-7、一群分時使用者、沒有網路、沒有圖形。他們設計的抽象（行程、檔案、Shell）是對那個世界的回答。

現在，我們面對的是：數千顆 GPU 的叢集、數十億參數的模型、AI 生成的即時程式、CXL 統一的記憶體。**如果今天重新發明作業系統，不背任何歷史包袱，它會長什麼樣子？**

這個思想實驗的價值，不在於「真的做出來」，而在於 **「看清楚哪些抽象是必要的，哪些只是歷史偶然」**。就像第 2 章用歷史分析拆解 POSIX，這個思想實驗用「重新設計」拆解同樣的問題。

## 11.1.2 拋棄清單

革命派的第一件事，是列出一份「拋棄清單」：

| 拋棄 | 理由 | 對應章節 |
| --- | --- | --- |
| POSIX 相容 | 為人類長期程式設計，AI 一次性程式不需要 | 第 2、4 章 |
| 檔案系統樹 | 人類的認知輔助，機器不需要 | 第 2、7 章 |
| `fork()` 與行程 | 為分時隔離設計，成本高 | 第 2 章 |
| 動態連結 / 套件 | 一次性程式不需共享 | 第 4 章 |
| 環境變數 / Shell（作為執行模型） | 隱性狀態噪音 | 第 2 章 |
| 系統呼叫 C ABI（作為介面） | 丟失高階語意 | 第 5 章 |
| 權限硬隔離（作為主機制） | 成本高，可用驗證取代 | 第 6 章 |

這份清單的每一項，都在前面的章節被論證過「為什麼不需要」。革命派不是「討厭 POSIX」，而是 **「在一個不同的世界裡，POSIX 的最佳化目標已不成立」**。

## 11.1.3 拋棄的代價：冷啟動魔咒

拋棄清單讀起來很痛快，但代價是真實的：**沒有應用程式**。

一個不相容 POSIX 的新 OS，無法執行現有的 Linux 程式。這就回到第 10.1.5 節的「冷啟動魔咒」。歷史上，這道魔咒殺死了多數新 OS。

所以革命派最大的挑戰不是「技術」，而是「如何讓新 OS 有應用可用」。這正是第 11.3 節「AI 寫 Code 打破冷啟動魔咒」要解決的——如果 AI 能即時生成「目標 OS 的程式」，那「舊應用生態」就不再是護城河。

## 11.1.4 設計原則：從「最小」出發

拋棄之後，要「建立」。革命派的設計原則，可以概括為 **「從最小出發（start from minimal）」**：

**（1）只用必要的抽象。**
不預先假設「需要檔案系統」「需要行程」。先問「這個抽象解決什麼問題」，只保留真正必要的。

**（2）顯性優於隱性。**
所有狀態都要顯性（第 2 章）。沒有環境變數、沒有 CWD、沒有隱性上下文。

**（3）靜態優於動態。**
能靜態決定的都靜態決定（第 3 章）。記憶體規劃、排程、驗證，都在編譯期完成。

**（4）驗證優於隔離。**
能用「載入前驗證」保證安全的，就不用「執行時隔離」（第 6 章）。

**（5）統一優於分裂。**
統一的記憶體、統一的 IR、統一的排程（第 5、7、8 章）。不要「雙軌制」。

這五個原則，是後面設計藍圖的基礎。

## 11.1.5 從「OS 是什麼」重新定義

拋棄與建立之後，要回答一個本體論問題：**新 OS 到底是什麼？**

傳統定義：OS 是「管理硬體資源、提供程式執行環境」的軟體。

革命派的定義：**OS 是「連接人類意圖、形式驗證與物理算力的透明薄層」**。

這個定義有三個關鍵詞：

* **人類意圖**：輸入是「意圖」（自然語言、範例、高階 API），不是「程式碼」。
* **形式驗證**：中間是「證明安全」的驗證器，不是「權限檢查」。
* **物理算力**：輸出是「異質硬體的執行」，不是「CPU 指令」。

```mermaid

    I["人類意圖"] --> OS["透明薄層<br/>（生成 + 驗證 + 排程）"] --> H["物理算力"]
```

「薄層」意味著：它不「管理」機器（像傳統 OS 那樣），而是「翻譯」意圖為執行。它越薄，越透明，越好。

## 11.1.6 「勇氣」的技術含義

標題說「勇氣」，但這不是修辭。拋棄歷史包袱，在技術上有具體的含義：

* **敢於不接受「向後相容」**：不為舊程式保留負擔。
* **敢於重新設計介面**：不用「系統呼叫」，用「計算圖」。
* **敢於重新設計安全**：不用「權限環」，用「驗證」。
* **敢於重新設計儲存**：不用「檔案」，用「物件」。

每一項「敢於」，都意味著「放棄一個熟悉的安全網」。這是工程上的勇氣，也是設計上的清醒。

## 11.1.7 一個警告：不要重蹈覆轍

革命派要小心一個陷阱：**「為了不同而不同」**。拋棄 POSIX 不是目的，「讓系統更適合 AI 與異質算力」才是目的。

如果一個新 OS 拋棄了檔案系統，卻發明了「另一個更糟的持久化機制」，那就是失敗。拋棄必須伴隨「更好的替代」，而非「單純的刪除」。

所以革命派的紀律是：**「每一個拋棄，都要對應一個更好的設計」**。這也是為什麼本書先花九章論證「為什麼舊抽象失效」，才在這一章談「新設計」——因為「知道為什麼拋棄」，比「拋棄本身」更重要。

## 11.1.8 本節小結

* 思想實驗：今天重新發明 OS，不背歷史包袱，會長什麼樣。
* 拋棄清單：POSIX、檔案樹、fork/行程、動態連結、隱性狀態、C ABI、權限硬隔離。
* 代價：冷啟動魔咒（沒有應用），這是革命派最大挑戰。
* 五原則：只用必要抽象、顯性優於隱性、靜態優於動態、驗證優於隔離、統一優於分裂。
* 重新定義：OS 是「連接意圖、驗證、算力的透明薄層」。
* 勇氣的技術含義：敢於不接受向後相容、重新設計介面/安全/儲存。
* 警告：不要為不同而不同，每個拋棄都要有更好的替代。
