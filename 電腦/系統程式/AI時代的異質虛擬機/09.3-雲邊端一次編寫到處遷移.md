# 9.3　雲邊端一次編寫到處遷移

> 本節導論：Wasm 與異質虛擬機結合的最終願景，是「同一份安全元件，在雲端訓練叢集、邊緣 NPU、終端設備之間無痛遷移」。這一節把這條路徑講清楚。

## 9.3.1 雲邊端的三種算力形態

「雲、邊、端」代表三種截然不同的部署環境：

* **雲端**：大量 GPU/TPU、充足記憶體、高速網路。適合大規模訓練與批次推理。
* **邊緣**：少量加速器、有限的功耗與記憶體、間歇性連線。適合低延遲推理、資料就地處理。
* **終端**：手機、IoT、車載，算力極有限、功耗嚴格、異質 SoC（CPU + NPU + DSP）。

三者的硬體差異巨大，傳統上要為每個環境寫不同的程式、做不同的最佳化。這正是「一次編寫、到處執行」要解決的問題。

## 9.3.2 三層可攜性

要實現跨雲邊端的可攜，需要三層可攜性：

* **語意可攜（semantic portability）**：程式的邏輯與硬體無關。這靠高階語言或 IR 表達。
* **安全可攜（security portability）**：程式的隔離與驗證在任何環境都成立。這靠 Wasm 沙盒 + IR Verifier。
* **效能可攜（performance portability）**：程式在每個環境都能達到可接受的效能。這靠 MLIR 的多後端降階 + JIT 特化。

傳統的虛擬機通常只解決「語意可攜」，安全與效能則要各環境自己做。異質虛擬機的目標是三層同時可攜。

## 9.3.3 Wasm 作為「可攜的執行單元」

Wasm 元件作為「可攜的執行單元」，有幾個優勢：

* **格式統一**：同一份 `.wasm` 或元件，可以在任何 runtime 執行。
* **啟動極快**：AOT 編譯後，啟動可達微秒到毫秒級。
* **沙盒一致**：無論在雲、邊、端，Wasm 的安全模型一致（線性記憶體、能力導向）。
* **可組合**：Component Model 讓不同元件組裝，適應不同環境。

因此「遷移」的單位不是「整個虛擬機」，而是「一組 Wasm 元件 + 它們的狀態快照」。這比遷移整台 VM 輕得多。

## 9.3.4 遷移的機制

「遷移」一個執行中的 Wasm 元件，需要：

* **狀態捕獲**：把 Wasm 的線性記憶體、全域變數、執行位置（program counter）保存成快照。
* **快照傳輸**：把快照從源環境傳到目標環境（可能跨網路）。
* **狀態恢復**：在目標環境重建 Wasm 實例，載入快照，繼續執行。
* **裝置狀態處理**：如果元件用了 GPU kernel，要決定「重算」或「遷移裝置狀態」。

Wasm 的優勢在於「狀態簡單」：線性記憶體是一段連續位址，全域變數有限，沒有複雜的核心狀態。這讓快照與恢復比整台 VM 簡單得多。

## 9.3.5 效能可攜：同一份元件、不同後端

效能可攜是最難的一層。同一份 Wasm 元件，在雲端 GPU 上要跑得快，在邊緣 NPU 上也要跑得快，需要 MLIR 的多後端降階：

* 雲端：`Wasm → IR → stablehlo → gpu → cuda`
* 邊緣：`Wasm → IR → stablehlo → linalg → 自訂 NPU`
* 終端：`Wasm → IR → stablehlo → linalg → DSP`

這正是第 4 章「虛擬 ISA + 多後端」的應用：Wasm 元件裡的高階計算圖，被降階到不同硬體。Wasm 本身只負責控制流，張量運算交給 MLIR 後端。

## 9.3.6 安全可攜：跨環境的一致隔離

安全可攜要求「同一份元件，在任何環境都有相同的安全保證」。這需要：

* **一致的驗證**：Wasm 驗證器在所有 runtime 上行為一致（標準化）。
* **一致的沙盒**：線性記憶體、能力導向的介面，在任何環境都一樣。
* **一致的預算**：Gas 機制在任何環境都適用（雖然定價可能不同）。

這種一致性，讓「開發者在雲端測試過的元件，可以放心部署到邊緣」——因為安全模型不變。

## 9.3.7 挑戰：異質硬體的語意差異

「一次編寫、到處執行」的最大挑戰，是異質硬體的 **語意差異**：

* **浮點精度**：不同硬體的 FP16/BF16 行為可能不同（舍入、denormal）。
* **整數溢位**：某些硬體對溢位的處理不同。
* **原子操作**：記憶體模型的強弱不同。
* **非確定性**：GPU 的平行執行順序不確定。

這些差異會導致「同一份元件，在不同硬體上得到不同結果」。對 AI 計算，這可能可接受（容許數值誤差）；但對某些應用（如金融計算），這不可接受。

解法是「**語意契約（semantic contract）**」：明確規定元件要求的語意（如「IEEE 754 嚴格浮點」），runtime 負責提供對應的語意，或拒絕執行。

## 9.3.8 本節小結

* 雲邊端是三種差異巨大的算力形態，傳統上要分別開發。
* 三層可攜性：語意、安全、效能，異質虛擬機要三者兼顧。
* Wasm 元件是可攜的執行單元：格式統一、啟動快、沙盒一致、可組合。
* 遷移靠「狀態快照 + 傳輸 + 恢復」，Wasm 狀態簡單，遷移比 VM 輕。
* 效能可攜靠 MLIR 多後端降階；安全可攜靠標準化驗證與沙盒。
* 異質硬體的語意差異是最大挑戰，靠「語意契約」處理。
