# 9.1 跨數十個 Pass 的全域不變式：SSA 支配、別名與生命週期

第三部收尾。第 7、8 章展示了生成式 AI 能做什麼；本章畫出**不能交給它的硬邊界**。第一塊基石是全域不變式（global invariants）——那些**跨越整個 IR、所有 pass、所有變換都必須成立**的性質。它們之所以是硬邊界，原因將在本節末尾給出：**它們的違反無法被局部驗證捕捉，且後果是全域性的。**

## 9.1.1 什麼是「全域不變式」

定義：不變式 $I$ 是全域的，若它滿足：

1. **範圍全域**： $I$ 的判定需要整個 IR（或大範圍上下文），不是單個 op/函式的局部性質；
2. **時程全域**： $I$ 必須在**每一個 pass 之後**成立——任何一個 pass 破壞它，後續所有 pass 的前提崩塌；
3. **後果全域**：違反 $I$ 的症狀通常在**遠離引入點**的地方爆發（錯誤的數值、錯誤的優化、崩潰），除錯半徑極大。

對照 5.1.4 節：MLIR verifier 檢查的就是一組全域不變式。但 verifier 只覆蓋了清單的一部分——**本節的任務是把完整清單攤開，看清哪些已機器可查、哪些仍是工程師的隱性責任**。

## 9.1.2 不變式一：SSA 支配關係

回顧 1.2.1 節：每個值的使用，其定義必須**支配**該使用（從入口到使用的每條路徑都經過定義）。這是 SSA 的合法性根基，也是：

* **DCE 的合法性前提**：「沒有使用者的值可刪」依賴使用的可信性；
* **code motion 的約束**：把計算提出循環，必須確認邊支配；
* **所有結構變換的底線**：split block、hoist、if-conversion 都可能無意破壞支配。

**機器可查性：完全可查**。支配樹可線性時間計算，verifier 逐使用檢查。**這一條已經被 MLIR/LLVM 的 verifier 全自動守護**——生成式 pass 產出非法 IR 會被當場攔截（7.3.2 節）。

但有一個微妙的殘餘風險：**verifier 檢查的是「形式合法」，不檢查「語意等價」**。一個生成的 pass 可以產出形式合法但語意錯誤的 IR（如把歸約改寫成錯誤的結合順序）——支配性檢查對此無能為力，需要差分測試（閘門二）補位。

## 9.1.3 不變式二：別名與記憶體效果

別名（aliasing）問題：兩個指標/memref 是否可能指向同一記憶體。它是整個優化體系的**最脆弱地基**：

| 依賴別名分析的 pass | 錯誤別名結論的後果 |
|---------------------|-------------------|
| DCE / CSE | 誤刪看似無副作用的載入 → 數值錯誤 |
| 迴圈向量化 / 交換 | 誤判迭代獨立 → 資料競爭式錯誤 |
| In-place bufferization | 覆寫仍在使用的資料（3.3.3、5.3.4 節） |
| 排程重排 | 違反記憶體依賴順序 |

別名分析的特殊困難在於**它是推斷而非聲明**：LLVM 從指標運算推斷 may-alias 集合，精度不足時保守化（說「可能別名」），優化機會流失但不會錯；**精度過頭（錯誤地說 no-alias）則直接產生錯誤代碼**。歷史上 LLVM 的 noalias/metadata 誤用、C 的 restrict 語意誤解，都是高發 bug 區。

MLIR 的改進方向是把「效果」變成**聲明**：`MemoryEffectOpInterface` 讓每個 op 聲明自己讀/寫/分配/釋放哪些 operands。**從「推斷」到「聲明」的轉移，本質上是把全域不變式轉化為局部可驗證的契約**——這是 5.1.4 節介面機制在正確性維度的深層意義。

**機器可查性：部分可查**。效果標註的「形式完整性」可查（每個 op 有沒有聲明）；「聲明的正確性」不可查（模型聲稱只讀、實際寫了——verifier 無從得知）。**這是生成式 pass 的隱形雷區**：LLM 生成的 op 定義漏標寫效果，下游 DCE 就會誤刪——症狀出現在幾十個 pass 之後。

## 9.1.4 不變式三：記憶體生命週期

生命週期不變式：**值的每個使用都發生在其生命區間內；buffer 的重用只發生在生命週期斷開之後**。

它在張量世界的形態（3.3.3 節）：

* UB/SMEM 位址的重用必須以生命週期不重疊為前提；
* bufferization 的 in-place 決策必須證明「舊值不再被讀」；
* 跨 device 的資料傳輸，其源的生存期必須覆蓋傳輸時段（異步 DMA 的隱性依賴）。

**機器可查性：結構上可查，語意上難查**。如果生命週期以顯式形式存在（如 SSA 值的定義-使用域、顯式的 dealloc op），著色驗證是機械的（3.3.3 節）。但**異步執行模型**（GPU stream、NPU 的非同步 DMA）把「使用」的時刻從語法位置解耦到執行時刻——事件序、stream 同步的正確性無法從單一 IR 形態完全驗證，需要**執行模型的形式化**（如 IREE 的 stream 方言嘗試做的事）。

## 9.1.5 不變式四：控制流與異常的完備性

* **CFG 完備性**：每個 block 有前驅（除入口）、每個終止 op 合法、返回值與簽名一致；
* **異常/錯誤路徑的完備性**：C++ 的 exception table、Rust 的 unwind 邊界、錯誤碼的傳播鏈——**「正常路徑正確」遠遠不夠**，優化 pass 移動代碼時必須保持異常語意（哪個清理先跑、哪個副作用先發生）；
* **跨函式契約**：inlining 之後 callee 的假設（預條件、ABI 約定、對齊承諾）必須隨之傳播。

生成式風險的具體形態：LLM 生成的 pass 處理了常規控制流，但對**不可達 block、無前驅 block、空 region、無限循環**這些「語法上合法但罕見」的形態產生錯誤變換——正是 8.2 節模糊測試最擅長炸出的類型。

## 9.1.6 為什麼這些不變式構成硬邊界

現在我們可以回答本節標題的問題：**為什麼全域不變式不能委託給生成者**：

1. **驗證的不完備性**：不變式的「形式面」可查（verifier），「語意面」只能靠測試抽樣——而全域不變式違反的後果恰恰藏在測試覆蓋的角落（9.1.2 節的結合順序、9.1.3 節的效果漏標）。**機率性生成 + 抽樣驗證，在全域不變式上是可靠性倒掛的**；
2. **錯誤的傳播半徑**：違反全域不變式的代碼一旦進入主線，它毒化的是**所有後續 pass 的運行環境**——不是一個 kernel 慢一點，而是整條管線的每一個決策都建立在沙地上。8.3 節 kernel 生成的失敗模式是「這個 kernel 錯了、重來」；不變式違反的失敗模式是「管線深處的任何一個結果都不可信」；
3. **修復的知識本質**：全域不變式的維護需要對整個系統語意的**演繹性理解**（從型別系統/執行模型推導「這樣變換必不違反」），而生成模型的知識是**歸納性的**（從語料統計「這樣寫通常沒事」）。演繹保證不可被歸納統計替代——這是第 7 章張力在最深處的形態。

## 9.1.7 不變式清單與守護機制的對照表

| 全域不變式 | 守護機制 | 完備性 |
|-----------|---------|--------|
| SSA 支配關係 | MLIR/LLVM verifier | **完全自動** |
| 型別與形狀一致性 | verifier + shape 推導 | 完全自動 |
| 記憶體效果聲明的形式完整性 | interface 檢查 | 自動 |
| 效果聲明的語意正確性 | 差分 + 模糊測試 | **抽樣性** |
| 別名結論的正確性 | 分析器本身 + 測試 | 抽樣性 |
| 生命週期（同步模型） | buffer 配置驗證 | 自動 |
| 生命週期（異步模型） | stream/事件形式化 + 執行期檢測 | 部分 |
| 異常/清理路徑完備性 | 專門 pass + 測試 | 抽樣性 |
| 跨 device 資料依賴 | HAL/stream 語意 + runtime 檢查 | 部分 |

表的閱讀方式：**「自動」欄是可以放心交給漏斗的；「抽樣/部分」欄是硬邊界的實體**——第 9.2 節將據此劃定 Merge 權限的歸屬。
