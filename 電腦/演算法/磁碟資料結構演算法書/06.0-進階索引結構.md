# 第6章 進階索引結構

B+tree 是讀取優化的極致，但現代工作負載越來越「寫多讀少」：日誌、物聯網感測、訊息流、點擊流——每一筆都只是「追加」，卻要在隨機位置維護索引，B+tree 會把寫入放大成數次隨機 I/O。本章介紹三個為現代儲存設計的結構：ISAM 是「建好就不再動」的靜態索引，讀取極快；LSM 樹反其道而行，把所有寫入變成順序追加，再用後台合併消化，成為 LevelDB、RocksDB、Cassandra 的心臟；Bloom Filter 則以少量位元換取「一定不在」的快速判斷，替 LSM 樹省下大量無謂的磁碟讀取。

學完本章，你將理解「讀取優化」與「寫入優化」的設計光譜，並能依工作負載選擇適合的索引結構。
