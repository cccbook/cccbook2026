# 《蒙地卡羅法》寫作規範

本專書所有檔案共用以下格式規範，撰寫時必須遵守。

## 1. 語言與文體

- 使用**繁體中文**（台灣用語），專業術語附英文原文，例如「變分推論（variational inference）」。
- 文體為教科書：條理清晰、層次分明、可自足閱讀。
- 每一節開頭先給出「學習目標」，節末給出「本章要點」與「延伸閱讀」。
- **必須寫出技術與理論的前因後果與驅動關係**：說明「為什麼需要這個技術」、「它解決了前一方法的什麼缺陷」、「它又引發了什麼新問題」。
- 避免行話堆砌；每個公式都要說明符號意義與直覺。

## 2. 檔名

- 格式：`NN.M-標題.md`，例如 `01.1-蒙地卡羅法的起源與發展.md`。
- 章節編號不可重複、不可跳號（缺號必須補檔）。
- 歷史事件相關標題盡量帶年份，例如 `08.3-1984年模擬量子系統.md`。

## 3. Markdown 格式

- 使用標準 GitHub Flavored Markdown。
- 標題層級：檔案開頭為 `# 第N章　標題`（或 `# 附錄X　標題`），其下用 `## 1.1 ...`、`### ...`、`#### ...`。
- 程式碼區塊標註語言：```python、```cpp、```julia、```bash。
- 表格用標準 pipe 表格。

## 4. 數學格式（重要）

GitHub 原生 LaTeX 支援：**行內數學必須寫成 `` $`...$` ``**。

規則：

- 行內數學的 `$` 與反引號之後**必須緊接非空白字元**，且結尾反引號與 `$` 之後**必須有空格或換行**（除非行尾）。
- 也就是說：`文字 $`x^2`$ 文字` 正確；`文字$`x^2`$文字` 錯誤（無空格）；`$` `` ` `` 內部不可為空或以空白開頭。
- 塊狀數學直接用 `$$` 獨立行（**不要**包在 fenced code block 中，否則 GitHub 會當成程式碼而非數學）：

$$
\int_0^1 f(x)\,dx = \mathbb{E}[f(U)]
$$

- 區塊公式的 `$$` 上下各留空行，內部內容不縮排開頭空白。
- 絕對不要使用 `\[ ... \]`、`\( ... \)`、`$...$`（無反引號）、或 `\begin{equation}` 之類 GitHub 不支援的環境。
- 禁止使用 `\begin{align}`、`\begin{alignat}`、`\begin{equation}`、`\begin{split}`（GitHub MathJax 對 `align` 支援有限且易出錯）。需要多行對齊時請改用 `\begin{array}{rl} ... \end{array}` 或分成多個 `$$` 區塊。

## 5. Mermaid 圖

使用 ```mermaid fenced code block，必須能在 GitHub 正常渲染：

- 流程圖用 `flowchart TD` / `flowchart LR`。
- 節點文字避免使用括號、冒號等易破壞解析的特殊字元；需要時用雙引號包住，例如 `A["蒙地卡羅積分"]`。
- 時序/狀態圖可用 `stateDiagram-v2`；類圖用 `classDiagram`。
- 每張圖前後要有一句說明它表達什麼，以及它呼應本章哪個論點。

## 6. 程式碼

- 範例程式碼要可讀、可執行意圖明確，附上必要的註解（中文註解）。
- 需要示範時提供輸出片段。
- 每段關鍵程式碼後用文字說明其對應的理論（例如對應中心極限定理、控制變數的協方差縮減公式）。

## 7. 章節間連結

- 每章開頭加上「上一章 / 下一章」導覽連結。
- 參考同書其他章節時使用相對連結，例如 `[第4章：蒙地卡羅積分法](04.0-蒙地卡羅積分法.md)`。
- 附錄 A1~A3 用 `A1-...md` 形式連結。

## 8. 內容長度

- 每個 `.M` 檔案至少 800 字以上（正文中文字），重要章節可更長。
- 章首檔（`NN.0`）是該章導論：說明該章在整本書中的位置、依賴哪些前置理論、將引出哪些後續問題。
- 附錄 A3 需含至少 15 筆真實存在、可查證的參考文獻（含作者、書名/論文名、出版社/期刊、年份）。

## 9. 範例（格式正確）

```markdown
蒙地卡羅估計量的定義為

$`\hat{\mu}_N = \frac{1}{N}\sum_{i=1}^{N} f(X_i)`$

其中 $`X_1,\dots,X_N`$ 為獨立同分布的樣本。
```

注意：`$` 與反引號緊接文字，結尾後有空格。
