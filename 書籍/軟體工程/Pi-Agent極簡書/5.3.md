# 5.3 打造自動化 CI/CD 與代碼審查工作流

## 從一個問題開始

Agent 不只能跟你聊天——`--print`、`--mode json`、RPC、SDK 讓 Pi 走進 CI/CD 與自動化工作流：PR 審查、commit 檢查、修 lint、跑測試。

## 核心組合：管線 + print mode

```bash
pi --print "Summarize this repository"
git diff | pi --print "Review this change"
git diff --staged | pi --print "找出這個 diff 的安全問題，只列問題不用改 code"
```

- `--print`（`-p`）：執行一次、輸出最終回應、結束
- 管線 stdin 的內容會前置到第一個提示
- `@path` 帶入檔案或圖片：`pi --print "審查這個檔案" @src/auth.ts`
- `--` 停止選項解析，讓提示以 `-` 開頭

## CI 環境的正確設定

| 設定 | 為什麼 |
|---|---|
| `--model` + 環境變數供 key | 憑證不落盤（不寫 auth.json） |
| `--no-session` | 一次性執行不留會話檔 |
| `--tools read,grep,find,ls` | 只給讀取工具，禁止修改 |
| `--no-builtin-tools` | 保留 extension 工具但關掉內建 |
| `--offline` | 關掉自動網路活動（模型目錄刷新） |

完整範例：

```bash
OPENAI_API_KEY=$CI_KEY pi \
  --model sonnet:high \
  --no-session \
  --tools read,grep,find,ls \
  --print "Review this PR for correctness and security" \
  @pr-diff.txt
```

### 憑證檢查

```bash
pi auth check --provider openai --json      # ready / not_ready / invalid
pi auth print-api-key --provider openai     # 印出解析後的 key（敏感！）
```

## GitHub Actions 範例

```yaml
name: AI Review
on: [pull_request]
jobs:
  review:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with: { fetch-depth: 0 }
      - uses: actions/setup-node@v4
        with: { node-version: 22 }
      - run: npm install -g --ignore-scripts @earendil-works/pi-coding-agent
      - name: Review PR
        env:
          ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}
        run: |
          git diff origin/main...HEAD > /tmp/pr.diff
          cat /tmp/pr.diff | pi --no-session --print \
            "審查這個 PR：正確性、安全、錯誤處理。輸出 Markdown。"
```

## 事件流分析：--mode json

要對執行過程做程式化處理：

```bash
pi --mode json "Inspect this repository" > events.jsonl
```

JSONL 事件流包含訊息更新、工具執行、佇列、compaction、重試等——你的腳本可以解析、統計、儀表板化。

## RPC：長駐服務化

IDE 或自訂服務整合：

```bash
pi --mode rpc --no-session
```

- stdin 收 JSONL 指令、stdout 回應與事件
- Python / Go / Rust 都能串（見 1.2 的最小客戶端）
- 指令帶 `id` 配對回應；等 `agent_settled` 才是工作結束

## Commit hook：本地自動檢查

`.git/hooks/pre-commit`（或用 husky）：

```bash
#!/bin/sh
STAGED=$(git diff --staged)
[ -z "$STAGED" ] && exit 0
RESULT=$(echo "$STAGED" | pi --no-session --no-tools --print \
  "這個 diff 有沒有明顯 bug 或 debug 程式碼？只回答 YES 或 NO")
[ "$RESULT" = "YES" ] && echo "AI review 發現問題，禁止 commit" && exit 1
exit 0
```

`--no-tools`（`-nt`）讓所有工具停用——純文字審查，安全且快。

```mermaid

    A[PR 開啟] --> B[CI: pi --print 審查 diff]
    B --> C[結果貼到 PR 評論]
    D[本地 commit] --> E[pre-commit hook: pi --print 快篩]
    F[開發者互動] --> G[tmux 多 Pi 分工]
    G --> H[/export 會話歸檔]
```

> 安全提醒：CI 與自動化場景務必——只給必要工具、憑證用環境變數、`--no-session`、輸出先審視再公開。會話可能含檔案內容與憑證，分享前要檢查。
