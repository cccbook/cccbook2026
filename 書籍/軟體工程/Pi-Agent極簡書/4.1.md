# 4.1 TypeScript Extensions：自訂命令、工具、快捷鍵與 TUI

## 從一個問題開始

別的 agent 把功能內建死了：想要 plan mode？等官方。想要權限彈窗？等官方。Pi 的答案：**Features 別人內建，你自己寫**。Extension 是 TypeScript 模組，能存取工具、指令、快捷鍵、事件與完整 TUI。

## 第一個 Extension：30 秒上手

建立 `~/.pi/agent/extensions/hello.ts`：

```typescript
import type { ExtensionAPI } from "@earendil-works/pi-coding-agent";

export default function (pi: ExtensionAPI) {
  pi.registerCommand("hello", {
    description: "Show a greeting",
    handler: async (name, ctx) => {
      ctx.ui.notify(`Hello, ${name || "world"}!`, "info");
    },
  });
}
```

啟動 Pi 後執行 `/hello`。開發中直接載入檔案：

```bash
pi --extension ./hello.ts
```

Pi 用 `jiti` 載入，**本地 TypeScript 擴充不需要另外編譯**。

## 擺放位置

| 位置 | 範圍 |
|---|---|
| `~/.pi/agent/extensions/` | 使用者全域 |
| `.pi/extensions/` | 專案（需 trust） |
| `--extension <path>` | 一次性載入（可重複） |

- 單檔放 `.ts`；多檔用資料夾含 `index.ts` 入口
- npm 依賴放在附近的 `package.json`
- 改完 code 執行 `/reload` 替換擴充 runtime、立即生效

## ExtensionAPI：每個整合點用什麼

| 能力 | API |
|---|---|
| 觀察或修改生命週期行為 | `pi.on()` |
| 加一個模型可呼叫的操作（工具） | `pi.registerTool()` |
| 加一個 `/` 指令 | `pi.registerCommand()` |
| 加快捷鍵或 CLI flag | `pi.registerShortcut()` / `pi.registerFlag()` |
| 送使用者或自訂訊息 | `pi.sendUserMessage()` / `pi.sendMessage()` |
| 持久化非 context 會話資料 | `pi.appendEntry()` |
| 改變活躍工具、模型、思考等級 | session 控制方法 |
| 加模型提供商 | `pi.registerProvider()` |
| 加 MCP 伺服器 | `pi.registerMcpServer()` |
| 讓每個請求路由到模型 | `pi.registerVirtualModel()` |
| 終端渲染 | renderer 註冊與 `ctx.ui` |
| 與另一個擴充溝通 | `pi.events` |

## 自訂工具（registerTool）

工具四要素：名稱、給模型看的描述、TypeBox 參數 schema、`execute()` 函式：

```typescript
pi.registerTool("roll", {
  description: "Roll a dice",
  parameters: Type.Object({ sides: Type.Number() }),
  async execute(_id, params, onUpdate, ctx, signal) {
    const value = Math.floor(Math.random() * params.sides) + 1;
    return { content: [{ type: "text", text: `Rolled ${value}` }], details: { value } };
  },
});
```

合約重點：

- 結果必須含給模型看的 `content`，`details` 供渲染或狀態重建
- **throw 才是錯誤**——return 物件不會被標為錯誤
- 檔案修改工具要用 `withFileMutationQueue()` 包住完整的讀改寫
- 大輸出要截斷，並告訴模型去哪裡讀完整內容
- 工具可以呼叫其他工具：`ctx.executeTool(name, args, { signal, onUpdate })`

### 工具曝光（exposure）

| exposure | 行為 |
|---|---|
| `direct`（預設） | 宣告給模型，且可被呼叫 |
| `model-only` | 宣告給模型，不可被其他工具呼叫 |
| `codemode` | 任何時候可被 codemode 腳本呼叫，不宣告給模型 |
| `deferred` | 同 codemode 但不被 codemode 列出，`tool_search` 可找到並啟用 |
| `hidden` | 已註冊但不可達（工具不能解除註冊，用 re-register 隱藏） |

## 事件（pi.on）

事件涵蓋資源發現、會話、agent 與訊息生命週期、提供商、工具、原始輸入。常用的：

| 事件 | 用途 |
|---|---|
| `session_start` / `session_shutdown` | 啟動/關閉長駐資源 |
| `before_agent_start` | 每次執行前改提示區塊、選工具、加指引 |
| `tool_call` | 改變工具輸入或**擋下執行**（權限彈窗就靠這個） |
| `tool_result` | 組合、改寫或遮蔽結果 |
| `context` / `context_with_system` | 轉換對話訊息（RAG、過濾歷史） |
| `turn_end` / `agent_before_settle` | 可行動邊界：可附加條目並請求一次續作 |
| `session_before_compact` | 自訂 compaction（見 3.3） |

### 用 annotations 做權限彈窗

工具自帶 MCP 語意的 annotations（`readOnlyHint`、`destructiveHint` 等），權限擴充可以據此決定哪些呼叫要確認：

```typescript
pi.on("tool_call", async (event, ctx) => {
  const hints = pi.getAllTools().find((tool) => tool.name === event.toolName)?.annotations;
  const needsApproval =
    hints?.destructiveHint === true ||
    (!hints?.readOnlyHint && ((hints?.destructiveHint ?? true) || (hints?.openWorldHint ?? true)));
  if (needsApproval && !(await ctx.ui.confirm("Allow tool call?", event.toolName))) {
    return { block: true, reason: `${event.toolName} was not approved` };
  }
});
```

## 動態啟用工具

先註冊全部工具，可選工具保持未啟用，用 `pi.setActiveTools()` 從一個 loader 工具動態選取——這是 Pi 管理 context 的核心手法之一。

## 狀態管理

| 狀態 | 放哪裡 |
|---|---|
| 跟著活躍分支的工具狀態 | tool-result `details` |
| 不進模型 context 的持久資料 | `pi.appendEntry()` |
| 要存且送給模型的自訂內容 | `pi.sendMessage()` |
| 跨會話資料 | 外部儲存 |

## UI 與模式

- `ctx.ui` 提供對話框、通知、狀態文字、widgets、標題、編輯器存取與自訂元件
- 擴充在 interactive、RPC、JSON、print 模式都會載入
- JSON 與 print 模式沒有 UI——用 `ctx.mode === "tui"` 保護終端專屬行為，`ctx.hasUI` 判斷可用互動
- **工具與事件行為要獨立於渲染**，讓非互動模式照常工作

## 生命週期合約

- 工廠函式可同步或非同步；Pi 會等非同步工廠完成才繼續啟動
- **工廠內不要啟動程序、socket、watcher、timer**——長駐資源從 `session_start` 或需要的指令/工具啟動
- `session_shutdown` 裡做冪等清理（取消、reload、換會話、程序結束都可能匯流到同一條清理路徑）
