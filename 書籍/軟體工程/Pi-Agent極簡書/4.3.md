# 4.3 Pi Packages 生態：打包與分享你的擴充

## 從一個問題開始

你寫了一個好用的 extension，同事也想要。散發單檔太陽春，維護太麻煩。Pi 的答案是 **Pi Packages**：把 extensions、skills、prompts、themes **打包成一個單位**，透過 npm 或 git 分享。

## 安裝與管理

```bash
pi install npm:@example/pi-tools@1.0.0      # 從 npm 安裝（版本鎖定）
pi install git:github.com/example/pi-tools@v1   # 從 git 安裝（tag/commit 鎖定）
pi install ./local-package                  # 從本地路徑載入（不複製）

pi list                     # 列出已設定的套件
pi remove <source>          # 移除套件與其設定條目（uninstall 是別名）
pi update --extensions      # 重新同步套件安裝
pi update <source>          # 更新單一套件
pi config                   # 選擇要載入哪些套件資源
```

- 個人安裝寫入 `~/.pi/agent/settings.json`
- `--local`（`-l`）寫入 `.pi/settings.json`（專案，需 trust 後才讀取）
- `pi -e npm:@example/pi-tools`：**試用一次**，不寫入設定

> 打比方：package 像「一盒便當」——extension 是主菜、skill 是配菜、prompt 是湯、theme 是包裝，一盒帶走、一條指令安裝。

## 建立套件：慣例目錄版

最簡單的套件就是一個普通資料夾，用慣例目錄名：

```text
my-pi-package/
├── package.json
├── extensions/
├── skills/
├── prompts/
└── themes/
```

沒有 `pi` manifest 時，Pi 自動從這些目錄發現 TS/JS 擴充、skill 資料夾、Markdown prompts、JSON themes。

## 建立套件：顯式 manifest 版

資源放在別處或需要過濾時，用 `package.json` 的 `pi` key：

```json
{
  "name": "my-pi-package",
  "keywords": ["pi-package"],
  "pi": {
    "extensions": ["./src/extension.ts"],
    "skills": ["./resources/skills"],
    "prompts": ["./resources/prompts/*.md"],
    "themes": ["./resources/themes/*.json"]
  }
}
```

- 路徑相對套件根目錄，陣列支援 glob 與排除
- `pi-package` keyword 讓 npm 套件可被 [Pi package gallery](https://pi.dev/packages) 收錄；`pi.image` 與 `pi.video` 加畫廊預覽

## 依賴宣告

- 擴充 import 的 npm 套件放 `dependencies`——Pi 安裝 npm/git 套件時會一併裝好
- **宿主提供的套件**（Pi 已內建，不要複製、不要放 `dependencies`）：

| 套件 | 內容 |
|---|---|
| `@earendil-works/pi-coding-agent` | Agent 核心 |
| `@earendil-works/pi-ai` | 模型層 |
| `@earendil-works/pi-agent-core` | Agent loop |
| `@earendil-works/pi-tui` | 終端 UI |
| `typebox` | Schema |

把宿主套件宣告在 `peerDependencies`（範圍 `"*"`）且不要 bundle。**把宿主套件複製進 `dependencies` 會繞過 Pi 的模組映射，造成重複類別與註冊表**——Pi 會報擴充警告。

## 來源格式

| 來源 | 範例 | 行為 |
|---|---|---|
| npm | `npm:@example/pi-tools@1.0.0` | 裝到 Pi 的 npm 目錄，版本鎖定 |
| git | `git:github.com/example/pi-tools@v1` | clone 並對齊到指定 ref |
| URL | `https://github.com/example/pi-tools` | 視為 git 來源 |
| 本地 | `./pi-tools` | 從解析路徑載入，不複製 |

## 選擇套件資源：settings 的物件形式

settings 裡的物件形式可收窄要載入的資源：

```json
{
  "packages": [
    {
      "source": "npm:@example/pi-tools",
      "extensions": ["extensions/*.ts", "!extensions/legacy.ts"],
      "skills": [],
      "prompts": ["prompts/review.md"]
    }
  ]
}
```

- 省略屬性 = 載入全部；`[]` = 全不載
- `!pattern` 排除；`+path` 精確包含；`-path` 精確排除
- `pi config` 互動式啟用/停用資源與內建擴充（Tab 切換全域/專案範圍）

## 範圍與身分（scope and identity）

- 同一套件可同時出現在個人與專案設定；專案條目通常**取代**個人條目
- `autoload: false` 時，專案條目變成對個人套件的**過濾差量**
- 身分規則：npm 用套件名、git 用不含 ref 的 repo URL、本地用解析後的絕對路徑——防止同一套件重複載入

## ⚠️ 安全提醒

套件會**執行 extension 程式碼**，skill 也能指示模型跑程式：

- 安裝第三方套件前，**先審視原始碼**
- 授予專案 trust 前，先看專案的套件宣告（`.pi/settings.json`）
- `pi config` 可查看與控制載入的資源
