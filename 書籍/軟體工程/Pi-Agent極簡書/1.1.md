# 1.1 安裝與環境準備

## 從一個問題開始

你想在終端機裡擁有一個聽話的 AI coding agent：不鎖定模型、不強迫你接受別人的工作流程、可以隨時改造成自己要的樣子。Pi 就是為此而生。

## 安裝

Pi 是一個 CLI 工具，五種安裝方式挑一種：

```bash
# macOS / Linux（推薦：會鎖定依賴版本，可用 pi update 更新）
curl -fsSL https://pi.dev/install.sh | sh
```

```powershell
# Windows
powershell -c "irm https://pi.dev/install.ps1 | iex"
```

```bash
# npm / pnpm / bun（注意 --ignore-scripts 是必要的）
npm install -g --ignore-scripts @earendil-works/pi-coding-agent
pnpm add -g --ignore-scripts @earendil-works/pi-coding-agent
bun add -g --ignore-scripts @earendil-works/pi-coding-agent
```

```bash
# Nix（macOS / Linux）
nix profile add github:earendil-works/pi/stable
```

**環境需求：Node.js 22.19 以上**。官方安裝程式（curl / PowerShell）會在需要時自動幫你裝好 Node，並鎖定所有依賴版本；npm 安裝則不會鎖定間接依賴，建議優先用官方安裝程式。

> 打比方：官方安裝程式像是「包好的套裝」（依賴全鎖定、可 `pi update` 一鍵更新）；npm 安裝像是「散裝零件」（彈性大，但版本相容性自己負責）。

## 第一次啟動

Pi 的核心觀念：**「在哪個資料夾啟動，就在哪個資料夾工作」**。啟動資料夾決定它發現哪些檔案、載入哪些指令檔、會話歸檔在哪裡。

```bash
cd /path/to/project
pi
```

第一次啟動後：

1. Pi 可能會詢問你是否**信任這個工作資料夾**（Project Trust）——因為專案裡的設定檔和擴充會在 Pi 程序內執行
2. 在 Pi 內執行 `/login` 連接模型提供商（訂閱帳號或 API key）
3. 直接下任務，開始工作

## 更新與版本管理

```bash
pi update              # 更新 Pi 本體
pi update --models     # 重新整理模型目錄
pi update --all        # 更新 Pi + 所有已安裝套件
pi --version           # 查看版本
```

> 注意：用 Nix 裝的 Pi，`pi update` 更新不了本体，要用 `nix profile upgrade pi`。

## 檢查安裝是否正常

```bash
pi --help              # 列出所有指令與選項（含擴充註冊的選項）
pi --list-models       # 列出可用的模型
```

> Pi 是 MIT 授權的開源軟體，原始碼在 [github.com/earendil-works/pi](https://github.com/earendil-works/pi)。

## 安全提醒

Pi **不會在每次工具呼叫前都問你**——這是它的設計哲學（少彈窗、快節奏）。所以：

- 不信任的專案，不要授予 trust
- 不受監督的自動化任務，跑在容器（container）或沙箱裡
- 想要確認機制？自己用 extension 寫一個 permission gate，或安裝現成套件
