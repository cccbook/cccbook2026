# 1.3 模型設定與切換：15+ 提供商與自訂 Provider

## 從一個問題開始

Agent 工具最怕被鎖死在一家模型提供商。Pi 支援 **15+ 提供商、數百個模型**，而且支援**會話中途即時切換模型**。

## 支援的提供商

Anthropic、OpenAI、Google、Azure、Bedrock、Mistral、Groq、Cerebras、xAI、Hugging Face、Kimi For Coding、MiniMax、NVIDIA、OpenRouter、Ollama 等。認證方式有兩種：**API key** 或 **OAuth**。

模型目錄見 [pi.dev/models](https://pi.dev/models)，內含提供商、模型 ID、能力、context 上限與價格。

## 內建提供商：/login + /model

```text
/login        # 選提供商，連接訂閱或 API key（憑證存 auth.json）
/model        # 搜尋並選擇模型
/thinking     # 選擇思考等級（off / minimal / low / medium / high / xhigh / max）
/logout       # 移除某提供商的憑證
```

選模型 picker 裡按 `Ctrl+S` 可設為新會話預設模型；`/thinking` 裡按 `Ctrl+S` 儲存啟動時的思考等級。

## 會話中即時切換

| 動作 | 快捷鍵 / 指令 |
|---|---|
| 開啟模型選擇器 | `Ctrl+L` 或 `/model` |
| 循環切換模型 | `Ctrl+P` |
| 循環切換思考等級 | `Shift+Tab` |
| 設定循環清單 | `/scoped-models` |

會話會記錄模型與思考等級的變更；恢復會話時會還原，不影響新會話的預設值。

## 憑證的優先順序

多個憑證來源同時存在時，Pi 依此順序取用：

1. 執行時期的 `--api-key`
2. `auth.json` 儲存的憑證
3. `models.json` 裡的 `apiKey`
4. 提供商的環境變數或雲端憑證

> CI 環境建議用環境變數供 key，讓 Pi 不用寫憑證檔。

## 自訂 Provider：models.json

當你要接的端點說的是 Pi 已支援的 API（OpenAI / Anthropic / Google 相容），加進 `models.json` 即可。位置：`~/.pi/agent/models.json`（全域）或 `.pi/models.json`（專案）。

接本地 Ollama 的範例：

```json
{
  "providers": {
    "ollama": {
      "baseUrl": "http://localhost:11434/v1",
      "api": "openai-completions",
      "apiKey": "ollama",
      "models": [
        { "id": "qwen2.5-coder:7b" }
      ]
    }
  }
}
```

- `apiKey` 可以是字面值、`$NAME`/`${NAME}` 環境變數插值，或 `!command`（每次請求時執行，不快取）
- dummy key 只是讓 Pi 認得這個模型，Ollama 會忽略它
- 打開 `/model` 時會重新載入此檔
- `modelOverrides` 可修改既有內建模型的中介資料（context 上限、promptCache 等），不必取代整個列表

### 接 OpenCode Zen（OpenAI 相容網關）

OpenCode Zen 是標準的 OpenAI 相容 API 網關，API key 沒有鎖死在 OpenCode TUI 上，Pi 也能用：

```json
{
  "providers": {
    "opencode-zen": {
      "baseUrl": "https://opencode.ai/zen/v1",
      "apiKey": "$OPENCODE_API_KEY",
      "api": "openai-completions"
    }
  }
}
```

啟動 Pi 後即可 `/model` 切換到 Zen 提供的模型。**計費與 OpenCode 完全共享**——每筆請求都打到同一個 Zen 網關，從同一個帳戶餘額扣款，Token 單價與你用哪個 client 無關。

## 本地模型：llama.cpp 路由器

Pi 直接整合 llama.cpp 路由器：自動發現 GGUF 檔案、按需載入模型。

```text
/llama        # 管理 llama.cpp 路由器
/model        # 選擇已載入的模型
```

Ollama、LM Studio、vLLM、SGLang 等相容伺服器，用上面 `models.json` 的方式接。

## 完全自訂的提供商：Extension

提供商若需要自訂串流行為、模型發現或認證流程，寫一個 provider extension，用 `pi.registerProvider()` 註冊（見第四章）。

## 疑難排解

| 症狀 | 解法 |
|---|---|
| 模型沒出現在 `/model` | 確認該提供商的憑證可用（`models.json` 載入 ≠ 憑證可用） |
| 憑證只在一個 shell 有效 | key 來自環境變數，啟動 Pi 的程序必須有該變數 |
| 遠端機器登入開了瀏覽器 | 用提供商的 headless 認證流程，或貼回最終 redirect URL |
| 相容端點拒絕請求 | 檢查 `models.json` 的 API type 與相容性設定 |
