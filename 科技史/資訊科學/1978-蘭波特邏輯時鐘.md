# 1978 - Lamport 邏輯時鐘（分佈式事件的因果全序）

## 案件摘要
1978 年，**Leslie Lamport（1941–）** 在《CACM》發表
*Time, Clocks, and the Ordering of Events in a Distributed System*：
$$\boxed{\text{沒有全局時鐘？那就用邏輯來定義「先後」}}$$
**Lamport 邏輯時鐘**的洞察驚人地簡單：
- 每個程序自己維護一個計數器；
- 收到訊息時，時鐘取「本地時鐘與訊息時鐘的最大值再加一」；
- 用「happens-before」關係 $\to$ 為分佈式事件**排序**。
$$\text{分佈式事件} + \text{邏輯時鐘} = \text{一致的全序}.$$
這篇論文是**分佈式系統理論的開山之作**——
它成為**計算機科學史上被引用最多的論文之一**，
而 Lamport 後來的 Paxos（1982，見 `1982-蘭波特Paxos.md`）
與 **2013 年的圖靈獎**，都建立在這座「時間的基石」上。

## 前因 -- 為什麼會有這個案子
- **分佈式系統的興起（1970 年代）**：
  ARPANET 之後，電腦開始**連網**；多台機器協作，卻各自有**自己的時鐘**。
  物理時鐘會**漂移**（drift）——即使校準，晶體振盪器的誤差也會累積。
  $$\text{機器 A 的 12:00} \neq \text{機器 B 的 12:00（時鐘漂移）}$$
  「什麼事件先發生？」這個在單機上顯而易見的問題，在分佈式系統裡**成了懸案**。
  同時代的 **UNIX（1973）** 已經讓多使用者共用一台機器，
  但**多台機器之間**的秩序，還沒有任何數學工具能管。
- **無全局時鐘的難題**：
  相對論告訴我們：**同時性（simultaneity）本來就不是絕對的**。
  若兩個事件沒有因果關聯，任何觀察者都**無法斷定**誰先誰後——
  這不是工程缺陷，而是**宇宙的定律**。
  $$\boxed{\text{因果無關聯的事件，「同時」是相對的}}$$
- **資料庫與一致性的需求（1970 年代）**：
  Codd 的關聯式資料庫（1970，見 `1970-科德關聯式資料庫.md`）需要
  **交易（transaction）**的 ACID 保證：
  複製資料到多台機器後，**所有副本必須對「寫入順序」達成一致**——
  而寫入順序的前提，就是能對事件**排序**。
- **Lamport 的動機（1970s）**：
  Lamport �腦中有兩個問題：**空間**（互斥、狀態機）與**時間**（事件排序）。
  他回憶：這篇論文的起點是「**什麼事件先發生？**」——
  一個看似幼稚、實則深刻的問題。

## 線索與推理 -- 數學式、程式、理論

### 第一條線索：happens-before 關係（$\to$）
Lamport 定義**happens-before** 關係 $\to$：
- 若 $a$、$b$ 在**同一程序**內，且 $a$ 在 $b$ 之前，則 $a \to b$；
- 若 $a$ 是某程序**發送的訊息**，$b$ 是另一程序**接收該訊息**，則 $a \to b$；
- $\to$ 具**遞移性**：$a \to b$ 且 $b \to c$ 則 $a \to c$。
$$a \to b \quad\Longleftrightarrow\quad \text{事件 } a \text{ 因果上先於 } b$$
若 $a \nrightarrow b$ 且 $b \nrightarrow a$，則稱 $a$、$b$ **並發（concurrent）**——
**因果無法區分先後，就交給邏輯時鐘打破平手**。

### 第二條線索：Lamport 邏輯時鐘
每個程序 $P_i$ 維護時鐘 $C_i$，規則：
1. **本地事件**：$C_i \leftarrow C_i + 1$；
2. **發送訊息**：先 $C_i \leftarrow C_i + 1$，再把時間戳 $T = C_i$ 隨訊息送出；
3. **接收訊息**（時間戳 $T$）：$C_j \leftarrow \max(C_j, T) + 1$。
$$C_j \leftarrow \max(C_j,\, T) + 1 \qquad\text{（接收方的時鐘更新）}$$
**時鐘條件**：若 $a \to b$，則 $C(a) < C(b)$。
$$\boxed{a \to b \;\Rightarrow\; C(a) < C(b)\quad\text{（注意：反方向不成立）}}$$
$C(a) < C(b)$ **不能**推出 $a \to b$——兩個並發事件可能有相同的邏輯時間，
甚至「大的時間戳」也可能來自無因果關聯的事件；
邏輯時鐘只保證「因果先後不顛倒」，對並發事件，用**程序編號打破平手**：
$$(C(a), P_i) < (C(b), P_j) \Longleftrightarrow C(a) < C(b) \;\text{或}\; C(a) = C(b) \text{ 且 } P_i < P_j$$
這就是**全序廣播（total order broadcast）**的基礎：
$$\boxed{\text{所有節點對訊息順序完全一致（全序）}}$$
有了全序，每個副本按同一順序執行同一串指令，就成了**狀態機複製（replicated state machine）**——
分佈式系統最核心的建築技術。

### Python：三程序邏輯時鐘模擬與事件排序

```python
# 1) 三個程序的 Lamport 邏輯時鐘模擬
clocks = {"P1": 0, "P2": 0, "P3": 0}
events = []   # (時間戳, 程序, 事件描述)

def local_event(p, desc):
    clocks[p] += 1
    events.append((clocks[p], p, desc))

def send(src, dst, desc):
    clocks[src] += 1
    events.append((clocks[src], src, f"{desc}（發送）"))
    # 訊息抵達：接收方更新時鐘
    clocks[dst] = max(clocks[dst], clocks[src]) + 1
    events.append((clocks[dst], dst, f"{desc}（接收）"))

# 事件序列
local_event("P1", "a1")
send("P1", "P2", "m1")
local_event("P2", "b1")
send("P2", "P3", "m2")
local_event("P1", "a2")
local_event("P3", "c1")

# 用 (時間戳, 程序編號) 做全序排序
order = sorted(events, key=lambda e: (e[0], int(e[1][1])))
print("Lamport 邏輯時鐘（全序排序後）：")
for t, p, desc in order:
    print(f"  ({t}, {p})  {desc}")

# 驗證時鐘條件：a -> b ⇒ C(a) < C(b)
print("\n時鐘條件驗證（因果鏈 a1 → m1(發送) → m1(接收) → b1）：")
chain = [("a1", 1), ("m1(發送)", 2), ("m1(接收)", 3), ("b1", 4)]
ok = all(chain[i][1] < chain[i + 1][1] for i in range(len(chain) - 1))
print(f"  C(a1)={chain[0][1]} < C(m1發送)={chain[1][1]} < C(m1接收)={chain[2][1]} < C(b1)={chain[3][1]}  成立？{ok}")

# 並發事件打破平手：C 相同時用程序編號排序
print("\n並發事件（a2 與 m1接收 的時鐘比較）：")
print(f"  C(a2)={clocks['P1']}（P1）, C(m1接收)={events[3][0]}（P2）")
print(f"  排序鍵 (C, 程序編號)：P1 較小 → a2 在前 → 全序唯一 ✓")
```
輸出：
```
Lamport 邏輯時鐘（全序排序後）：
  (1, P1)  a1
  (2, P1)  m1（發送）
  (3, P1)  a2
  (3, P2)  m1（接收）
  (4, P2)  b1
  (5, P2)  m2（發送）
  (6, P3)  m2（接收）
  (7, P3)  c1

時鐘條件驗證（因果鏈 a1 → m1(發送) → m1(接收) → b1）：
  C(a1)=1 < C(m1發送)=2 < C(m1接收)=3 < C(b1)=4  成立？True

並發事件（a2 與 m1接收 的時鐘比較）：
  C(a2)=3（P1）, C(m1接收)=4（P2）
  排序鍵 (C, 程序編號)：P1 較小 → a2 在前 → 全序唯一 ✓
```

**偵探的註記**：看第 3 行與第 4 行——$C = 3$ 出現了**兩次**（P1 的 a2、P2 的 m1接收）。
邏輯時鐘**不唯一**，這正是「$C(a) < C(b)$ 不能推出 $a \to b$」的活例證：
並發事件在時鐘上**平手**，得靠 $(C, \text{程序編號})$ 這把鑰匙才能打開**唯一全序**的鎖。

## 結案 -- 後果與影響
- **邏輯時鐘的分水嶺（1978）**：
  $$\boxed{\text{「先後」不靠物理時鐘，靠因果與邏輯}}$$
  《Time, Clocks...》成為**計算機科學史上被引用最多的論文之一**——
  邏輯時鐘的思想延伸為**向量時鐘**（vector clocks，1988）、
  **因果排序**、**事件溯源（event sourcing）**——
  連 **Git 的 commit 圖**都是同一思想的小規模體現：
  commit 之間靠 parent 指標定義因果，**不需要看錶上的時間**。
- **狀態機複製的誕生**：
  全序廣播 + 確定性狀態機 = **狀態機複製**——
  這是之後一切**複製式系統**（資料庫副本、鎖服務、組態管理）的理論骨架。
  $$\text{邏輯時鐘（1978）} \xrightarrow{\text{全序}} \text{狀態機複製} \xrightarrow{} \text{分佈式系統的骨架}$$
- **通往共識之路**：
  排序解決了「事件的先後」，但「**選定哪個值**」還需要**共識**——
  Lamport 自己接手了下一個案子：Paxos（1982，見 `1982-蘭波特Paxos.md`）。
  後來的 **Google Spanner** 更把「邏輯時間」發揚光大：
  **TrueTime API** 用 GPS 與原子鐘給出**有界不確定性的物理時間**——
  邏輯時鐘與物理時鐘在四十年後**握手言和**。
  $$\text{Paxos} \xrightarrow{} \text{Google Chubby / Spanner} \xrightarrow{} \text{ZooKeeper（Zab）} \xrightarrow{} \text{Raft（2014）}$$
- **圖靈獎的伏筆（2013）**：
  ACM 將 2013 年**圖靈獎**頒給 Lamport，
  表彰他對**分佈式系統理論與實踐的根本性貢獻**——
  評獎理由的第一句話，就是這篇 1978 年的論文。
  $$\text{邏輯時鐘（1978）} \xrightarrow{} \text{Paxos（1998）} \xrightarrow{} \text{圖靈獎（2013）}.$$
- **LaTeX 的副業（1984）**：
  同一位 Lamport 也是 **LaTeX** 的原作者——
  他寫作論文時嫌 TeX（Knuth，1978）太低階，包了一層**巨集與結構化標記**——
  **一個人在「時間」與「排版」兩個領域都留下了同名遺產**。
- 歷史定位：**Lamport 是「時間的偵探」**——
  他證明了：在沒有全局時鐘的世界裡，
  **秩序不是靠運氣，而是靠數學**；
  $$\text{無全局時鐘（1978）} \xrightarrow{\text{邏輯時鐘}} \text{因果全序} \xrightarrow{} \text{分佈式系統的時間觀}.$$
  **一切從那個簡單的問題開始：「什麼事件先發生？」**
