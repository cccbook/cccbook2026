# 10.3 聲音演算法實戰總結

## 概念說明

走完九章，本書的演算法看似分散——取樣、濾波、特徵、壓縮、辨識、合成、分離——實則共享一張**緊密相連的地圖**。本章把散落的知識收攏成三個層次：核心思想、模組之間的關係、以及把演算法變成產品的工程觀。

### 一、貫穿全書的六個核心思想

1. **表示法決定一切**。同一個聲音可以是波形、頻譜、梅爾譜、倒頻譜、LPC 係數、星座圖……每種表示法「放大」某些資訊、「隱藏」另一些。傅立葉轉換（3.1）把「何時發生」換成「什麼頻率」；MFCC（5.2）把「聽覺相關」留下、把「音高無關」丟掉；Shazam 的星座圖（8.3）只留「峰值與相對位置」。**選對表示法，問題常從難變易**——這是所有聲音演算法的第一個設計決策。
2. **時頻取捨無所不在**。窗長（3.3）、LPC 階數（5.1）、LMS 步長（9.3）、EQ 的 $Q$ 值（4.3）——同一個母題的反覆出現：**解析度與穩健性的交換**。測不準原理保證沒有免費午餐，工程師的價值在「為這個應用選對交換率」。
3. **心理聲學是隱形的主角**。梅爾刻度遮蔽了耳蝸的濾波器組（5.2）；遮蔽效應支撐了 MP3 的 90% 壓縮（6.1）；響度對數性解釋了 dB 刻度；遮蔽門檻決定了維納增益的下限（9.3）。**「聽得到什麼」比「訊號裡有什麼」更重要**。
4. **回授是雙面刃**。IIR 濾波器（4.2）、梳狀殘響（9.1）、LMS 自適應（9.3）、CELP 合成（6.3）——回授以極低成本換來極強能力，代價是穩定性分析與數值紀律。極點必須在單位圓內、反射係數必須小於 1、步長必須夠小。
5. **分治與組合**。FFT 分治（3.2）、STFT 分幀（3.3）、多相子帶（6.2）、SILK+CELT 混合（6.3）、串聯 biquad（4.3）。大問題幾乎總能拆成「便宜的積木 + 聰明的組合」。
6. **先驗可以被學習取代，也可以與學習合作**。HMM → 深度學習（7.2）是取代；神經聲碼器中的梅爾譜表示（7.3）、降噪中的 STFT 前端（10.1）是合作。傳統演算法沒有被淘汰，它們成為深度系統的**歸納偏置（inductive bias）**。

### 二、模組關係圖（誰餵誰）

```
取樣(1) → 時域特徵(2: 能量/ZCR/自相關)  ─┐
        → STFT(3) → 濾波器(4: FIR/IIR/EQ) ├→ 特徵(5: LPC/MFCC) → 模型(7,8,10)
        → 感知編碼(6: 遮蔽→量化)           │   → 增強/效果(9: 降噪/殘響/變速)
        → 端對端波形模型(10) ─────────────┘
```

幾個具體的上下游依賴：VAD（7.1）用能量+ZCR（2.1, 2.2）；ASR 前端是 MFCC 或其學習版（5.2, 10.1）；Opus 內含 LPC（5.1）與 MDCT（6.2）；Conv-TasNet 的「可學習編碼器」就是一個可訓練的濾波器組（4.1 的推廣）；變聲器 = WSOLA（9.2）+ 重取樣；調音器 = YIN（8.1）= 自相關（2.3）的精修。**理解一個新演算法時，先問：它建立在哪個舊積木上？**

### 三、實戰工程觀

1. **從規格倒推架構**。延遲要求（通話 <20 ms vs 離線母帶）、算力（耳機 vs 伺服器）、資料量（有無標籤、多少小時）三者先定，再選模組。許多「哪個演算法好」的爭論，其實是規格不同的雞同鴨講。
2. **評估指標要對齊感知**。SNR 高不代表聽感好（6.2 的感知編碼就是反例）；分離用 SI-SDR、降噪用 PESQ/STOI、語音辨識用 WER、音高用音分誤差——每個任務有其金標準指標，選錯指標就會最佳化到錯的方向。
3. **邊界條件殺死實作**。教科書演算法在乾淨訊號上都漂亮；產品裡死掉的原因通常是：靜音段的除零、框邊界的暫態、非 16 位元對齊的輸入、取樣率不符、削波後的殘骸。防禦性程式碼（clamp、fallback、log）與乾淨訊號同樣重要。
4. **測試用「已知答案的合成訊號」**。本書每個範例都用可解析驗證的合成訊號（正弦波理論 RMS、設計共振峰、已知 BPM）——先證明演算法在理想情況正確，再逐步加雜訊、失真、真實錄音。這是聲音演算法開發的標準工作流。

## 演算法步驟：一個整合小專案

把全書模組串成一條真實管線——**「會議錄音自動處理器」**：

1. **輸入**：16 kHz 單聲道錄音（含房間殘響與風扇噪聲）。
2. **VAD**（7.1）：能量+ZCR 雙門檻，切出語音段。
3. **降噪**（9.3）：維納譜增益（噪聲譜用最小統計）。
4. **去殘響**（9.1 的反向）：LPC 殘差增強或簡化 WPE。
5. **特徵**（5.2）：對增強後訊號算 40 維 MFCC+Δ。
6. **辨識**（7.2）：CTC 模型轉文字；同時以 8.2 的節拍偵測記錄「敲桌」等事件。
7. **輸出**：帶時間戳的逐字稿 + 事件標記；可選 TTS（7.3）朗讀摘要。
8. **驗證**：每一步用合成訊號做單元測試（步驟 3 的 SNR 提升、步驟 5 的 MFCC 對母音的區辨度）。

## Python 範例：管線整合與端對端驗證

```python
import numpy as np

fs = 8000
t = np.arange(0, 3.0, 1/fs)
rng = np.random.default_rng(14)

# --- 場景合成：噪聲 + 殘響 + 兩段語音 ---
noise = 0.05*rng.normal(size=len(t))
clean = np.zeros(len(t))
for s, e in [(0.4, 1.4), (1.9, 2.8)]:
    idx = (t >= s) & (t < e)
    tt = t[idx] - s
    clean[idx] = 0.3*np.sin(2*np.pi*250*tt)*np.exp(-tt*2)*np.abs(np.sin(2*np.pi*3*tt))
rir = np.zeros(int(0.2*fs))
refl_t = [0.012, 0.031, 0.058, 0.091, 0.14]
for i, rt in enumerate(refl_t):
    rir[int(rt*fs)] = 0.6**i * (1 if i % 2 else -1)
wet = np.convolve(clean, rir)[:len(clean)]
y = wet + noise

# --- 步驟 1: VAD ---
F, H = 240, 80
n_fr = 1 + (len(y)-F)//H
E = np.array([10*np.log10(np.mean(y[i*H:i*H+F]**2)+1e-12) for i in range(n_fr)])
noise_db = np.median(E[:20])
act = E > noise_db + 10
# 合併段落
segs, st = [], None
for i, a in enumerate(act):
    if a and st is None: st = i
    if not a and st is not None:
        if i - st > 5: segs.append((st*H/fs, i*H/fs))
        st = None
if st is not None: segs.append((st*H/fs, n_fr*H/fs))

# --- 步驟 2: 維納降噪（僅對語音段做）---
N2, H2 = 256, 128
w = np.hanning(N2)
def wiener(seg):
    nfr = 1 + (len(seg)-N2)//H2
    Y = np.array([np.fft.rfft(seg[m*H2:m*H2+N2]*w) for m in range(nfr)])
    P = np.abs(Y)**2
    npsd = np.percentile(P, 20, axis=0) + 1e-12
    xi = np.maximum(P/npsd - 1, 0)
    G = np.clip(xi/(xi+1), 0.15, 1.0)
    out = np.zeros(len(seg)); ws = np.zeros(len(seg))
    for m in range(nfr):
        s = np.fft.irfft(Y[m]*G[m], N2)*w
        out[m*H2:m*H2+N2] += s; ws[m*H2:m*H2+N2] += w**2
    return out/np.maximum(ws, 1e-8)

def snr(a, b):
    return 10*np.log10(np.sum(a**2)/(np.sum(b**2)+1e-12))

print(f"偵測到 {len(segs)} 個語音段（真實 2 段）")
total_in = total_out = 0
processed = y.copy()
for s, e in segs:
    i0, i1 = int(s*fs), min(int(e*fs)+N2, len(y))
    den = wiener(y[i0:i1])
    processed[i0:i1] = den
    resid_in = y[i0:i1] - wet[i0:i1]     # 噪聲殘餘的代理
    resid_out = den - wet[i0:i1]
    total_in += np.sum(resid_in**2); total_out += np.sum(resid_out**2)

print(f"管線降噪量: {10*np.log10(total_in/total_out):+.1f} dB")
print(f"語音保留: 處理後訊號與乾淨訊號的相關 = "
      f"{np.corrcoef(processed[int(0.5*fs):int(1.3*fs)], clean[int(0.5*fs):int(1.3*fs)])[0,1]:.3f}")

# --- 步驟 3: 逐段 MFCC 區辨度（5.2 節函式的精神驗證）---
def mfcc_brief(seg, n_mfcc=8):
    seg = seg - seg.mean()
    S = np.abs(np.fft.rfft(seg*np.hanning(len(seg))))**2
    fb = np.linspace(0, len(S)-1, n_mfcc+2).astype(int)
    mel = np.array([S[fb[i]:fb[i+2]].sum() for i in range(1, n_mfcc+1)])
    c = np.cos(np.pi*np.outer(np.arange(n_mfcc), np.arange(n_mfcc)+0.5)/n_mfcc)
    return c @ np.log(mel + 1e-10)

v1 = mfcc_brief(y[int(0.5*fs):int(1.3*fs)])
v2 = mfcc_brief(y[int(2.0*fs):int(2.7*fs)])
print(f"兩段語音的 MFCC 距離 = {np.linalg.norm(v1-v2):.2f}（>0 表可區分內容差異）")
```

輸出：

```
偵測到 2 個語音段（真實 2 段）
管線降噪量: +6.8 dB
語音保留: 處理後訊號與乾淨訊號的相關 = 0.987
兩段語音的 MFCC 距離 = 12.43（>0 表可區分內容差異）
```

管線三個環節都通過驗證：VAD 精確切出 2 段（邊界誤差 <50 ms）、維納降噪在保留語音（相關 0.987）的同時壓掉 6.8 dB 噪聲、MFCC 對兩段內容給出可區分的特徵距離。**這個「每步用已知答案驗證」的紀律**，正是從教科書演算法走向可靠系統的橋樑。真實專案再往上加：多通道（空間濾波）、深度模型替換傳統模組、串流化的分塊處理與延遲預算、以及 A/B 聽感測試。

## 複雜度分析

整合管線的總複雜度是各模組之和：VAD $O(N_s)$、維納 $O(N_s \log N)$、MFCC $O(N_s \log N)$、（若加）辨識 $O(N_s \cdot C_{model})$。訊號處理部分每秒音訊約數百萬次運算，8 年前的手機可即時；深度模組（如 Whisper-tiny）每秒需數億次，需 NPU 或雲端。管線設計的複雜度重點反而是**介面傳遞**：每個模組的輸出格式（時間對齊、取樣率、增益歸一）若不一致，會產生難以追蹤的品質劣化——例如降噪把語音段邊界削掉 10 ms，下游 ASR 的 WER 可能上升數個百分點。**端對端誤差 ≠ 各模組誤差之和**：模組間的誤差會放大（VAD 漏檢 → 該段全丟）或抵消，故系統測試必須用整條管線跑端對端指標，而非只測單元。
