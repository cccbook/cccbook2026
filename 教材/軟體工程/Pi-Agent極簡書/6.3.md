# 6.3 Pi vs OpenCode：差異與選擇

## 從一個問題開始

Pi 與 OpenCode 都是開源、不鎖定單一模型（Model-agnostic）的終端 AI Agent。它們差在哪？一句話：

> **Pi 是「可模組化的極簡 Engine/SDK」**——不設限，讓開發者透過 TypeScript 打造專屬工具鏈；
> **OpenCode 是「開箱即用的開源 Agent 平台」**——內建完整功能，下載就能用。

## 核心差異對比

| 構面 | Pi | OpenCode |
|---|---|---|
| **設計哲學** | Primitives, Not Features——框架越輕量越好，不強制 Plan 模式、子 Agent 或權限彈窗，全部交由 Extension 實現 | Batteries-Included——開箱即用，內建 Plan/Build 雙模式與完整編程功能 |
| **語言與架構** | TypeScript 輕量級單體/SDK，可直接 import 當 SDK | Go 語言 Client-Server 分離架構（`opencode serve` / attach 遠端連線） |
| **執行與擴充** | TypeScript Extensions & Packages（Codemode 沙箱，可即時撰寫擴充修改 Pi 本身） | MCP 協議與 Plugin 生態，支援自訂 Command |
| **代碼診斷** | 依賴模型或 Tool 自行處理（可自寫 extension） | **深度整合 LSP**——修補後自動讀取 LSP 報錯並自動修復 |
| **歷史管理** | 單檔**樹狀分支**（`/tree` 自由跳躍、導出 HTML） | **Git-based Snapshot**（每次修改建 snapshot，`/undo`、`/redo`） |
| **模型切換** | 對同一 Session 中途切換模型有嚴格的 prompt 與上下文轉換測試 | 支援廣泛模型 API（Models.dev），主要靠抽象層轉換 |
| **介面** | TUI（全螢幕/regular）、Print/JSON、RPC、SDK | TUI、IDE 外掛、Client-Server 遠端 |

## 怎麼選？

### 選 Pi，如果你：

1. **想完全掌控工作流**：不喜歡預設的 Plan 模式、過多確認彈窗、被框架限制
2. **需要嵌入與深度擴充（SDK 導向）**：想把 agent 嵌入自己的 Node.js 應用，或用 TypeScript 為 agent 寫客製化邏輯/UI（甚至讓 agent 幫自己寫擴充）
3. **喜歡樹狀思考與探索**：解決複雜問題常需要「開平行分支試錯」——Pi 的樹狀 session 管理非常適合

### 選 OpenCode，如果你：

1. **要開箱即用的 coding 助手**：下載後直接抓 bug、改 code、跑測試，不想花時間寫擴充
2. **重視代碼正確性（LSP 反饋）**：喜歡 agent 改完 code 後自動接收 compiler 報錯並自發修正
3. **需要遠端/服務化部署**：Client-Server 架構可在遠端伺服器跑 `opencode serve`，從本地 TUI 或 IDE 外掛 attach

## 共通點

- 都是**開源**（MIT 授權）
- 都**不鎖定單一模型**，支援主流提供商
- 都有 TUI、都跑在終端機
- 都支援 AGENTS.md 式的專案指令檔
- 都能用 OpenCode Zen 的模型

## Pi 接 OpenCode Zen 的模型

可以，而且**計費額度完全共享**。OpenCode Zen 的本質是標準的 OpenAI 相容 API 網關，API key 沒有鎖死在 OpenCode TUI 上。

在 Pi 的 `~/.pi/agent/models.json` 新增自訂 Provider：

```json
{
  "providers": {
    "opencode-zen": {
      "baseUrl": "https://opencode.ai/zen/v1",
      "apiKey": "$OPENCODE_API_KEY",
      "api": "openai-completions"
    }
  }
}
```

啟動後 `/model` 切換到 Zen 提供的模型即可。

**額度與計費**：

- Zen 以量計費（Pay-as-you-go），基礎是帳戶儲值餘額與 token 消耗量
- Pi 發出的每筆請求都直接打到 Zen 網關，從**同一個帳戶餘額**扣款
- Token 單價由 Zen 後端統一計算，與你用哪個 client（OpenCode CLI、Pi、curl）**無關**

> 💡 提示：Pi 與 OpenCode 的 compaction 策略與系統提示詞長度不同——單價相同，但 context 消耗量可能有差異。Pi 的系統提示詞較極簡，某些情況下消耗的 context 較少。

## 對照表總結

| 你的樣子 | 該用 |
|---|---|
| 想要工具、愛自己改、SDK 嵌入、樹狀試錯 | **Pi** |
| 想要開箱即用、LSP 自動修復、遠端服務化 | **OpenCode** |
| 兩者都用？完全可以——Pi 接 Zen 模型，同一個帳戶扣款 | **都要** |
