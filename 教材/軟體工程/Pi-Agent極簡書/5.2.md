# 5.2 結合 tmux 實現多 Agent 協同

## 從一個問題開始

想要多個 agent 並行工作？Pi 官方立場：**不內建 sub-agents**。答案不是「等官方」，而是：用 tmux 開多個 Pi 實例，或用 extension 自己建，或裝套件。

> "Spawn Pi instances via tmux, or build your own with extensions, or install a package that does it your way."

## 為什麼 Pi 不內建 sub-agents

1. **單一進程的 sub-agent 是黑箱**：狀態、輸出都藏在主 agent 裡，難觀察
2. **tmux 給你全程可觀察**：每個 Pi 實例就是一個可見的視窗，你能直接跳進去看它在做什麼、直接互動
3. **核心維持極簡**：多 agent 是一種工作流程，不是必備功能——交給 Unix 老將 tmux

## 方案一：tmux 直接開多個 Pi

```bash
# 開一個名為 agents 的 session，三個視窗各跑一個 Pi
tmux new-session -d -s agents -n "refactor"
tmux send-keys -t agents 'cd ~/proj && pi' Enter
tmux new-window -t agents -n "tests"
tmux send-keys -t agents:tests 'cd ~/proj && pi' Enter
tmux new-window -t agents -n "docs"
tmux send-keys -t agents:docs 'cd ~/proj && pi' Enter
tmux attach -t agents
```

日常操作：

| 指令 | 功能 |
|---|---|
| `tmux new-window -t agents` | 開新的 agent 視窗 |
| `tmux attach -t agents` | 接上觀察所有 agent |
| `Ctrl+B` 然後 `0-9` | 切換視窗，直接看某個 agent 的畫面 |
| `tmux send-keys -t agents:0 '...' Enter` | 從腳本送訊息給某個 agent |

> 打比方：別的 tool 的 sub-agent 像「一個主管在腦內同時想三件事，你只能問他」；tmux 多 Pi 像「開三間會議室，每間一個 agent，你想進哪間就進哪間，全程透明」。

## 方案二：CLI 一次式分派

tmux + print mode 組合，每個任務一條指令：

```bash
tmux send-keys -t agents:0 'pi --print "refactor the auth module"' Enter
tmux send-keys -t agents:1 'pi --print "fix flaky test in utils.test.ts"' Enter
```

需要觀察過程就用互動模式；只要結果就用 `--print`。

## 方案三：用 Extension 建 sub-agent

想要「模型自己 spawn 子 agent」的體驗？寫一個 extension：用 `pi.registerTool()` 註冊一個 `spawn_agent` 工具，內部用 `child_process` 起 `pi --print` 或 RPC 模式的 Pi 實例，回傳結果。

官方直接提供範例：[examples/extensions/subagent/](https://github.com/earendil-works/pi/tree/main/packages/coding-agent/examples/extensions/subagent/)。

## 方案四：裝現成套件

到 [Pi Packages 畫廊](https://pi.dev/packages) 找現成的多 agent 套件：

```bash
pi install npm:套件名
```

## 會話隔離：多實例不衝突

Pi 的會話依工作資料夾分組儲存（`~/.pi/agent/sessions/<專案>/`），多個實例同時跑也不會互相踩到：

- 每個實例有獨立的會話檔（樹狀）
- 不同專案目錄 = 不同會話群組
- 想共用脈絡？`/export` 匯出 JSONL，另一個實例 `/import` 接續

## 協同工作流範例

1. 視窗 1：agent A 重構 auth 模組（互動模式）
2. 視窗 2：agent B 修測試（互動模式）
3. 視窗 3：你在這裡寫 code，隨時 `Ctrl+B` 跳去視窗 1 檢查 A 的方向、`Enter` 送 steering 訊息
4. A 做完 → `/export` 匯出會話給 reviewer
5. 視窗 4：agent C 跑 `pi --print "review the diff"` 做最終審查

> 重點：多 agent 的關鍵不是「同時跑」，是「**全程可觀察、可介入**」。tmux 的可見性 + Pi 的 Steer/`!` 指令，讓你始終是總指揮。
