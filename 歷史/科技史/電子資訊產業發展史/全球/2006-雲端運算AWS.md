# 2006：雲端運算 AWS — 把資本支出變成電費

## 案情
2006 年 3 月 14 日，Amazon 推出 S3（Simple Storage Service），宣告「儲存就像水電，用多少付多少」：每 GB 每月 0.15 美元。同年 8 月 25 日，EC2（Elastic Compute Cloud）以測試版上線，租一台虛擬伺服器每小時 0.10 美元。這家賣書起家的公司，把自己內部支撐電商的基礎設施包裝成商品出售，開啟了「雲端運算」時代。

## 前因
- 2000 年代初，Amazon 為應付假日購物尖峰，必須按「最高負載」採購伺服器——其餘十個月大量機器閒置。
- 內部各開發團隊各自重造儲存、佇列、運算的輪子，2003 年前后 AWS 起源專案開始規劃標準化基礎設施。
- Bezos 深受 Service-Oriented Architecture 影響，2002 年曾發內部命令（API Mandate）：所有團隊必須以服務介面溝通，介面必須設計成可對外開放。
- 同期，Salesforce（1999）喊出 "No Software"、Google 與 IBM 也在談 grid computing；「雲端」一詞要等 2006 年 Eric Schmidt 才被廣泛使用。

## 線索與推理
偵探的第一個疑點：為什麼是 Amazon，而不是 Sun（喊出「The Network is the Computer」）或 IBM？線索有三。其一，Amazon 有真實的規模化基礎設施與閒置產能——旺季尖峰之外，機器平均利用率可能僅 10–20%，把固定成本攤到對外銷售上是純利潤。其二，零售基因：Amazon 擅長賣低毛利、高周轉的標準品，運算力正是這種商品；Sun、IBM 賣的是高毛利的諮詢與硬體，不願自毀定價權。其三，Bezos 的 API Mandate 已強迫全公司練好了「把能力變成服務」的肌肉——雲端不是發明，是內部紀律的外溢。

第二個推理：定價的心理學。每小時 0.10 美元聽起來微不足道，但工程師可以在實驗室裡用公司信用卡直接刷卡開機——採購流程消失了。偵探的鑑識：AWS 砍掉的不是成本，是「審批」。這使新創公司的進入門檻從「先募資建機房」降為「下午就能上線」，創業週期從月縮到日。

第三條線索：先賣 S3（3 月）再賣 EC2（8 月）的順序不是偶然。儲存是運算的前置依賴——先建立資料的重力，運算自然被吸過來。這是平台經典策略：先鎖資料，再賣算力。

## 理論
雲端的核心經濟學是 CAPEX（資本支出）轉 OPEX（營運費用）。自建資料中心的總擁有成本：

$$TCO_{own} = \underbrace{C_{hw}}_{\text{硬體}} + \underbrace{C_{bldg}}_{\text{機房}} + \int_0^T \left( C_{power}(t) + C_{admin}(t) \right) dt$$

且須按尖峰負載 $L_{max}$ 容量規劃，平均利用率

$$u = \frac{\int_0^T L(t)\, dt}{L_{max} \cdot T} \ll 1$$

Web 負載的尖峰/均值比常達 2–10 倍（假日效應、時區疊加），自建的閒置浪費為 $(1/u)$ 倍容量。雲端的解法是統計多工（statistical multiplexing）： $n$ 個客戶的負載尖峰不同步，聚合後所需容量為

$$C_{cloud} \approx \max_t \sum_{i=1}^{n} L_i(t) \;<\; \sum_{i=1}^{n} L_{i,\max}$$

由大數法則， $n$ 越大，聚合負載越平滑， $u_{cloud}$ 越高——規模經濟與風險池化同時成立，這正是保險業的數學搬進了運算業。

對使用者而言，雲端把成本函數從固定成本改為近似線性變動成本：

$$Cost_{cloud}(t) = p \int_0^t L(\tau)\, d\tau$$

這改變了財務結構：新創不再需要前期融資建機房，損益兩平點大幅前移；對經濟景氣的敏感性也由「資本沉沒」變成「隨時退租」。學術上，這可對應到 Armstrong 的兩部收費理論與規模報酬遞增產業的自然壟斷傾向——資料中心的一次性投資巨大、邊際成本極低，天然走向寡占。

## 後果
1. 2007–2008 年，Dropbox、Netflix、Instagram 等新創以 AWS 起家，「伺服器零資產」成為新創標配。
2. Google（2008 GAE、App Engine→GCP）、Microsoft（2010 Azure）被迫跟進，三大雲形成寡占；甲骨文、IBM 轉型掙扎。
3. 2011 年 Netflix 全面遷移上雲，證明關鍵業務可託管，企業市場解凍。
4. 雲端直接為大數據（Hadoop on EC2）、AI 訓練（2012 年後 GPU 租用）提供火藥——深度學習革命是踩在雲端的肩上。
5. 2010 年代的「雲端遷移」成為企業 IT 最大支出移轉，Amazon 營業利益近半來自 AWS，零售公司成了基礎設施公司。

## 冷案檔案
- 時間：2006 年 3 月 14 日（S3）；2006 年 8 月 25 日（EC2 beta）；2007 年（歐洲區上線）
- 案由：電商公司的閒置機房，被重新包裝成以小時計價的公共事業，運算自此像電力一樣販售
- 歷史定位：雲端運算把 CAPEX 變 OPEX、把機房變電網——是 2010 年代行動與 AI 浪潮最底層的那塊基石
