# 2025：C++26 反射與未來——編譯期後設程式設計的終點站

## 事件
2025 年，**C++26** 的主要特性陸續定案（預計 2026 年正式發佈）。最大亮點是**靜態反射（static reflection）**——C++ 樣板元程式設計的終極目標。

## 關鍵語法/特性
- **靜態反射**：`^^T`（反射運算元）、`[: :]`（拼接運算元）——編譯期取得型別/成員資訊並生成程式碼，取代樣板元程式設計（TMP）與宏的黑魔法。
- **契約（contracts）**：`pre`、`post`、`contract_assert`——前置/後置條件寫進語言，安全性設定檔（profiles）的基礎。
- **`std::execution`**（發送器/接收器，Senders/Receivers）：標準非同步執行框架。
- **`std::hive`、`std::simd`、Hazard pointers、`std::inplace_vector`**。
- **`constexpr` 更進一步**：更多標準庫可編譯期使用。

## 為何重要
- **反射是 40 年的終點站**：從 1993 樣板、2011 可變參數樣板、2020 concepts，C++ 的編譯期程式設計能力一路擴充，2026 年的反射讓「以程式碼生成程式碼」不再需要宏或 TMP——序列化、ORM、綁定程式碼可用標準語法生成。
- **契約是安全性的官方回應**：面對 Rust 的競爭與 NSA/CISA 的記憶體安全報告，C++ 以「profiles + contracts」作為語言層面的安全策略。
- **`std::execution` 統一非同步**：2020 協程 + 2026 發送器，非同步的語言支援與標準框架終於齊備。

## 理論與實用原因
- **理論原因**：反射源自 Lisp 的 homoiconicity 與 Metaobject Protocol（MOP）理論；契約源自 Hoare 邏輯（1969）與契約式設計（Eiffel, Meyer 1986）。
- **實用原因**：樣板錯誤訊息與宏的安全性問題長年無解；資安政策要求記憶體安全——契約與 profiles 是 C++ 的官方回應。

## 彌補了什麼缺陷
彌補了 C++「無編譯期反射、無語言層面契約、非同步無標準執行框架」的缺陷——從 1979 年 C with Classes 到 2026 年反射，C++ 的設計主軸「零成本抽象」貫穿始終。

## 程式範例

**靜態反射：編譯期列舉 struct 成員（提案語法，示意碼）**

```cpp
// C++26 前：要用宏或樣板元程式設計（TMP）才能反射式生成程式碼
// 例如 Boost.Hana / 手寫巨集：
#define DESCRIBE(Type, member) \
    os << #member << " = " << t.member << "\n";   // 宏黑魔法，無法自動列舉成員
// 每加一個成員都要手動更新宏，錯漏無從編譯期偵測。

// C++26 新語法（P2996 靜態反射，即將定案，示意碼）：
template <class T>
void describe(const T& t) {
    // ^^T：取得型別 T 的反射資訊（reflection value）
    // members_of：編譯期取得所有資料成員的反射列表
    template for (constexpr auto m : std::meta::members_of(^^T)) {
        // [:m :]：拼接（splicing）運算元——把反射變回真正的實體
        std::println("{} = {}", std::meta::identifier_of(m), t.[:m:]);
    }
}

struct Point { int x; int y; };
// describe(Point{1, 2});  // 自動印出「x = 1」「y = 2」，成員增減無須改程式
```

```cpp
// 反射取代 TMP：編譯期依成員生成 enum 名稱轉字串（示意碼）
enum class Color { red, green, blue };

template <Color E>
constexpr std::string_view enum_name() {
    // 列舉 Color 的成員反射，比對拼接後的實體，回傳其名稱——
    // 以往這需要 X-macro（#define X(red) "red", …）或複雜 TMP 才辦得到
    template for (constexpr auto m : std::meta::enumerators_of(^^Color)) {
        if (E == [:m:]) return std::meta::identifier_of(m);
    }
    return "unknown";
}
```

**契約：條件寫進語言（提案語法，示意碼）**

```cpp
// 舊寫法：assert 是執行期檢查（且 release 版可能被編譯掉），
// 前置/後置條件只能寫在註解裡，編譯器與工具無法利用。
int divide(int a, int b) {
    // pre: b != 0   （僅是註解，毫無約束力）
    assert(b != 0);          // 執行期才爆掉
    return a / b;
}

// C++26 新語法（契約，示意碼）：
int divide2(int a, int b)
    pre(b != 0)                              // 前置條件：違約即契約違反
    post(r : r * b <= a + b && r >= 0)       // 後置條件：可引用結果 r
{
    contract_assert(r : a / b >= 0);         // 函式內部的契約斷言
    return a / b;
}
```
